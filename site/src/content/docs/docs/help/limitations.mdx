title: Known limitations
description: What cornercase doesn't do yet, and the trade-offs it makes on purpose.
---

cornercase is young. These are the gaps you may run into today.

## Not there yet

| Limitation | What it means for you |
| --- | --- |
| **No search in the scrollback** | The wheel [scrolls back](../../guides/panes-and-splits/#scroll-back) through a pane's history, but you can't search it, nor scroll with the keyboard. `cornercase read --lines 20000 \| grep …` searches it from a shell. |
| **Shells don't survive the server** | After `cornercase kill-server`, a reboot or a restart after an update, the layout comes back but every pane starts a new shell: running programs and their output are gone. Claude Code, Codex, Gemini CLI, Grok Build, Cursor CLI, Vibe CLI and GitHub Copilot CLI [resume their conversations](../../guides/sessions/#agents-resume-their-conversations), but whatever they were doing is stopped. |
| **Terminal colours are read once** | The server asks your terminal for its colours when it starts. If you switch theme, restart it with `cornercase restart` (or **settings → restart**) to see the new colours. |
| **No key releases** | Programs inside cornercase only see key presses, never releases, even with the kitty keyboard protocol. |
| **No pictures inside panes** | Programs in your panes can't draw pictures: `kitten icat`, `chafa` and file managers' image previews don't show them, though some fall back to characters. Images show in the [files panel](../../guides/files/#images) instead, as still pictures (an animation shows its first frame), and only in [terminals that can draw them](../../guides/files/#which-terminals-show-them). |
| **One machine per window** | [`cornercase remote`](../../guides/remote/) shows the server of one machine; projects of several machines don't share a sidebar. Open a window for each. |
| **One size for all clients** | When several terminals are attached, all of them use the size of the one you used last. The others show the session cut off or with empty space around it. |
| **The Processes view samples** | The [Processes](../../guides/projects-workspaces-tabs/#processes) dialog and `cornercase processes` measure at an interval, so a program that starts and ends between two samples is not counted. A program that daemonizes leaves its pane's tree, so it is not listed; one in a container or another PID namespace is not seen. On macOS the figures of another user's process, a `sudo` child for example, cannot be read and show as `-`. |
| **100 issues per source** | The issue browser lists up to 100 issues from each tracker. Use the filters to narrow the list down. |
| **Agent status needs OSC 7501 or a supported reader** | Tabs show what Claude Code, Codex, Gemini CLI, opencode, Grok Build, Cursor CLI, Vibe CLI and GitHub Copilot CLI are doing and notify you when they need you or finish; other recognised agents get icons and notifications when they emit [OSC 7501](../../reference/agents/#program-status-protocol). The limitations below apply when no OSC 7501 report exists. Codex's `!` comes from its terminal title, so it is lost if you take the activity out of that title. opencode never shows `!`: it doesn't save a pending permission or question anywhere cornercase can read, so it shows working until it finishes. Two opencode in the same folder show neither an icon nor a model/context line. Gemini's icons need its dynamic window title; disabling or hiding it gives no status. Two Gemini using the same home and folder hide their conversation data. All eight show model and context lines. Cursor CLI shows `!` only with `/status-indicators` turned on in Cursor, and has no token counts for Stats. Its chat store is read from Cursor CLI 2026.10.14's code, not a live session, so a different layout shows no model or context rather than a wrong one. Grok Build shows `!` for a permission, a question or a plan approval, and keeps working through other tools. A background shell does not keep its turn open. GitHub Copilot CLI shows `!` for a permission prompt, a question it asks you or a plan awaiting approval; its rate-limit and session-limit questions are not written to its session files, so they show as working. Its npm (`npm-loader.js`) and `gh copilot` paths and macOS have not been checked live. Vibe CLI reports `done` at the end of a successful turn, so a hidden tab gets `✓`; a failed turn reports `error` then `idle` at once, so its red `!` can pass before the failure notice. Its Stats have no cache-write split, since the store's cumulative usage has no field for it. Subagents keep an agent working only for Claude Code and GitHub Copilot CLI (Vibe CLI reports its subagents as a count, while its own OSC reports decide the icon): for Codex, Grok Build and Cursor CLI the tab follows the agent's own turn (Gemini CLI and opencode run subagents inside the turn anyway). A subagent that has written nothing for 10 minutes stops counting, and Claude Code's teammates and workflows are not counted. Subagents parked by `Esc` were not checked live. Agents have to run locally in the pane: through `ssh` or inside a container, cornercase can't see them. |
| **Codex context needs an identifiable rollout** | Verified against Codex CLI 0.160.0. cornercase must be able to inspect the agent's environment and open files (`/proc` on Linux; process metadata and `/usr/sbin/lsof` on macOS). Missing or ambiguous sessions omit the line. When Codex's background app-server writes the sessions, cornercase matches them by folder, so two Codex in the same folder show no line. Missing usage/window data shows the model alone. |
| **The context window is worked out** | Claude Code doesn't write the size of its context window anywhere, so cornercase works it out from the model and Claude's settings. After switching models with `/model`, or on an account without the 1M window, the percentage under a tab can be off; see [How full the context is](../../guides/projects-workspaces-tabs/#how-full-the-context-is). |
| **Ids change with the server** | The ids that the [commands for scripts and agents](../../guides/scripts-and-agents/#ids-and-where-commands-act) take last as long as the server runs. After a restart the same tabs get new ids, so take them from `cornercase status` again. |
| **Restarting an agent on another account** | [`account restart`](../../guides/accounts/#restart-open-agents-on-another-account) moves Claude Code's and Codex's conversation into the other account's folder as hard links (one file in both folders), but not Claude Code's rewind of past file edits; Gemini CLI starts a new conversation. When the two folders are on different disks the files are copied instead, so going back to the first account later fails (its copy lacks what was added since); and cornercase never writes through a symbolic link, so a `projects` or `sessions` folder that links elsewhere stops the restart with a message saying so. Codex resuming a conversation moved this way has only been tested with a stand-in for Codex, not the real one. A shell can only be restarted on another account at its prompt: stop the program in it first. Restarts waiting for an agent's turn are forgotten by `cornercase kill-server`. |
| **Agent readiness is a guess** | cornercase decides when a shell or an agent is ready by watching its output settle. A very slow agent may get its prompt late, or not at all; see [The launch](../../guides/issues-and-agents/#the-launch). |

## On Windows

cornercase runs natively on Windows 11 and Windows 10 from version 1809, on x64. Its tests run on Windows on every change, but it has been tried by hand on Windows 11 only, so expect rough edges. Most of what these pages describe works there too; these are the gaps known today:

| Limitation | What it means for you |
| --- | --- |
| **A Windows computer at the other end is new** | [`cornercase remote`](../../guides/remote/) and `--remote` work from Windows with the OpenSSH client that comes with it, and a Windows computer can be the other end too, through cmd or PowerShell ([A Windows machine at the other end](../../guides/remote/#a-windows-machine-at-the-other-end)). That end was tried against a stand-in for Windows' OpenSSH Server, not a real one yet, nor with PowerShell 7 as its shell. There, ending a `restart --when-idle` or `update --when-idle` here doesn't call off its wait, which goes on until the agents are idle. [Opening cornercase from your phone](../../guides/phone/) and the [Telegram](../../guides/telegram/) and [Discord](../../guides/discord/) bots haven't been tried end to end on Windows yet (a real phone over `tailscale serve`, a real bot). ([#603](https://github.com/usecornercase/cornercase-terminal/issues/603)) |
| **PowerShell doesn't say where it is** | `cd` in PowerShell doesn't change its process's folder, and its default prompt doesn't report the folder either, so a PowerShell pane counts as being in the folder it started in: a new tab, a relative path you click and `cornercase status` start from there. A prompt that reports its folder (OSC 7, or OSC 9;9 as in Windows Terminal's docs, which oh-my-posh and Starship can send) fixes it. cmd and Git Bash are followed as on Linux. |
| **A background job counts as running** | A program started in the background (`start /b` in cmd, `&` in PowerShell 7 or Git Bash) can't be told from one the shell waits for, so while it runs the tab is named after it and cornercase treats the pane as busy: `cornercase wait` keeps waiting and closing a worktree warns that a program runs. |
| **Some agent arguments are refused** | In a PowerShell pane (the default), Windows PowerShell 5.1 hands a program a word holding `"`, or holding a space and ending with `\`, in pieces, and passes the words after a bare `--%` without their quotes, so cornercase refuses to start an agent whose launch line has such a word (JSON in `agent_args` among them) and says which one. cmd doesn't read quotes at all, so a cmd pane gets each word as it is, and a word holding a space or one of `& \| < > ^ % ! "`, an empty word, or a program path holding `=`, `,` or `;` is refused there. A Git Bash pane gets the line quoted for bash, so every word reaches the agent whole, except that Git Bash turns a word that looks like a Unix path (`/opt/x`, `--add-dir=/c/x`) into a Windows one, as for any program it starts (`MSYS_NO_PATHCONV=1` stops it). In a PowerShell pane, an agent installed with npm starts through `node` directly, whatever its folder or arguments hold, when cornercase can read the shim npm wrote. Another batch file, or an npm shim cornercase can't read (an older npm's; pnpm's and yarn's shims too), is refused a line holding `& \| < > ^ % !`, which cmd would read as its own. ([#632](https://github.com/usecornercase/cornercase-terminal/issues/632)) |
| **`file://` folders in a `.code-workspace`** | In a `.code-workspace` file, folders written as `file://` URIs are skipped; plain paths work. |
| **Some texts still look Unix** | The help of `cornercase logs` and of `cornercase flow` names Unix folders in its examples, and `cornercase status` writes a path under your user folder as `~/` followed by the rest with backslashes. |
| **x64 only** | There is no native Arm build; Windows on Arm runs the x64 one under emulation. |

## On purpose

| Choice | Why |
| --- | --- |
| **No keyboard shortcuts unless you ask** | Every key belongs to the program in the active pane until you choose a [prefix key](../../reference/keyboard-and-mouse/#keyboard-shortcuts), and then only that key is taken. See the [FAQ](../faq/#why-is-everything-a-mouse-click). |
| **No nesting** | Running `cornercase` inside one of its own panes is refused, because the inner one would fight the outer one for the mouse and the screen. The [commands for scripts and agents](../../guides/scripts-and-agents/) work there, and so does [`cornercase remote`](../../guides/remote/), which shows another machine's server. |
