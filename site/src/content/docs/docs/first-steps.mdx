This tour takes you through a normal session: opening projects, starting a line of work, splitting a tab and leaving everything running. You only need the mouse; keys always go to the shell in front of you.

## Start in a project folder

Open your terminal in a project and run `cornercase`:

```sh
cd ~/code/shop
cornercase
```

The first time, cornercase starts its background server and opens the folder you started from as your first project, with one tab running your shell:

<Screen
  name="first-run"
  alt="cornercase right after starting in the shop folder: the shop project in the sidebar, its main workspace with a bash tab, an existing worktree called feat/dark-mode, and the shell on the right"
  caption="A fresh start in ~/code/shop. The feat/dark-mode worktree already existed, so it shows up on its own."
/>

On the left are your projects and the workspaces of the active one, in one column with the projects on top (you can also [put them side by side or in one tree](../guides/projects-workspaces-tabs/#arrange-the-columns)); the rest is the pane:

| Area | What it holds |
| --- | --- |
| Top left | The **search bar**: click it to jump to any project, workspace or tab. |
| **Projects** | Every project you opened, with its number of workspaces, optionally in [groups](../guides/projects-workspaces-tabs/#groups). `+ New` at the end of the list; `Settings`, [`Usage`](../guides/projects-workspaces-tabs/#plan-usage) and `Quit` at the bottom, with an [update](../installation/#update) button next to `Settings` when a new version is out. |
| **Workspaces** | The workspaces of the active project, each with its tabs. `+ Tab` adds a tab to a workspace, `+ New workspace` starts a new one, `Issues` opens the issue browser, `Files` the [files panel](../guides/files/), `TODO` your [TODO list](../guides/todo/). |
| The pane | The active tab: one shell, or several in splits. |

The active project and tab are marked with a cyan bar `▌` on the left edge and a highlighted background. Tabs hang from their workspace on thin tree lines.

## Open another project

<Steps>

1. Click **`+ New`**, then **open project**. A folder picker opens in the folder above your current project.

2. Type to filter the folders. Folders that are git repositories show their branch on the right.

   <Screen
     name="picker-filter"
     crop={[19, 3, 72, 24]}
     alt="The open project folder picker in ~/code with the filter a: api, infra and playground match, api is selected"
     caption="Typing filters the folders; the best match is selected."
   />

3. Press `Enter` to go into the selected folder, then `Enter` again — or click **open** — to open the folder you are in.

</Steps>

You can also click a folder to go into it, `←` or `Backspace` to go up, and type `~` or a path to jump straight there. Opening a folder that is already a project just switches to it. All the picker's tricks are in [Projects, workspaces and tabs](../guides/projects-workspaces-tabs/#open-a-project).

## Start a line of work

A **workspace** is a line of work in a project: a feature, a bug, an experiment. Every project starts with one, the project folder itself.

<Steps>

1. Click **`+ New workspace`** under the workspaces.

2. Type a name. When the project folder is the root of a git repository, the name is also a branch and **with its own worktree** is ticked: the workspace gets its own checkout of the repository, so its files don't mix with your other work.

   <Screen
     name="new-workspace"
     crop={[23, 10, 64, 10]}
     alt="The new workspace dialog: name feat/login, in ~/.cornercase/worktrees/shop/feat-login, with its own worktree ticked, create and cancel buttons"
   />

3. Click **create** or press `Enter`. cornercase runs `git worktree add` and opens a shell in the new checkout.

</Steps>

Untick the box (click it or press `Tab`) to create a workspace in the project folder itself instead. Worktrees have a page of their own: [Git worktrees](../guides/worktrees/).

## Add tabs and split them

Click **`+ Tab`** under a workspace to open another shell in its folder. Tabs are named after the program running in them, so a tab where you start `nvim` is called `nvim`.

To split a tab, **right-click** inside a pane:

<Screen
  name="pane-menu"
  crop={[48, 6, 62, 12]}
  alt="The pane menu opened with a right-click on a pane: split right, split down, send right-clicks to the pane, close pane"
/>

- **split right** and **split down** open a new shell next to the pane, in the same folder.
- **close pane** ends the shell in that pane.
- Drag a divider to resize the panes; double-click it to make them equal again.
- Drag a pane with the right button onto an edge of another to move it there, or onto its middle to swap the two.
- Click a pane to make it the active one: inactive panes are dimmed.

## Copy and paste

Drag over text in a pane to select it. When you release the button, cornercase copies the text to your clipboard and confirms it with a small toast. Programs that use the mouse themselves, such as htop or an editor with mouse support turned on, get the drag instead.

Paste with your terminal's usual paste keys; the text goes to the program in the active pane.

<Aside type="note" title="Clipboard access">
cornercase copies through your terminal with the OSC 52 escape sequence, so it also works over SSH. Some terminals ask you to allow it first: in iTerm2, enable *Applications in terminal may access clipboard*; in tmux, `set -g set-clipboard on`.
</Aside>

## Close things

Hover a project, workspace or tab: its row gets a lighter background and a `⋯` and a `×` appear at its end. Clicking `×` closes it and ends the programs inside; `⋯` opens its menu. Closing a project asks first, because it stops every program in it; so does closing a workspace that has its own worktree, because it also deletes the worktree's folder (never the branch). In the [compact layout](../guides/small-terminals/) both are always there, and closing a tab or a workspace asks first too.

To rename something, click the `⋯` at the end of its row, or right-click the row. A project's menu also moves it into a [group](../guides/projects-workspaces-tabs/#groups).

## Leave and come back

Click **`Quit`** at the bottom of the projects column, or simply close the terminal window. cornercase detaches, but your shells, editors and agents keep running in the background server.

Run `cornercase` again, from any terminal, and you are back where you left off. You can even attach from two terminals at once: they show the same session.

```sh
cornercase              # attach again
cornercase kill-server  # stop the server and every shell in it
```

After `kill-server` or a reboot, the next `cornercase` brings back your projects, workspaces, tabs and splits, each pane with a fresh shell in its folder. See [Sessions and the server](../guides/sessions/).
