cornercase is two programs in one binary. A **server** runs in the background and owns every shell, emulator and agent. The `cornercase` command you type is a **client**: it shows what the server draws and sends it your keys and clicks. Because the shells belong to the server, closing the window doesn't close them.

```text
 your terminal ── cornercase (client) ─┐
                                       │  Unix socket
 another terminal ── cornercase ───────┤
                                       ▼
                         cornercase server ── shells, editors, agents
```

## Start, detach, reattach

- **The first `cornercase`** starts the server for you and attaches to it. The server opens the folder you started from as your first project, unless it restores a saved session (see below).
- **Detach** by clicking `quit` at the bottom of the projects column, or by closing the terminal window. Only the client goes away; everything in your panes keeps running.
- **Reattach** by running `cornercase` again, from any terminal and any folder. You find everything as you left it, including programs that kept printing while you were away.

This also works over SSH: run `cornercase` on the remote machine, close the connection when you leave, and reattach when you log in again. Or keep the window on your laptop with `cornercase remote <host>`, which reconnects by itself when the connection drops: see [Remote machines](../remote/).

## Several terminals at once

Run `cornercase` in as many terminals as you like. They all attach to the same server and mirror each other: the same projects, the same active tab, even the same open menu. What you type in one shows up in all of them.

All clients share one screen size: the size of the terminal you used last. Attaching, typing or clicking in a terminal makes it the one in charge; moving the mouse over it does not. A larger terminal shows the session with empty space around it, a smaller one shows it cut off at the right and bottom edges. So attaching from your computer after your phone always fits the computer, even if the phone's connection is still hanging.

## What is saved

The server saves your session to `~/.local/state/cornercase/session.json` (or `$XDG_STATE_HOME/cornercase/session.json`):

- your projects, workspaces and tabs, in the order you put them in, with their custom names;
- your project groups, in order, with their icon, colour, which ones are collapsed and which projects they hold;
- every pane's folder, and how each tab is split, including the divider positions;
- which project, workspace, tab and pane are active;
- the width of the sidebar's columns, the line between stacked lists, the height of the [agents section](../projects-workspaces-tabs/#the-agents-section) and the width of the [changes panel](../changes/), whether it, the [files panel](../files/) or the [TODO panel](../todo/) is open, and which tab the changes panel shows;
- which projects and workspaces are folded in the [tree](../projects-workspaces-tabs/#the-tree);
- the branch each workspace's changes panel compares with, when you picked one;
- which panes send right-clicks to their program;
- the issue browser's last tab and filters.

The [TODO list](../todo/) itself is kept apart, in `todos.json` next to `session.json`.

It saves once your layout has stayed the same for two seconds, so the burst of shells closing when you log out of your computer doesn't overwrite a good session with an empty one.

## What is restored

Processes can't be saved. When a **new** server starts, after `cornercase kill-server`, a reboot or a restart after an [update](../../installation/#update), its first client restores the saved layout: the same projects, workspaces, tabs and splits, each pane with a **fresh shell in its saved folder**. Folders that no longer exist are skipped; a pane whose folder is gone starts in its workspace's folder. If a shell can't start in some folder (one you can no longer enter, say), that tab is left out, everything else comes back, and a message names the projects it was in. If no shell could start at all, a new one opens in the folder you started cornercase from. The session as it was is kept in `session.json.bak`, next to `session.json`.

A server that is already running never restores: reattaching just shows what is there.

## Restart the server

Click **settings**, then **restart** next to **done**, or run:

```sh
cornercase restart
```

Restarting stops every program in your terminals, agents included, so cornercase first lists what is running and asks. Then it saves your session, starts a new server and reopens every attached window on it: your projects, workspaces, tabs and splits come back, each pane with a new shell in its folder. To pick up a Claude Code conversation afterwards, run `claude --continue` in its tab.

## Stop the server

```sh
cornercase kill-server
```

This ends every shell and program in every pane, and closes all attached clients. When something was running, it says what it stopped, such as `stopped 1 agent and 2 other programs`. If no server is running, it says `no cornercase server is running`. The server also stops when it receives `SIGTERM` or `SIGINT`; it ignores `SIGHUP`, so a closed terminal or SSH connection doesn't take it down.

## Updating cornercase

When you [update](../../installation/#update) from the app, its last step, **restart now**, saves your session, restarts the server on the new binary and reopens every attached terminal on it. [`cornercase update`](../../reference/command-line/#cornercase-update) does the same from a shell when you answer `y`. Your layout comes back from the saved session; programs that were running, agents included, are stopped, and each pane starts a new shell in its folder. Before restarting, cornercase says what is running right now, so you can wait for an agent to finish first: how many agents are working or waiting for you, and which other programs run where. Panes sitting at their shell prompt aren't listed.

A client only attaches to a server built from the same binary. If you skip the restart, or update with Homebrew or by rebuilding, the old server keeps running and the next `cornercase` asks:

```text
The running cornercase server comes from another build; cornercase was probably updated.
Restarting stops every program running in cornercase's terminals. Running now: 2 agents (1 working,
1 waiting for you) and 1 other program (`npm` in shop › main). Your projects, workspaces, tabs and
splits come back, each tab with a new shell in its folder. To pick up a Claude Code conversation
afterwards, run `claude --continue` in its tab.
Restart it now? [y/N]
```

Save your work in the panes and answer `y`. Answer anything else to keep the old server for now; restart it later with `cornercase kill-server`, then `cornercase`.

## A separate server

`CORNERCASE_SOCKET` points cornercase at another socket, which means another, completely independent server:

```sh
CORNERCASE_SOCKET=/tmp/cc-demo/server.sock cornercase
```

That server keeps its own settings, saved tokens, session and issue cache in the socket's folder, so it never touches your usual ones. It's handy for trying things out, for a demo, or for keeping two unrelated sets of projects apart. Stop it with the same variable:

```sh
CORNERCASE_SOCKET=/tmp/cc-demo/server.sock cornercase kill-server
```

<Aside type="caution" title="Keep socket paths short">
Unix sockets have a path limit of about 100 bytes (108 on Linux, 104 on macOS). Pick a short path for `CORNERCASE_SOCKET`.
</Aside>

## No cornercase inside cornercase

Every shell that cornercase starts has `CORNERCASE=1` in its environment. Running `cornercase` from inside one of its own panes refuses with:

```text
cornercase is already running in this terminal; nesting it is not supported
```

To attach a second view, use another terminal window.

## The environment of your shells

The server is started by the first client, from that terminal, and keeps that client's environment. Every shell it opens inherits it, plus `TERM=xterm-256color` and `CORNERCASE=1`. The shell itself is your `$SHELL`, or `/bin/sh` if it isn't set.

So if you change an environment variable in your login files, open a new tab to get a shell that reads them again, and restart the server for variables cornercase itself reads, such as `SHORTCUT_API_TOKEN`. The full list is in [Files and environment](../../reference/files-and-environment/).
