If you have two accounts of one agent, say a work and a personal Claude Code subscription, cornercase can keep both logged in and start each new agent with the one you pick, in one click.

- An **account** is a folder of its own in which the agent keeps its login. cornercase hands the folder to the agent through the variable it already reads: `CLAUDE_CONFIG_DIR` for Claude Code, `CODEX_HOME` for Codex, `GEMINI_CLI_HOME` for Gemini CLI.
- Each agent also has its **own login**, the usual one in `~/.claude`, `~/.codex` or `~/.gemini`, called *System* until you give it a name.
- For each agent you choose the account **new tabs** start with. Tabs that are open keep the one they started with, until you [restart them on it](#restart-open-agents-on-another-account), in the same conversation.

cornercase never reads, copies or refreshes a token: you log in with the agent itself, in its account's folder.

Everything here can be done in the window (**Settings › Accounts** and the status bar at the bottom of the window) or from the command line (`cornercase account`).

## Add an account

In **Settings › Accounts**, click **`+ add account`** under the agent and type a name. cornercase makes the folder, closes Settings and opens a tab named `personal login` that runs `claude auth login` with it (`codex login` for Codex, `gemini` for Gemini CLI, where you log in from its first screen). Log in there once.

Each agent's section starts with its own login, then its accounts. Each one says whether it is logged in, and as whom (`signed in as ana@acme.dev (max)`, `signed out`). cornercase asks the agent itself (`claude auth status`, `codex login status`) when you open the tab and every 30 seconds while it shows; it never opens the files the login is kept in. Gemini CLI has no such command, so its accounts show no state. When a token variable such as `ANTHROPIC_API_KEY` is set where the server runs, a line at the top names it: it wins over every account (see below).

From the command line:

```sh
cornercase account add claude personal --login
```

This makes the folder and opens a tab named `personal login` that runs `claude auth login` with it. Without `--login`, [use the account](#choose-the-account-new-tabs-use), open a tab and log in as you would anywhere.

An account's folder name is letters, digits, `.`, `_` and `-`, at most 32. `cornercase account list` shows each agent's own login and accounts, with their folders and names, marks the one in use, and `--check` asks each one whether it is logged in first.

## Name an account

**rename…** under an account, or under the agent's own login, gives it the name the window shows: in the buttons, the tabs, Usage and the start dialogs. Call Claude Code's own login `work` and you can tell it from `personal` at a glance. The folder never moves, since Claude Code finds its login by the folder's path and a new path would log it out; an empty name goes back to the folder's name (or *System*). Two accounts of one agent cannot have the same name.

```sh
cornercase account rename claude --system work      # the agent's own login
cornercase account rename claude personal Personal
cornercase account rename claude personal --clear   # back to its folder's name
```

Commands always name an account by its folder (and `--system` for the agent's own login), never by the name the window shows.

### What the accounts share

A new account links the settings of the agent's usual folder (`~/.claude`, `~/.codex`, `~/.gemini`), so your instructions, skills and commands are the same in every account:

| Agent | Shared | Kept per account |
| --- | --- | --- |
| Claude Code | `settings.json`, `settings.local.json`, `CLAUDE.md`, `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `hooks/`, `keybindings.json`, `statusline*` | the login, `.claude.json`, history, sessions and transcripts, caches |
| Codex | `config.toml`, `AGENTS.md`, `prompts/`, `skills/`, `rules/` | `auth.json`, sessions, history, logs |
| Gemini CLI | `settings.json`, `GEMINI.md`, `commands/`, `extensions/`, `skills/`, `policies/`, `trustedFolders.json` | the login, `.env`, history |

They are symbolic links, made again before each agent starts if one is missing. When an agent saves a setting by replacing a file (a `/model` choice in Claude Code, a trusted project in Codex's `config.toml`), the link becomes a file of that account only: `account list` names it as `not shared`, and cornercase never overwrites it. Delete the file and the next start links it again.

<Aside type="note" title="Claude Code asks for project trust again">
Claude Code keeps your login together with each project's trust and your user-scope MCP servers in one file, `.claude.json`. That file stays with each account, so a new account asks again whether you trust a folder, and does not see MCP servers you added with `claude mcp add --scope user` in the other one. Add them again in that account.
</Aside>

## Choose the account new tabs use

Once you have an account, a status bar along the bottom of the window, under the sidebar, the panes and the side panel, has a button per agent with accounts, such as ` claude: work ▾ `. Click it to see that agent's own login and accounts, the one in use with a check mark, and click another to use it. **manage accounts…** opens Settings › Accounts. The bar is there in every layout, the [compact one](../small-terminals/) too, and the panes give it one row while it shows. When there is no room for every button, they shorten to the account's name (` work ▾ `), and then the last ones are left out.

In **Settings › Accounts**, `Enter` on a row (or a click) does the same; `●` marks the one in use.

From the command line:

```sh
cornercase account use claude personal   # new claude tabs use personal
cornercase account use claude --system   # back to its own login
```

Choosing changes only what starts afterwards, and only for that agent. Tabs that are open keep the account they started with, so you can have a work agent and a personal agent side by side. A split takes the accounts of the pane it splits, and so does `cornercase start` or `cornercase new-tab` run inside a pane (by you or by an agent there) without `--profile`: an agent on `personal` starts its helpers on `personal` too, whatever is in use now. `--account` still changes the agent it names. Run from outside cornercase, and for `cornercase flow run`, they use the account in use. Typing `claude` in a tab you open in the window uses the account in use too: the folder is in the tab's environment.

### Another account once

To start one agent with another account without changing the one in use, pick it in the account list that opens when you [start an issue](../issues-and-agents/) (or ahead with **account…** on its page), in the agent's account list when you start [a flow](../flows/) (one list per agent of the team that has accounts), or in the **Account** list beside the agent when you [schedule](../queue/) one. Each starts on the account in use. From the command line, `--account AGENT=ACCOUNT` (once per agent; `AGENT=` is its own login):

```sh
cornercase start claude --account claude=personal --prompt 'fix the tests'
cornercase new-tab --account claude= --account codex=team
cornercase flow run 'Full issue' --account claude=personal --prompt 'add gift cards'
cornercase queue add --at 18:00 --prompt 'update the docs' --account claude=personal
```

If the account you picked is removed before the agent starts, nothing starts: the issue's and the flow's dialogs say so, and a scheduled agent fails when its time comes and says why. A scheduled agent with no account picked starts with the one in use at that moment. A flow's team keeps the accounts it started with if you change the one in use while it runs.

### Profiles, for scripts

A **profile** picks one account per agent under a name, so a script can switch several agents at once. The window never shows or changes profiles: while one is active, the buttons show its accounts, and choosing an account in the window leaves the profile.

```sh
cornercase profile new Work claude=work codex=work
cornercase profile use Work        # new tabs use Work's accounts
cornercase profile use --system    # every agent back to its own login
cornercase profile list            # the active one is marked with *
```

`profile set Work --provider codex --account personal` changes one agent of a profile, and without `--account` that agent goes back to its own login; `profile set Work --rename Job` renames it; `profile delete Work` deletes it and keeps its accounts. A profile cannot be named `system`, in any case: that name stands for every agent's own login, which `profile use --system` chooses (it also forgets the accounts chosen in the window). `--profile NAME` on `start`, `new-tab` and `flow run` uses a profile once; `--account` wins over it for its agent.

## Restart open agents on another account

An agent reads its account when it starts, so agents already open keep theirs after you choose another. To move them, restart them on it from the command line:

```sh
cornercase account restart claude                  # restart the open claude agents on the account in use
cornercase account restart claude personal         # on personal
cornercase account restart claude --system         # on the agent's own login
cornercase account restart claude personal --pane 4 --pane 7
```

Without `--pane`, every Claude Code agent that runs on another account restarts. With `--pane`, only those panes do, and a pane that is a shell at its prompt, with no agent in it, starts a new shell in the same place and folder with that account, so the `claude` you type next uses it. Nothing is typed into it. A shell running another program is skipped with `stop <program> first`, and one where you are typing a command, or where a script's `send` waits for you, until the line is sent or cleared.

Each agent comes back **in the same pane, in the same conversation**: cornercase stops the pane's shell, starts a new one in the same folder with the other account, and resumes the agent there (`claude --resume`, `codex resume`), with the mode it ran in. The pane keeps its place, its id and its tab. While it comes back the pane shows ` restarting claude on personal… ` with a ` cancel ` button and takes no keys, as after a restart of cornercase.

- **The conversation goes along.** Claude Code and Codex keep a conversation in their account's folder, where the other account cannot see it, so cornercase first adds that conversation's files to the other account's folder (for Claude Code, its transcript and its subagents'; for Codex, its rollout) as hard links, or as checked copies when the two folders are on different disks. It never overwrites or deletes a file: if the other account already has a different file at that place, that agent is not restarted, keeps running as it was, and a message says why. Since a hard link is one file in two folders, what the agent writes after the restart shows in the old account's copy too.
- **Gemini CLI starts a new conversation**: cornercase cannot hand it the old one, so it starts Gemini without `--resume`.
- **Busy agents wait for their turn.** An agent that is working, waiting for your answer, or that was just sent a prompt (by you or by a script) it has not taken yet, restarts once its turn is over; meanwhile its pane shows ` restarts on personal after this turn ` with ` cancel `. Choosing another account in use, or a profile, leaves those waiting restarts as they are; removing the account they wait for drops them, and asking to restart one on the account it already uses cancels its waiting restart. They are not saved: `cornercase kill-server` forgets them.
- **Left as they are**: agents and shells of a [flow](../flows/) (a team keeps the accounts it started with), agents and shells whose folder variable you set yourself (`custom`), and a shell still being set up or resuming an agent. `account restart` lists them as skipped, with the reason.
- **What does not come along**: Claude Code's rewind of past file edits (its `file-history`), and its trust in the folder, which the other account asks again. A shell in which you exported the old account's variable by hand keeps it.

`cornercase status` marks an agent waiting to restart `(restarts after this turn)`, and `cornercase status --json` gives each pane with accounts its `accounts`, one per agent. Choosing an account in the status bar or in Settings › Accounts does not restart anything yet: the window only says that open tabs keep theirs.

## Which account an agent uses

Once you have an account, an agent's tab names it on its second line, after the model: `Opus 5.5 · work · 12%`. So do the tab bar and the [agents section](../projects-workspaces-tabs/#the-agents-section). A narrow column cuts the model first, then the account. An agent on its own login shows that login's name, or `System`, while the agent has accounts, and nothing otherwise; one whose folder variable points somewhere you set yourself shows `custom`.

**Settings › UI** has three switches, on by default and shown only once you have an account: **account** for that mark, **account switcher** for the buttons above `Usage`, and **account picker** for the account lists in the issue, flow and schedule dialogs.

`cornercase status --json` gives each agent's pane an `account`: the account's folder name, or `custom` when its folder variable points somewhere else (one you exported by hand). A pane without one has no `account` key. When cornercase restarts, each agent resumes its conversation with the account it had; if that account was removed meanwhile, the pane comes back as a plain shell and a message names the account.

## Remove an account

Select it in **Settings › Accounts** and press `Backspace`: a dialog asks first and reminds you to log out before (see below). Or:

```sh
cornercase account remove claude personal
```

It asks first, then deletes the account's folder and forgets its name; an agent that used it goes back to its own login, and so does every profile that named it. The agent's own login cannot be removed.

<Aside type="caution" title="Log out first">
On macOS, Claude Code and Codex keep the login in the system keychain, under a name made from the folder's path, which removing the folder leaves behind. cornercase never touches the keychain. To remove the login too, log out in a tab of that account before removing it: `claude auth logout`, or `codex logout`.
</Aside>

## Things to know

- **The folder's path is the login.** Claude Code finds its login in the keychain by the exact path of its folder, and the folders live in cornercase's state folder (`~/.local/state/cornercase/accounts/`, see [Files](../../reference/files-and-environment/)). If you move that folder, set `XDG_STATE_HOME` to another place or run a server with `CORNERCASE_SOCKET`, the path changes and each account has to log in again. A build from source (`cargo run`) has its own accounts.
- **Tokens in the environment win.** `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, `CODEX_API_KEY`, `OPENAI_API_KEY` and the like override the folder's login. cornercase leaves them as they are, and Settings › Accounts and `account list` name the ones set (never their values); unset them in the environment the server starts from if you want the accounts to decide.
- **Gemini CLI with encrypted storage shares one login.** With `GEMINI_FORCE_ENCRYPTED_FILE_STORAGE=true`, Gemini CLI keeps its login in one keychain item for every folder, so its accounts cannot be told apart. Leave it unset to use accounts.
- **Which agents.** Claude Code, Codex and Gemini CLI. GitHub Copilot CLI, Cursor CLI and Grok Build may keep their login in a place that does not depend on the folder, so they are left out until that is checked; opencode uses providers of its own.
- **From a program**: the requests are `account-list`, `account-add`, `account-remove`, `account-rename`, `account-use`, `profile-list`, `profile-new`, `profile-set`, `profile-use`, `profile-delete` and `account-restart`; `start`, `new-tab` and `flow-run` take `profile` and `accounts`, and the queue's entries `accounts`; `cornercase contract` lists the features `accounts`, `account-login` (`account-list` with `check`), `account-switch` (`account-rename`, `account-use` and the `accounts` field) and `account-restart`. See [Scripts and agents](../scripts-and-agents/#accounts-and-profiles).
