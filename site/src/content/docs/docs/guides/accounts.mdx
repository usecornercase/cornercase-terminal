If you have two accounts of one agent, say a work and a personal Claude Code subscription, cornercase can keep both logged in and start each new agent with the one you pick.

- An **account** is a folder of its own in which the agent keeps its login. cornercase hands the folder to the agent through the variable it already reads: `CLAUDE_CONFIG_DIR` for Claude Code, `CODEX_HOME` for Codex, `GEMINI_CLI_HOME` for Gemini CLI.
- A **profile** picks one account per agent, such as *Work* (Claude Code's `work`, Codex's `work`) or *Home*. An agent the profile does not name keeps its usual login.
- The **active profile** applies to every tab and agent started after you choose it. *System*, the default, is no profile at all: each agent uses its own usual login.

cornercase never reads, copies or refreshes a token: you log in with the agent itself, in its account's folder.

For now accounts are managed from the command line; a button in the window comes in a later release.

## Add an account

```sh
cornercase account add claude work --login
```

This makes the folder and opens a tab named `work login` that runs `claude auth login` with it (`codex login` for Codex, `gemini` for Gemini CLI, where you log in from its first screen). Log in there once. Without `--login`, start the agent in a tab of a profile that uses the account and log in as you would anywhere.

An account name is letters, digits, `.`, `_` and `-`, at most 32. `cornercase account list` shows each agent's accounts and their folders.

### What the accounts share

A new account links the settings of the agent's usual folder (`~/.claude`, `~/.codex`, `~/.gemini`), so your instructions, skills and commands are the same in every account:

| Agent | Shared | Kept per account |
| --- | --- | --- |
| Claude Code | `settings.json`, `settings.local.json`, `CLAUDE.md`, `agents/`, `commands/`, `skills/`, `plugins/`, `output-styles/`, `hooks/`, `keybindings.json`, `statusline*` | the login, `.claude.json`, history, sessions and transcripts, caches |
| Codex | `config.toml`, `AGENTS.md`, `prompts/`, `skills/`, `rules/` | `auth.json`, sessions, history, logs |
| Gemini CLI | `settings.json`, `GEMINI.md`, `commands/`, `extensions/`, `skills/`, `policies/`, `trustedFolders.json` | the login, `.env`, history |

They are symbolic links, made again before each agent starts if one is missing. When an agent saves a setting by replacing a file (a `/model` choice in Claude Code, a trusted project in Codex's `config.toml`), the link becomes a file of that account only: `account list` names it as `not shared`, and cornercase never overwrites it. Delete the file and the next start links it again.

<Aside type="note" title="Claude Code asks for project trust again">
Claude Code keeps your login together with each project's trust and your user-scope MCP servers in one file, `.claude.json`. That file stays with each account, so a new account asks again whether you trust a folder, and does not see MCP servers you added with `claude mcp add --scope user` in the other one. Add them again in that account.
</Aside>

## Make and choose a profile

```sh
cornercase profile new Work claude=work codex=work
cornercase profile new Home claude=personal
cornercase profile use Work        # new tabs and agents use Work's accounts
cornercase profile use --system    # back to each agent's usual login
cornercase profile list            # the active one is marked with *
```

`profile set Work --provider codex --account personal` changes one agent of a profile, and without `--account` that agent goes back to its usual login; `profile set Work --rename Job` renames it; `profile delete Home` deletes it and keeps its accounts. A profile cannot be named `system`, in any case: that name stands for *System*, which `profile use --system` chooses.

Choosing a profile changes only what starts afterwards. Tabs that are open keep the accounts they started with, so you can have a work agent and a personal agent side by side. A split takes the accounts of the pane it splits. Typing `claude` in a new tab uses the active profile too: the folder is in the tab's environment.

To use another profile once, without changing the active one:

```sh
cornercase start claude --profile Home --prompt 'fix the tests'
cornercase new-tab --profile ''            # the agents' usual logins
cornercase flow run 'Full issue' --profile Work --prompt 'add gift cards'
```

A flow's team gets the profile's accounts when it starts, and keeps them if you change the active profile while it runs.

## Which account an agent uses

`cornercase status --json` gives each agent's pane an `account`: the account's name, or `custom` when its folder variable points somewhere else (one you exported by hand). A pane without one has no `account` key. When cornercase restarts, each agent resumes its conversation with the account it had; if that account was removed meanwhile, the pane comes back as a plain shell and a message names the account.

## Remove an account

```sh
cornercase account remove claude work
```

It asks first, then deletes the account's folder and takes it out of every profile, whose agent goes back to its usual login.

<Aside type="caution" title="Log out first">
On macOS, Claude Code and Codex keep the login in the system keychain, under a name made from the folder's path, which removing the folder leaves behind. cornercase never touches the keychain. To remove the login too, log out in a tab of that account before removing it: `claude auth logout`, or `codex logout`.
</Aside>

## Things to know

- **The folder's path is the login.** Claude Code finds its login in the keychain by the exact path of its folder, and the folders live in cornercase's state folder (`~/.local/state/cornercase/accounts/`, see [Files](../../reference/files-and-environment/)). If you move that folder, set `XDG_STATE_HOME` to another place or run a server with `CORNERCASE_SOCKET`, the path changes and each account has to log in again. A build from source (`cargo run`) has its own accounts.
- **Tokens in the environment win.** `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, `CODEX_API_KEY`, `OPENAI_API_KEY` and the like override the folder's login. cornercase leaves them as they are; unset them in the environment the server starts from if you want the accounts to decide.
- **Gemini CLI with encrypted storage shares one login.** With `GEMINI_FORCE_ENCRYPTED_FILE_STORAGE=true`, Gemini CLI keeps its login in one keychain item for every folder, so its accounts cannot be told apart. Leave it unset to use accounts.
- **Which agents.** Claude Code, Codex and Gemini CLI. GitHub Copilot CLI, Cursor CLI and Grok Build may keep their login in a place that does not depend on the folder, so they are left out until that is checked; opencode uses providers of its own.
- **From a program**: the requests are `account-list`, `account-add`, `account-remove`, `profile-list`, `profile-new`, `profile-set`, `profile-use` and `profile-delete`, and `start`, `new-tab` and `flow-run` take `profile`; `cornercase contract` lists the feature `accounts`. See [Scripts and agents](../scripts-and-agents/#accounts-and-profiles).
