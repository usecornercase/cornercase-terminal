Every tab holds one or more **panes**. Each pane is a real terminal running its own shell, emulated by Ghostty's terminal core, so full-screen programs such as nvim, htop, fzf, lazygit and coding agents behave as they do in a regular terminal.

## Split a pane

**Right-click** inside a pane to open its menu:

<Screen
  name="pane-menu"
  crop={[48, 6, 62, 12]}
  alt="The pane menu: split right, split down, send right-clicks to the pane, close pane"
/>

| Item | What it does |
| --- | --- |
| **split right** | Opens a new shell to the right of the pane. |
| **split down** | Opens a new shell below the pane. |
| **send right-clicks to the pane** | Lets the program in this pane have right-clicks; see [below](#right-clicks-inside-programs). |
| **close pane** | Ends the program in this pane and removes it. |

The new pane starts in the folder the pane you split is currently in, and becomes the active one. A split is only offered when both halves would still be usable: at least 10 columns wide or 3 rows tall each.

You can split a pane again and again; the dividers join up like in Ghostty. When the program in a pane exits, the pane closes and its neighbour takes the space. Closing the last pane closes the tab.

## Focus, resize and dim

- **Click a pane** to make it active. That first click only moves the focus; it is not sent to the program.
- **Drag a divider** to resize the panes on both sides. It lights up cyan while you hover or drag it, and stops where a pane on either side, including panes split inside it, would get smaller than 10 columns or 3 rows. **Double-click** a divider to split the space in half again.
- **Inactive panes are dimmed** so you always know where your keys go. You can turn this off in **settings → TUI → inactive panes**.

Programs are told about every size change, and Ghostty's emulator reflows their output, so long lines rewrap instead of being cut.

### When the tab gets too small

When the terminal shrinks, for example when you attach from a phone, the panes shrink too, each down to 10 columns and 3 rows. If even that doesn't fit, the tab shows only its active pane, over the whole tab, until there is room again. The other panes keep running at their last size, and the tab goes back to its splits, with the same proportions, as soon as they fit. Meanwhile the pane menu offers no split.

## The keyboard

Every key goes to the active pane. cornercase has no shortcuts of its own, so `Ctrl+B`, `Ctrl+A`, `Alt` combinations and function keys all reach your program.

Keys are encoded the way a modern terminal does it: when a program turns on the kitty keyboard protocol, cornercase speaks it, and it asks your own terminal for the same so that combinations like `Shift+Enter` and `Ctrl+Enter` keep their modifiers. See [Keyboard and mouse](../../reference/keyboard-and-mouse/) for the details.

## The mouse inside programs

When the program in a pane asks for the mouse (htop, lazygit, nvim with `mouse=a`), cornercase sends it clicks, drags and the scroll wheel, in the encoding the program asked for and relative to the pane.

When the program doesn't ask for the mouse, dragging selects text instead; see below. There is no scrollback navigation in cornercase yet, so the wheel does nothing over a plain shell.

### Right-clicks inside programs

Right-clicks normally open cornercase's pane menu, even while a program uses the mouse, because almost no program needs the right button. For the ones that do, choose **send right-clicks to the pane** in the pane menu: from then on, right-clicks go to the program in that pane while it uses the mouse.

When the program stops using the mouse, a right-click opens the menu again, and the same item now reads **use this menu on right-click** to switch back. The choice belongs to that pane and is saved with your session.

## Copy text

When the program doesn't use the mouse, press, drag and release over text to select it. On release, cornercase copies the selection to your clipboard and says so in a toast:

<Screen
  name="toast"
  crop={[47, 20, 63, 10]}
  alt="The bottom right of the screen with a green toast that says copied to clipboard over the test output"
/>

The copy goes through your terminal with the OSC 52 escape sequence, so it reaches your local clipboard even when cornercase runs on another machine over SSH.

Programs can copy too. When a program in a pane writes to the clipboard with OSC 52 (nvim's OSC 52 clipboard, for example), cornercase passes the text on to your terminal and shows the same toast. Requests to *read* your clipboard, and writes to the primary selection, are dropped.

<Aside type="note" title="If nothing reaches the clipboard">
Some terminals need you to allow OSC 52. In iTerm2, enable *Applications in terminal may access clipboard*. In tmux, add `set -g set-clipboard on` to your `tmux.conf`.
</Aside>

## Paste

Paste with your terminal's usual keys. cornercase hands the text to the program in the active pane, wrapped in bracketed-paste markers when the program asked for them, so shells and editors can tell a paste from typing.

While a dialog or the search is open, a paste goes into its text field instead.
