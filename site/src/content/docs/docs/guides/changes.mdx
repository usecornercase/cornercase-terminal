The changes panel shows the diff of the active workspace in a column on the right of its panes. It follows the workspace as it changes, so you can watch an agent edit files, review its work as it goes, and point it at a hunk without leaving cornercase.

## Open and close it

The panel is there for workspaces inside a git repository. Click **`changes`** at the bottom of the sidebar, next to `issues`, to open it, and again (or **`×`** in the panel) to close it. It shares its column with the [TODO panel](../todo/): opening one closes the other. The button shows how many files changed, such as `changes 3`, even while the panel is closed.

The panel follows the active workspace: switch workspaces and it shows the other one's changes. Drag its left border to make it wider or narrower; a double click on the border gives it back its automatic width, half of the room right of the columns. Whether it is open, which tab it shows and its width are kept in the [saved session](../sessions/#what-is-saved).

In the [compact layout](../small-terminals/), a **`±`** button in the top bar opens the panel over the whole screen.

## What it compares

Three tabs at the top choose what you see:

| Tab | Shows |
| --- | --- |
| **uncommitted** | What isn't in a commit yet: staged and unstaged edits, and new files git doesn't track yet. |
| **commits** | What the branch committed since it left the base branch. |
| **all** | Both: everything the branch changed, committed or not, which is what its pull request will show. |

**commits** and **all** compare with a base branch, shown at the right of the summary as `vs main ▾`. It is the repository's default branch: the one `origin/HEAD` points to, or else a local `main` or `master`. The comparison starts where your branch left the base, like a pull request on GitHub, so commits that land on the base later don't show up as changes of yours.

## Reading a diff

- The summary line counts the files and the lines added and removed, with a bar for the proportion.
- Each file has a row with its status (`M` modified, `A` added, `D` deleted, `R` renamed), its path and its counts. Click it to fold or unfold it.
- Each hunk starts with a thin line naming the function or block it is in. Lines carry their old and new numbers, a green or red bar, and a stronger colour on the words that changed when a line was edited rather than replaced.
- Code is highlighted with your terminal's palette.
- Between two hunks, **`↕ 12 unchanged lines`** shows the code in between when you click it.
- Lockfiles (`Cargo.lock`, `package-lock.json`, `pnpm-lock.yaml` and the like) start folded. Binary files and files with thousands of changed lines show their counts but no lines.
- When a diff is long, every file starts folded. **`fold all`** at the bottom folds or unfolds them all.

## Filter the files

Click **`⌕`** next to the panel's `×` to show only some files. A field opens under the tabs, and what you type goes to it instead of your pane:

<Screen
  name="changes-filter"
  crop={[95, 0, 45, 30]}
  alt="The all tab with !tests.rs in the filter field: 2 of 3 files, src/returns/address.rs and src/returns/mod.rs shown"
/>

| Type | Shows |
| --- | --- |
| `order` | Files whose path contains `order`, such as `src/order.rs` or `src/orders/list.ts`. |
| `*.test.js` | Only the test files. |
| `src/api/**` | Only the files under `src/api`. |
| `*.ts *.rs` | TypeScript and Rust files: every word adds files. |
| `!*.snap !*.lock` | Every file but snapshots and lockfiles. |
| `src/ !*.test.js` | What is under `src/`, without its tests. |

- A word without `*` or `?` is a piece of the path. With them it is a pattern, as in `.gitignore`: without `/` it matches a file or folder name anywhere (`*.test.js` finds `src/cart/total.test.js`), with `/` it matches from the root of the workspace, `*` stays within a folder, `**` crosses folders, and a pattern ending in `/` matches only folders.
- A word that starts with `!` leaves the files it matches out.
- Case is ignored unless the word has an uppercase letter. A renamed file matches by its old path too.
- The summary counts what is left, such as `3 of 31 files`.
- **`Enter`** keeps the filter and gives the keys back to your pane. **`Esc`** or the field's **`×`** closes it and shows every file again.

Clicking in a pane also gives it the keys back and keeps the filter; a click on the field takes them again. The filter stays when you switch tabs or workspaces, and isn't saved with the session.

### Mark files as viewed

Hover a file row and click the **`✓`** at its right to mark it as viewed: it folds, and the footer counts how many you have viewed. When the file changes again, for example because the agent touched it, the mark goes away and it opens again, so you only review what is new.

## Act on a hunk

Hover a hunk and three buttons appear on its first line:

| Button | Does |
| --- | --- |
| **open** | Opens the file in a new tab, at the hunk's first changed line, with your `$VISUAL` or `$EDITOR` (or `vi`). The tab closes when you quit the editor. |
| **ask agent** | Types a reference such as `src/returns/address.rs:11-12 ` into the agent running in this workspace and switches to its tab, so you can write your question after it. Without an agent in the workspace, it copies the reference to your clipboard instead. |
| **copy** | Copies the hunk, as a patch, to your clipboard. |

The editor gets the line as `+11`, which `vi`, `vim`, `nvim`, `nano`, `emacs` and `micro` understand.

## Live, and light on your repository

While the panel is open it asks git for changes every second, so edits show up shortly after they are saved; while it is closed it checks every three seconds, for the count on the button. It runs git in the background with options that never take git's index lock, so it doesn't get in the way of an agent running `git add` or `git commit` at the same time. When nothing changed, nothing is redrawn.

<Aside type="tip">
The green and red backgrounds are mixed from your terminal's own background and palette when your terminal supports 24-bit colour and says so in `COLORTERM` (most modern terminals set `COLORTERM=truecolor`). Without it, cornercase uses palette colours: on dark themes the changed lines get only the coloured bar and numbers, with the changed words highlighted.
</Aside>
