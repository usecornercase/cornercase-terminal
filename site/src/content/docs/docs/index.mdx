cornercase is a terminal multiplexer for working on several things at once. It keeps your **projects** in a sidebar, gives each line of work its own **workspace** (optionally its own git worktree and branch), and runs as many **tabs** and **split panes** of real shells as you need. It can also read an issue from GitHub, Shortcut or Linear and start a coding agent on it, in a fresh worktree, in a few clicks.

Everything is a button. There is no prefix key to learn and no shortcut that steals keys from your shell, your editor or your agent: every key you type goes to the program in front of you. If you'd rather use the keyboard, an [optional prefix key](reference/keyboard-and-mouse/#keyboard-shortcuts) opens a menu of shortcuts.

## How it is organised

Each level lives inside the one before it, and each one has its own column or area on screen:

```text
shop                       project     a folder
├── main                   workspace   the folder itself
│   ├── nvim               tab
│   └── bash               tab
├── feat/login             workspace   its own worktree
│   └── bash               tab
└── #482 Returns page …    workspace   from an issue
    └── claude             tab         split in two panes
```

- **Projects** are folders. The sidebar on the left lists them, with the number of workspaces each one has, optionally in groups with an icon and a colour.
- **Workspaces** are lines of work inside a project. The first one is the project folder itself; you can add more, and in a git repository each one can get its own [worktree](guides/worktrees/).
- **Tabs** are shells inside a workspace. A tab is named after whatever runs in it: `bash`, `nvim`, `claude`. A tab running Claude Code, Codex or opencode also shows whether it is [working, needs you or finished](guides/projects-workspaces-tabs/#what-your-agents-are-doing), and [how full its context is](guides/projects-workspaces-tabs/#how-full-the-context-is). The optional [agents section](guides/projects-workspaces-tabs/#the-agents-section) lists every agent in every project, one click from each.

Claude Code, Codex and opencode tabs show their model and [context use](guides/projects-workspaces-tabs/#how-full-the-context-is), with a percentage when it is available.
- **Panes** split a tab, right or down, like in Ghostty. Each pane is a real terminal.

## A few deliberate choices

**Mouse first.** Out of the box cornercase has no keyboard shortcuts of its own. Keys always reach the program in the active pane, so `Ctrl+B`, `Alt` combinations and everything your editor or agent uses keep working. Inside a dialog, `Enter` confirms and `Esc` cancels. Shortcuts are there if you want them, behind a [prefix key](reference/keyboard-and-mouse/#keyboard-shortcuts) you choose.

**A real terminal inside.** Panes are emulated with [libghostty-vt](https://github.com/ghostty-org/ghostty), the core of the Ghostty terminal. It answers the queries that programs like nvim, fzf, htop and full-screen agents wait for, supports the kitty keyboard protocol, and reflows text when a pane is resized.

**The server owns your shells.** The `cornercase` command is a thin client that only draws what the server sends it. Quitting detaches; the shells keep running until you stop the server.

**Your colours.** cornercase asks your terminal for its colours when it starts and draws everything with palette colours, so it looks right in light and dark themes alike.

:::note
cornercase is young and moving fast. It runs on **Linux** and **macOS**.
:::
