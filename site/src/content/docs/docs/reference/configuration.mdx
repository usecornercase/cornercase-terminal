cornercase is configured from the **Settings** modal, opened from **`More ▴` › settings** at the bottom of the sidebar. Every change is saved at once to `config.json`, so there is nothing to apply or restart. You can also edit the file by hand, and the server applies it within a second; this page lists every key. A script or another app reads and changes the same settings with [`cornercase config`](../../guides/scripts-and-agents/#settings).

## The settings modal

The modal has eight tabs: Worktrees, Agents, Accounts, Flows, Issues, UI, Remote and Plugins. Click a row, or select it and press `Enter`, to change it; the line at the bottom explains what the selected row does and confirms every change.

The ` share ` button hands your settings to a colleague, or imports theirs: see [Share your setup](#share-your-setup). The ` restart ` button next to ` done ` restarts cornercase. It first lists what is running in your terminals, since restarting stops every program in them; your projects, workspaces, tabs and splits come back, each tab with a new shell in its folder. See [Restart the server](../../guides/sessions/#restart-the-server).

| Row | What it sets |
| --- | --- |
| **worktrees folder** | Where new [worktrees](../../guides/worktrees/) are checked out: `<folder>/<repository>/<branch>`. Must be an absolute path or start with `~/`. |
| **fetch branches every** | How often, in minutes, the remotes are fetched to show the [commits to pull](../../guides/worktrees/#commits-to-pull) as `↓n` on each workspace. `0` turns it off. |
| **merged PRs in stats** | On (the default): Usage → Stats counts your merged pull requests and merge requests, read with `gh` and `glab`. Off: nothing is asked. The note names the accounts read, or why none were. See [Usage and stats](../../guides/projects-workspaces-tabs/#usage-and-stats). |
| **pull requests** | On (the default): each workspace whose branch has a pull request on GitHub, or a merge request on GitLab, shows its number, the state of its checks (its pipeline's jobs on GitLab) and whether it has merge conflicts, and on GitHub its layer in a stack, read with `gh` or `glab`. Off: nothing is asked. The note says why none show when every project read with one of them fails, because it is missing, logged out or failing. See [Pull requests and their checks](../../guides/worktrees/#pull-requests-and-their-checks). |
| **shared files** | Off (the default): no workspace is scanned for the files it shares with the others. On: when two workspaces of a project change the same files, both rows show `⇄n` and those files carry `⇄` in the changes panel, from a git scan every few seconds in projects with two or more checkouts. The **merge check** works either way. See [Workspaces that change the same files](../../guides/worktrees/#workspaces-that-change-the-same-files). |

| Row | What it sets |
| --- | --- |
| **default agent** | The agent that takes an issue when you don't pick one: a specific agent, or `auto`, which uses the agent running in your current tab and otherwise asks. |
| **send the prompt** | Off: the prompt is typed on one line and you press `Enter`. On: it is pasted as written and sent for you. |
| **trust prompts** | Off (the default): when an agent cornercase starts asks "do you trust this folder?", you answer, and the prompt waits. On: cornercase answers yes for you, which lets the repository's agent configuration run. |
| **resume conversations** | On (the default): after a server restart, `kill-server` or a reboot, each pane that ran Claude Code, Codex, Gemini CLI, Grok Build, Cursor CLI, Vibe CLI or GitHub Copilot CLI comes back in the same conversation. Off: it comes back as a plain shell. See [Agents resume their conversations](../../guides/sessions/#agents-resume-their-conversations). |
| **keep awake** | Off (the default): the computer sleeps when idle, as it always does. On: while an agent is working, the computer does not go to sleep on its own. The note says whether it is being kept awake now, or why it can't be on this machine. See [Keep the computer awake](../agents/#keep-the-computer-awake). |
| **How each agent starts** | One row per agent: the default agent, the agents with start modes (`claude`, `codex`, `gemini`, `opencode`, `grok`, `cursor` and `copilot` out of the box) and any you set up. Click one to choose its mode and extra arguments. |
| **+ another agent…** | Adds one of the other [known agents](../agents/) to the list so you can set it up. |

Your [agent accounts](../../guides/accounts/). One section per agent that takes accounts (Claude Code, Codex, Gemini CLI): first the agent's own login (*System*, or the name you gave it, with its usual folder), then a row per account (whether it is logged in and as whom, its folder, and the settings that stopped being shared), each followed by **rename…**, which gives it a name for the window, and last **`+ add account`**, which makes one and opens a tab to log in. `●` marks each agent's default account, the one new workspaces start with; `Enter` on a row makes it the default, `Backspace` on an account asks before removing it. | Row | What it sets |
| --- | --- |
| **Shortcut API token**, **Linear API key** | Paste a token and press `Enter`; cornercase checks it, then saves it to `secrets.json`. Hover a saved one and click `×`, or press `Delete`, to remove it. When the token comes from an environment variable, the row says so and can't be changed here. |
| **Jira site**, **Jira email** | Your Jira Cloud site, such as `acme.atlassian.net` (a bare name like `acme` gets `.atlassian.net`), and the email of your Atlassian account. The Jira tab of the issue browser asks for both when they are missing. |
| **Jira API token** | Like the tokens above; the site and the email must be set first, since the token is checked against that site. |
| **Jira filter** | A JQL condition the Jira tab always applies, such as `project = SHOP`. Empty lists every issue of the site you can see. |
| **Plane workspace**, **Plane URL** | Your Plane workspace, the part of the address after the server's name (`acme` in `app.plane.so/acme`), and the address of a self-hosted server, such as `https://plane.acme.dev`. Empty means Plane Cloud. The Plane tab of the issue browser asks for the workspace when it is missing. |
| **Plane API key** | Like the tokens above; the workspace must be set first, since the key is checked against it. |
| **Plane filter** | Query parameters the Plane tab always adds to its list, such as `priority=high` or `project_id=…&label_id=…`. Empty adds nothing; finished work items still need **closed**. |
| **Asana workspace** | Your Asana workspace, by name or ID; the row shows its name once the account is known, with the saved ID in the note. Empty means the only workspace your token belongs to; with several, the Asana tab of the issue browser asks which one. |
| **Asana projects** | The projects whose tasks the Asana tab lists, as IDs or links separated by spaces or commas (saved as IDs). Empty lists the tasks assigned to you. |
| **Asana access token** | Like the tokens above; it needs no workspace first. |
| **GitLab URL** | The address of a self-hosted GitLab server, such as `https://gitlab.acme.dev`. Empty means gitlab.com. The GitLab tab of the issue browser asks for it before the token. |
| **GitLab access token** | Like the tokens above; it is checked against the server set in **GitLab URL**. |
| **Sources shown** | Which tabs the [issue browser](../../guides/issues-and-agents/) shows. Click to show or hide one (at least one stays); hover a row and use its `↑` `↓` buttons, or press `Shift+↑` `Shift+↓`, to change the order. |

| **prefix key** | The key that opens the menu of [keyboard shortcuts](../keyboard-and-mouse/#keyboard-shortcuts). Select the row, then press the combination you want; `Backspace` turns it off, `Esc` keeps the current one. Off by default. |

### Plugins

The [plugins](../../guides/plugins/) you installed with `cornercase plugin install` or linked with `cornercase plugin link`, under **Installed**. Each row shows the plugin's name and version and whether it is on. While it is off, the note says what it asks for; once on, its description, or whether its service runs. `Enter` turns it on or off, and the change is saved in `plugins.json`, not in `config.json`. A plugin whose manifest cannot be read, or whose command leads out of its folder, says why and cannot be turned on. With no plugin linked, the tab says how to add one.

Plugins run as you, with your rights: what they ask for is shown, not enforced. Other apps read the same rows, and what each service is doing, with `cornercase plugin status` (or the `plugin-list` request; see [Scripts and agents](../../guides/scripts-and-agents/#plugins)).

### Search the settings

The field under the tabs has the keys as soon as the settings open, so you just type. It looks in every tab, in each row's label, section, tab, value and note: every word you type must be the start of a word there, so `def ag` finds **default agent** and `ose` finds nothing. Matches in a label come first, then in a section or tab, then in a value or note. Each tab shows how many results it holds, and a tab with none is dimmed.

`↑` `↓` pick a result and `Enter` or a click goes to its tab and row; it selects the row and changes nothing. A row that only shows under another (**forum mode**, **closed workspaces**, **phone**, **paired browsers**) is listed in grey with what it needs, and going to it stops at the nearest row that shows. A tab's name is a result too. Plugins are searched as rows of their tab; the flows themselves are not, so `flows` leads to the Flows tab. `Esc` clears the field, then closes the settings. While the field is empty, the keys below work on the rows.

The [search](../../guides/search/#settings) of the whole window lists the same results after its names. Scripts search the same way with [`cornercase config search`](../../guides/scripts-and-agents/#settings).

### Keys in the settings modal

| Key | Does |
| --- | --- |
| Any letter or number | Starts a [search](#search-the-settings). |
| `Enter`, `Space` | Change the selected row. |
| `↑` `↓` | Select a row. The mouse wheel does the same. |
| `Tab`, `→` / `Shift+Tab`, `←` | Next / previous tab. |
| `Shift+↑` `Shift+↓` | Move the selected source up or down. |
| `Delete`, `Backspace` | Remove the selected saved token or chat bot, or forget the paired phone. |
| `Esc` | Close the modal, or leave a list or a text field. |

In a list, type to filter it and press `Enter` to pick. In a text field, `Enter` saves and `Esc` cancels.

Pasting several lines while no list or row is being edited opens [Share](#share-your-setup) with what you pasted, ready for ` preview `; a single line goes to the search.

## Share your setup

To set up a colleague's cornercase the way yours is, click ` share ` in the settings and then **` copy my setup `**: your settings are copied as a short text that you can send in a chat. The toast says how many settings and repositories it holds, and what it left out, counting the projects whose setup it could not share (such as one with no git remote); the line above the buttons names each of them.

The text holds five sections, each of which the other person can leave out:

| Section | What it carries |

| `agents` | [`agent`](#agent), [`agent_args`](#agent_args), [`agent_modes`](#agent_modes), [`agent_commands`](#agent_commands), [`prompt`](#prompt), [`submit`](#submit), [`accept_trust_prompts`](#accept_trust_prompts), [`resume_agents`](#resume_agents), [`trust_prompt_pattern`](#trust_prompt_pattern) |
| `issues` | [`issue_branch`](#issue_branch), [`issue_tabs`](#issue_tabs), [`gitlab_url`](#gitlab_url), [`jira_site`](#jira_site), [`jira_jql`](#jira_jql), [`plane_url`](#plane_url), [`plane_workspace`](#plane_workspace), [`plane_filter`](#plane_filter), [`asana_workspace`](#asana_workspace), [`asana_projects`](#asana_projects) |
| `worktrees` | [`worktrees_dir`](#worktrees_dir), [`fetch_minutes`](#fetch_minutes), [`pull_requests`](#pull_requests), [`merged_pull_requests`](#merged_pull_requests), [`shared_files`](#shared_files), [`gh`](#gh), [`glab`](#glab) |
| `interface` | Every switch of the UI tab, from [`sidebar`](#sidebar) to [`tour`](#tour), with the sounds and the [prefix key](#prefix_key) |
| `repositories` | Each project's [setup and teardown](../../guides/worktrees/#set-up-each-new-worktree), found by the project's git remotes (such as `github.com/acme/web-shop`) rather than its folder, so it reaches the same repository wherever your colleague cloned it |

It never holds a token, a chat bot, a paired chat or browser, your accounts and profiles, [`jira_email`](#jira_email), [`remote`](#remote), [`remote_port`](#remote_port) or [`keep_awake`](#keep_awake). It lists the trackers you are connected to, by name only, so the other side is told which to connect. A setup or a prompt is copied as you typed it, so when one looks like it holds a secret (`NPM_TOKEN=…`, `--api-key …`, `Bearer …`) the toast says where, in red: check before you send it.

To import one, paste it on Share (or anywhere on a settings tab, when it has several lines) and click **` preview `**. **Settings › Import** shows every setting that would change, as its value now → the shared one, grouped by section; a repository's setup and teardown are shown in full, a line at a time, in red:

<Screen
  name="settings-import"
  alt="Settings › Import: agents with 4 changes (default agent auto to claude, agent_args, prompt, send the prompt), issues with 2, worktrees with 1, interface with 2 (sidebar to tree, counts hidden) and repositories with 1 (the setup of ~/code/web-shop, its commands on a line of their own in red, with a note that it runs in every new worktree), each ticked, then connect linear in Settings › Issues; the buttons back and import"

Click a section to untick it, then **` import `**: the ticked sections are saved at once, and the rest stay as they are, as do the settings the text does not mention. The notes say what to check first: in red, the commands that will run on their own (a repository's setup and teardown, `agent_commands`, `gh` and `glab`, an agent mode that skips permission prompts, trust prompts answered for you) and what looks like a secret; then a path or a program this computer lacks, a tracker to connect, a repository with no open project (open it and import again), and a setting this cornercase does not know yet (update it to get that one; the rest still imports). If anything in the text cannot be used, such as a value the settings would refuse, nothing at all is imported and the page says why.

From a terminal, `cornercase config export` and `cornercase config import` do the same, and `config import --preview` prints what would change without applying it: see [Share your setup](../../guides/scripts-and-agents/#share-your-setup) in Scripts and agents.

## config.json

| | Path |
| --- | --- |
| Usually | `~/.config/cornercase/config.json` |
| With `XDG_CONFIG_HOME` set | `$XDG_CONFIG_HOME/cornercase/config.json` |

#### `worktrees_dir`

The folder for new worktrees, checked out in `<worktrees_dir>/<repository>/<branch>`. An absolute path, or one starting with `~/`.

#### `fetch_minutes`

How often, in minutes, each project's remotes are fetched to show the [commits to pull](../../guides/worktrees/#commits-to-pull) on its workspaces. A whole number; `0` turns fetching and the counts off.

#### `pull_requests`

Whether each workspace shows the pull request of its branch and the state of its checks and whether it has merge conflicts, and, on GitHub, its layer in a stack, asked of GitHub with [`gh`](#gh) or, for a GitLab merge request and its pipeline, with [`glab`](#glab). On by default. See [Pull requests and their checks](../../guides/worktrees/#pull-requests-and-their-checks).

#### `merged_pull_requests`

Whether Usage → Stats counts the pull requests and merge requests you opened that were merged, read with [`gh`](#gh) and [`glab`](#glab). On by default; off asks nothing. See [Usage and stats](../../guides/projects-workspaces-tabs/#usage-and-stats).

#### `shared_files`

Whether workspaces of a project look for the files they both change: the `⇄n` badge on their rows and the `⇄` mark in the changes panel, from a git scan every few seconds in projects with two or more checkouts. Off by default; off runs no scan, and the **merge check** still checks a workspace against its base branch. See [Workspaces that change the same files](../../guides/worktrees/#workspaces-that-change-the-same-files).

#### `issue_branch`

The branch an issue's worktree is made on, as a template such as `"feat/{key}-{slug}"` or `"{user}/{key}"`, with the placeholders `{key}`, `{number}`, `{slug}`, `{source}` and `{user}` (your git `user.name`). It must hold `{key}` or `{number}`; the result is cleaned into a name git takes. Empty keeps each tracker's own name (`issue-482-…`, `482-…` on GitLab, `sc-48-…`, `ENG-123-…`). Start in the issue browser shows it filled in and lets you change it for that issue. See [Your team's branch names](../../guides/issues-and-agents/#your-teams-branch-names).

#### `issue_tabs`

The tabs of the issue browser, in order. Accepts `all`, `github`, `gitlab`, `shortcut`, `linear`, `jira`, `plane` and `asana`, in any case; unknown names and repeats are ignored, and a list with no valid name shows all eight. A list saved before Jira existed gets `jira` added at the end once, one saved before Plane existed gets `plane`, one saved before Asana existed gets `asana`, and one saved before GitLab existed gets `gitlab` right after `github` (at the end without it).

#### `gitlab_url`

The address of your GitLab server, such as `"https://gitlab.acme.dev"`, or one under a path such as `"https://acme.dev/gitlab"`; a trailing `/` is dropped. Empty is gitlab.com. Requests carry your token, so they don't follow redirects: enter the address the server ends up at. An `http://` address works too; one that isn't loopback (`localhost`, `127.x.x.x` or `[::1]`) gets a warning, since the token then travels unencrypted. The GitLab tab lists the issues of the project whose remote is on this server. Set from the issue browser or the settings modal. The token is never stored here: it goes in `secrets.json` or comes from `GITLAB_TOKEN` (see [Files and environment](../files-and-environment/)).

#### `jira_site`

Your Jira Cloud site, as a host name such as `acme.atlassian.net`. Set from the issue browser or the settings modal, which also accept a URL or a bare name.

#### `jira_email`

The email of your Atlassian account, sent with the API token to sign in to Jira. The token itself is never stored here: it goes in `secrets.json` or comes from `JIRA_API_TOKEN` (see [Files and environment](../files-and-environment/)).

#### `jira_jql`

A [JQL](https://support.atlassian.com/jira-software-cloud/docs/what-is-advanced-search-in-jira-cloud/) condition added to every Jira list, such as `project = SHOP` or `project in (SHOP, API) AND labels = backend`. The list is always sorted by last update, so an `ORDER BY` in it is dropped.

#### `plane_url`

The address of a self-hosted Plane server, such as `"https://plane.acme.dev"`; a trailing `/` is dropped. Empty is Plane Cloud (`https://app.plane.so`). Requests carry your API key, so they don't follow redirects: enter the address the server ends up at. Set from the settings modal.

#### `plane_workspace`

Your Plane workspace, the slug in the address after the server's name: `acme` in `app.plane.so/acme`. Lower case letters, numbers and dashes. Set from the issue browser or the settings modal. The API key is never stored here: it goes in `secrets.json` or comes from `PLANE_API_KEY` (see [Files and environment](../files-and-environment/)).

#### `plane_filter`

Query parameters added to every Plane list, written as in a URL: `priority=high&label_id=…`. The parameters are those of Plane's work item list (`state_group`, `priority`, `project_id`, `label_id`, `cycle_id`, …; lists take comma-separated values). They are not checked: when Plane refuses them, its answer is shown in the list. The list asks for the work items that are not done on its own, so a `state_group__in` here narrows that rather than replacing it: while **closed** is off only its open groups count, and one that names only finished groups lists nothing.

#### `asana_workspace`

Your Asana workspace, by name (any case) or ID. Choosing one in the issue browser saves its ID, since two workspaces can share a name; a name that two share is refused, with their IDs. Empty means the only workspace your token belongs to; when it belongs to several and this names none of them, the issue browser asks which one and the Asana tab says so. Set from the issue browser or the settings modal. The access token is never stored here: it goes in `secrets.json` or comes from `ASANA_ACCESS_TOKEN` (see [Files and environment](../files-and-environment/)).

#### `asana_projects`

The projects the Asana tab lists, as project IDs or links separated by spaces or commas: `"1200000000000001 https://app.asana.com/1/12/project/34/list/56"`. The settings modal saves them as IDs joined by `, `. Empty lists the open tasks assigned to you, and then the assignee filter can only be *anyone* or *me*.

#### `agent`

The default agent: an agent kind such as `"claude"` or `"codex"`, or `"auto"` for the agent running in your current tab, and otherwise ask.

#### `agent_args`

The arguments each agent kind starts with, including those of its mode. For example `{"claude": ["--permission-mode", "plan"]}` starts `claude --permission-mode plan`.

#### `agent_modes`

Extra or replaced start modes for an agent kind: `{"kind": {"mode name": ["args"]}}`. A mode with the same name as a built-in one replaces it; an empty list hides it.

#### `agent_commands`

The program to run for an agent kind, a name on your `PATH` or a path: `{"cursor": "/opt/bin/cursor-agent"}`. A kind that cornercase doesn't know adds a new agent.

#### `prompt`

The [prompt template](../prompt/) handed to an agent started on an issue. Placeholders such as `{url}`, `{title}` and `{branch}` are filled in.

#### `submit`

`true` sends the prompt for you; `false` leaves it typed at the agent's prompt for you to send.

#### `accept_trust_prompts`

Whether cornercase answers yes to the agent's "do you trust this folder?" question when it starts one. Off by default: you answer, and the prompt waits until you have. Older versions called this key `auto_accept_trust_prompt` and had it on; that key is ignored now, so it is off until you turn it on again. See [Trust prompts](../agents/#trust-prompts).

#### `resume_agents`

Whether a pane that ran Claude Code, Codex, Gemini CLI, Grok Build, Cursor CLI, Vibe CLI or GitHub Copilot CLI comes back in the same conversation when a new server restores your session: cornercase types `claude --resume <id>`, `codex resume <id>`, `gemini --resume <id>`, `grok --resume <id>`, `cursor-agent --resume <id>`, `copilot --resume=<id>` or `vibe --resume <id>` into its new shell, with the agent's command and arguments and the mode it was running in. On by default. See [Agents resume their conversations](../../guides/sessions/#agents-resume-their-conversations).

#### `keep_awake`

Whether the computer stays awake while an agent is working. Off by default. See [Keep the computer awake](../agents/#keep-the-computer-awake).

#### `hidden_flows`

The names of the built-in [flows](../../guides/flows/) you deleted in Settings → Flows, compared ignoring case and surrounding spaces. They leave Settings, the start dialog and `cornercase flow list`, and `cornercase flow run` refuses them; a deleted name stays reserved, so a project's flow named like one does not run. A name that matches no built-in flow is ignored, and the list is kept across updates. Remove a name here, or use **deleted built-ins** in Settings → Flows, to bring the flow back.

#### `default_flow`

The name of the [flow](../../guides/flows/#choose-a-default-and-an-order) the start dialog opens with selected, compared ignoring case and surrounding spaces; empty for none. **`set default`** in Settings → Flows writes it, and `cornercase flow default NAME` does too. When the flow is missing, hidden or has problems, the dialog opens on Full issue, or on the first flow that can start. Deleting or hiding the flow clears it, and renaming it in the editor moves it to the new name. It is not part of the settings you [share](#share-your-setup), since it names a flow the colleague may not have.

#### `flow_order`

The names of the flows in the order you dragged them into in Settings → Flows, first to last, compared ignoring case and surrounding spaces; `cornercase flow order NAME…` writes it too. Settings, the start dialog and `cornercase flow list` follow it. Flows that are not in the list, such as a new built-in flow, an import or a project's flow, go after the others, by name. A name that matches no flow is skipped, and removed the next time the order is written; a project's flow keeps its place while another project is open. It is not part of the settings you [share](#share-your-setup).

#### `trust_prompt_pattern`

The regular expression, matched without regard to case against the last 15 non-blank lines of the agent's screen, that recognises a trust question. The default is:

```text
trust the files|trust this (folder|directory|workspace|repository)|do you trust|yes, proceed
```

#### `gh`

The GitHub CLI to run for GitHub issues and for the [pull requests](../../guides/worktrees/#pull-requests-and-their-checks) of workspaces: a name looked up in your `PATH`, or a path, which may start with `~/`.

#### `glab`

The GitLab CLI to run for the [merged merge requests](../../guides/projects-workspaces-tabs/#usage-and-stats) of Stats and for the [merge requests](../../guides/worktrees/#pull-requests-and-their-checks) of workspaces on GitLab: a name looked up in your `PATH`, or a path, which may start with `~/`.

#### `sidebar`

How projects, workspaces and tabs are laid out: `"projects_on_top"` and `"workspaces_on_top"` stack both lists in one column, the first one named on top; `"side_by_side"` gives each its own column; `"tree"` shows [one list](../../guides/projects-workspaces-tabs/#the-tree) with every project, its workspaces and their tabs. An unknown value counts as the default, `"projects_on_top"`; before 0.9.0 the default was `"side_by_side"`, and a `config.json` that already names it keeps it. It applies from 90 columns up; below that the [compact layout](../../guides/small-terminals/) shows one list at a time.

#### `tabs`

Where a workspace's tabs are listed: `"sidebar"` under their workspace, in the workspaces list or the tree; `"top"` in a bar above the pane, with only the active workspace's tabs and, on a second line, the model and context of the one on screen. An unknown value counts as the default, `"sidebar"`. It applies from 90 columns up; the [compact layout](../../guides/small-terminals/) always lists the tabs in its menu. See [Tabs above the pane](../../guides/projects-workspaces-tabs/#tabs-above-the-pane).

#### `icon_bar`

Whether the buttons at the bottom of the sidebar become a column of icons on the left edge, from 90 columns up. The icons come from [Nerd Fonts](https://www.nerdfonts.com/): Ghostty, kitty and WezTerm include them, other terminals need a Nerd Font set as their font. See [The icon bar](../../guides/projects-workspaces-tabs/#the-icon-bar).

#### `icons`

Which windows draw Nerd Font icons: an icon per file type in the files tree, the changes panel and the files search results, and the glyphs of the compact layout's top bar and the panels' search and full-screen buttons. `"auto"` decides for each window, so a Ghostty window and a phone attached at once each get their own choice: it draws them in Ghostty, kitty (0.36 and later, or an unknown version) and WezTerm, also inside tmux (the terminal outside tmux decides), in the browser window, and wherever [`icon_bar`](#icon_bar) is on. `"on"` draws them in every window, so other terminals need a Nerd Font set as their font. `"off"` draws plain symbols everywhere. An unknown value counts as the default, `"auto"`. Zellij and screen cannot name the terminal behind them, so `auto` leaves them plain; use `"on"`. With `CORNERCASE_IMAGES` set, cornercase does not ask tmux about the terminal outside it, so use `"on"` there too.

The browser window ships a subset of Symbols Nerd Font: Nerd Fonts (MIT), Seti UI (MIT), Codicons (CC BY 4.0, © Microsoft) and Material Design Icons (Apache 2.0). Their licences are served at `/symbols-LICENSE.txt` on the browser window's address.

#### `agents_section`

Whether the sidebar ends with a list of every Claude Code, Codex, Gemini CLI, opencode, Grok Build, Cursor CLI, Vibe CLI and GitHub Copilot CLI running in any project, with what each is doing, its model and context; a click on one jumps to it. In every layout; below 90 columns it is a third menu. See [The agents section](../../guides/projects-workspaces-tabs/#the-agents-section).

#### `working_icon`

What the tab of a working agent shows, also in the tab bar and the agents section: `"moon"`, a still `◐`, or `"spinner"`, `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` turning about ten times a second. An unknown value counts as the default, `"moon"`. See [What your agents are doing](../../guides/projects-workspaces-tabs/#what-your-agents-are-doing).

#### `counts`

Whether a project shows how many workspaces it has after its name, such as `(3)`, and a collapsed group how many projects it holds.

#### `todo_dot`

Whether the **`TODO`** button shows a grey `●` while at least one item is left to do (`☐ ●` in the compact layout's top bar). It never shows a number, and goes away once every item is done or the list is empty. See [TODO list](../../guides/todo/#open-and-close-it).

#### `dim_inactive_panes`

Whether panes you aren't typing in are dimmed, in tabs split into several panes.

#### `prefix_key`

The key that opens the menu of [keyboard shortcuts](../keyboard-and-mouse/#keyboard-shortcuts), such as `"ctrl+]"`, `"alt+k"` or `"f12"`: modifiers (`ctrl`, `alt`, `shift`) joined by `+`, then a character, `space` or a function key. `Ctrl` or `Alt` is needed except for function keys, and `ctrl+c`, `ctrl+d` and `ctrl+z` are refused. Empty, the default, or anything that can't be a prefix leaves keyboard shortcuts off.

#### `model`

Whether a Claude Code, Codex, Gemini CLI, opencode, Grok Build, Cursor CLI, Vibe CLI or GitHub Copilot CLI tab shows its model on a second line under its name, such as `Opus 5.5`. When the file has no `model`, it takes the value of [`context`](#context), so a line turned off in 0.6 stays off.

#### `context`

Whether that line shows how full the agent's context is, such as `23%`, after the model. With `model`, `context` and [`memory`](#memory) all `false`, every tab takes one row. cornercase 0.6 called it `context_line`, and it hid the model too; that key is still read.

#### `memory`

Whether every tab shows how much memory its processes use on its second line, such as `Opus 5.5 · 23% · 1.2 GB`, or `1.2 GB` alone in a shell tab or with `model` and `context` off. While it is `true`, the tabs of the project on screen are measured every 2 seconds; in the [tree](../../guides/projects-workspaces-tabs/#the-tree), those of every open workspace. See [How much memory a tab uses](../../guides/projects-workspaces-tabs/#how-much-memory-a-tab-uses).

#### `account_mark`

Whether an agent's tab, the tab bar and the agents section name the [account](../../guides/accounts/) it uses, such as `Opus 5.5 · work · 12%`. Nothing shows while you have no account, whatever this says.

#### `account_switcher`

Whether each pane gives its last row to its [accounts](../../guides/accounts/#change-a-panes-account): the button of the agent it runs, such as ` claude: work ▾ `, or in a shell one per agent with accounts, to change that pane's account. Each terminal is one row shorter while it shows. Nothing shows while you have no account. Off, the right-click menu of a pane and the ` ⋯ ` menu of a tab still have **account ›**.

#### `account_picker`

Whether the dialogs that start an issue or a flow, and the schedule form, offer an account list for the agents that have accounts. Off, they use the default accounts. Nothing shows while you have no account.

#### `desktop_notifications`

How cornercase asks your terminal for a desktop notification when an agent in another tab needs you or finishes: `"auto"` picks it from each terminal, `"osc777"`, `"osc9"`, `"osc99"` or `"bell"` forces one, and `"off"` sends none. An unknown value counts as `"auto"`. The toast inside cornercase shows either way; see [Notifications](../../guides/projects-workspaces-tabs/#notifications).

#### `sound`

Whether cornercase also plays a sound when an agent in another tab needs you or finishes: at the same moments as the toast, once the state has held for a second, never for the tab you are looking at. It plays on the computer the window is on, whatever your terminal does with notifications, so it is heard while Ghostty is focused and inside tmux, screen or Zellij; with [`cornercase remote`](../../guides/remote/) it plays on your laptop. A window opened in a plain SSH session (`ssh -t host cornercase`) plays none, since it would play on the other computer. It does not depend on [`desktop_notifications`](#desktop_notifications), which can be `"off"`. On macOS it uses `afplay`; on Linux the first of `pw-play`, `paplay` and `aplay` found. On by default. See [A sound](../../guides/projects-workspaces-tabs/#a-sound).

#### `sound_waiting`

The file played when an agent waits for you or fails. `""` (the default) plays the built-in one. The path must be absolute or start with `~/`, your home folder on the window's computer, where it is read; Settings refuses any other. A file that is missing or cannot be read plays the built-in one. `afplay` plays most formats; on Linux use WAV with `aplay`, or WAV, OGG or FLAC with `pw-play` and `paplay`.

#### `sound_done`

The file played when an agent finishes, the same way as [`sound_waiting`](#sound_waiting). `""` plays the built-in one, which sounds different from the other, so you can tell them apart without looking.

#### `sound_subagents`

Whether the sound also plays for agents started by another agent (with `cornercase start`, `new-tab` or `split` run in its pane) or by a [flow](../../guides/flows/), the ones the [agents section](../../guides/projects-workspaces-tabs/#the-agents-section) hangs under another. `false` by default: only the agents you started make a sound, and the others still get their toast and notification. An agent whose parent closed counts as one you started.

#### `check_updates`

Whether cornercase asks GitHub for the latest release, when the server starts and then every hour, to offer an [update](../../installation/#update). Only a request for the latest release is sent, and, once a newer one is out, a download of its changelog for the update dialog; nothing about you. Builds made with `cargo run` never check. An explicit check, `cornercase update --check` or a program's [`update-check`](../../guides/scripts-and-agents/#updates-from-a-program), asks GitHub whatever this setting says.

#### `star_prompt`

Whether cornercase may ask for a star on GitHub. After about 14 days on which a window was open and an agent ran (not calendar days since you installed it), a small card appears at the bottom right of the window: **star on GitHub** copies the repository's link to your clipboard and never asks again, **later** asks again in about 90 days, and **don't show again** never asks again. If you don't answer, it counts as **later**. It never appears while an agent is working or waiting for you, while a dialog, the search or a panel's field has the keys, or in the compact layout (below 90 columns), and it never takes the keys from the pane. Nothing is sent anywhere and cornercase doesn't check whether you starred; what it remembers (the days counted, when it last asked and your answer) is in `star.json` next to `session.json`. Set it to `false` to turn it off for good.

#### `tour`

Whether the guided tour shows by itself on a new install: the first time cornercase runs, with no `session.json`, `stats.json` or `star.json` yet. It shows once; an install from before the tour gets a toast saying it is in **`Help`** instead. Whatever this says, **`Help`**, the keys menu's `h`, **settings → UI → start the tour** and `cornercase tour` open it. Your progress is in `tour.json` next to `session.json`.

[Agents](../agents/) explains `agent`, `agent_args`, `agent_modes`, `agent_commands` and the trust prompt in depth.

#### `remote`

Whether this cornercase can be opened in a browser over Tailscale, from a phone that scans the code **`More ▴` › remote… › open in your phone's browser** shows. Off by default. See [From your phone](../../guides/phone/).

#### `remote_port`

The port cornercase listens on for browsers, on your computer only (`127.0.0.1`); `tailscale serve` passes Tailscale's port 8443 to it. Change it when something else uses 47681.

#### `discord_forum`

[Forum mode](../../guides/discord/#forum-mode): each workspace gets a post in a forum channel of your Discord server, with a status tag, and what you write in it goes to that workspace's agent. Off by default. Turned on in the settings modal, it opens the dialog that sets the forum up; turned on here or with `cornercase config`, nothing opens, and the **forum mode** row says `enter sets it up` until Discord is read; the setup then goes on in the background (see the [guide](../../guides/discord/#forum-mode)). The settings modal shows it, and `cornercase config` sets it, only while a Discord phone is paired. It is not part of the settings you [share](#share-your-setup), since it belongs to your own bot and server.

#### `discord_forum_close`

What happens to a workspace's post when you close the workspace, in forum mode: `"archive"` tags it `done`, then archives and locks it; `"delete"` deletes it. An unknown value counts as the default, `"archive"`. Closing a workspace's agents only archives its post, whatever this says. `cornercase config` sets it while forum mode is on, as the row shows. It is not part of the settings you [share](#share-your-setup).

#### `projects`

Per-project settings, keyed by the project's folder (`~/` is expanded): `setup` runs in the first tab of each new [worktree](../../guides/worktrees/#set-up-each-new-worktree) before its agent starts, `teardown` runs before a worktree is removed, and `builds` lists the folder names that [free builds](../../guides/worktrees/#free-build-folders) deletes in the project's worktrees when git ignores them. Without `builds` the list is `node_modules`, `target`, `.next`, `.turbo`, `dist`, `build`, `.venv` and `__pycache__`; `[]` means no folder of the project is freed. Edit them in the project's `⋯` menu, **project settings**; an entry with nothing set is removed.

```json
"projects": { "~/code/web-shop": { "setup": "npm ci\ncp ../.env .env", "teardown": "docker compose down", "builds": ["node_modules", ".next"] } }
```

#### `profiles`

Your [profiles](../../guides/accounts/): for each, the account each agent uses. Left out of the file while you have none. Manage them with `cornercase profile`.

```json
"profiles": { "Work": { "claude": "work", "codex": "work" }, "Home": { "claude": "personal" } }
```

#### `profile`

The active profile, whose accounts are the default, the ones new workspaces and agents start with. Empty, the default, means no profile: each agent uses the account in [`active_accounts`](#active_accounts), else its usual login. A name that is not in `profiles` counts as empty. `cornercase profile use` changes it, and an edit to the file applies at once. Choosing a default in Settings › Accounts empties it.

#### `account_names`

The names the window shows for your [accounts](../../guides/accounts/), per agent; `""` is the agent's own login, which is otherwise called *System*, and an account without one shows its folder's name. The folders never move. Left out of the file while you have none. **rename…** in Settings › Accounts and `cornercase account rename` change it.

```json
"account_names": { "claude": { "": "work", "personal": "Personal" } }
```

#### `active_accounts`

Each agent's default account while no [profile](#profile) is active: what a new workspace, a new project and an agent started from outside a pane start with (a new tab takes the accounts of the workspace's active pane); an agent left out uses its usual login. Left out of the file while it is empty. `Enter` in Settings › Accounts and `cornercase account use` change it; `cornercase profile use --system` empties it.

```json
"active_accounts": { "claude": "personal" }
```

### A customised example

```json title="config.json"
{
  "worktrees_dir": "~/work/trees",
  "issue_tabs": ["github", "linear"],
  "agent": "codex",
  "agent_args": {
    "codex": ["--sandbox", "workspace-write"],
    "mine": ["--fast"]
  },
  "agent_modes": {
    "claude": { "auto": [] }
  },
  "agent_commands": {
    "mine": "/opt/bin/my-agent"
  },
  "prompt": "Work on {url} ({title}). You are on branch {branch}; start with a failing test.",
  "submit": true,
  "dim_inactive_panes": false
}
```

This keeps worktrees in `~/work/trees`, shows only the GitHub and Linear tabs, starts Codex in its *workspace write* sandbox by default, hides Claude Code's *auto* mode, adds a custom agent called `mine`, sends a fuller prompt for you, and keeps every pane equally bright.

<Aside type="caution" title="Editing the file by hand">
The server looks at `config.json` once a second and applies what you saved, with no restart: a changed `remote` starts or stops browser access, `keep_awake` takes effect, the layout changes, and an open settings modal shows the new values. Editors that replace the file, or save it a moment late, are fine.

If you and cornercase change the file at once, nothing is lost: whatever cornercase changes (a click in the modal, `cornercase config`) is applied to the file as it is on disk at that moment and rewrites only the keys it touches, so the rest of your edit stays. A key changed in both places keeps cornercase's change, which came last.

If the file isn't valid JSON, or a single value has the wrong type (a number where a switch goes, say), the whole edit is rejected: cornercase says why in a message and in `cornercase config`, keeps the settings it was using, and does not write over the file until you fix it or remove it. A file that goes missing while the server runs also leaves the settings as they are; the next change writes it again. Only a server that starts with a broken file runs on the defaults.
</Aside>
