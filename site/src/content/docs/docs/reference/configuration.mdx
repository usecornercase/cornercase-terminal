cornercase is configured from the **settings** modal, opened with the `settings` button at the bottom of the projects column. Every change is saved at once to `config.json`, so there is nothing to apply or restart. You can also edit the file by hand; this page lists every key.

## The settings modal

The modal has four tabs. Click a row, or select it and press `Enter`, to change it; the line at the bottom explains what the selected row does and confirms every change.

### Worktrees

<Screen
  name="settings-worktrees"
  crop={[2, 1, 106, 7]}
  alt="The Worktrees tab: worktrees folder ~/.cornercase/worktrees, new worktrees go in folder/repo/branch; fetch branches every 5 min, commits to pull show as ↓n"
/>

| Row | What it sets |
| --- | --- |
| **worktrees folder** | Where new [worktrees](../../guides/worktrees/) are checked out: `<folder>/<repository>/<branch>`. Must be an absolute path or start with `~/`. |
| **fetch branches every** | How often, in minutes, the remotes are fetched to show the [commits to pull](../../guides/worktrees/#commits-to-pull) as `↓n` on each workspace. `0` turns it off. |

### Agents

<Screen
  name="settings-agents"
  crop={[2, 1, 106, 28]}
  alt="The Agents tab: default agent claude, send the prompt unticked, trust prompts accepted, and how each agent starts: claude in plan mode, codex and gemini in their default mode, plus another agent"
/>

| Row | What it sets |
| --- | --- |
| **default agent** | The agent that takes an issue when you don't pick one: a specific agent, or `auto`, which uses the agent running in your current tab and otherwise asks. |
| **send the prompt** | Off: the prompt is typed on one line and you press `Enter`. On: it is pasted as written and sent for you. |
| **trust prompts** | On: cornercase answers "do you trust this folder?" questions when it starts an agent. |
| **How each agent starts** | One row per agent: the default agent, the agents with start modes (`claude`, `codex` and `gemini` out of the box) and any you set up. Click one to choose its mode and extra arguments. |
| **+ another agent…** | Adds one of the other [known agents](../agents/) to the list so you can set it up. |

Choosing how an agent starts opens a list of its modes, each with the arguments it adds, plus **extra arguments…** for anything else you want on its command line:

<Screen
  name="settings-claude-modes"

Modes whose name says *dangerous* are shown in red. Extra arguments are split like a shell would: use quotes for arguments with spaces.

### Issues

<Screen
  name="settings-issues"
  crop={[2, 1, 106, 19]}
  alt="The Issues tab: Shortcut API token and Linear API key not connected; the Jira section with its site, email, API token and filter not set; and the sources shown: All, GitHub, Shortcut, Linear and Jira, with move arrows on the hovered row"
/>

| Row | What it sets |
| --- | --- |
| **Shortcut API token**, **Linear API key** | Paste a token and press `Enter`; cornercase checks it, then saves it to `secrets.json`. Hover a saved one and click `×`, or press `Delete`, to remove it. When the token comes from an environment variable, the row says so and can't be changed here. |
| **Jira site**, **Jira email** | Your Jira Cloud site, such as `acme.atlassian.net` (a bare name like `acme` gets `.atlassian.net`), and the email of your Atlassian account. The Jira tab of the issue browser asks for both when they are missing. |
| **Jira API token** | Like the tokens above; the site and the email must be set first, since the token is checked against that site. |
| **Jira filter** | A JQL condition the Jira tab always applies, such as `project = SHOP`. Empty lists every issue of the site you can see. |
| **Sources shown** | Which tabs the [issue browser](../../guides/issues-and-agents/) shows. Click to show or hide one (at least one stays); hover a row and use its `↑` `↓` buttons, or press `Shift+↑` `Shift+↓`, to change the order. |

### TUI

<Screen
  name="settings-tui"
  crop={[2, 1, 106, 11]}
  alt="The TUI tab: sidebar projects_on_top, how projects, workspaces and tabs are laid out; inactive panes dimmed, in a split tab; model shown, under a Claude Code or Codex tab, such as Opus 5.5; context shown, how full its context is, such as 23%; memory hidden, the RAM its processes use, such as 1.2 GB; desktop notifications auto, when an agent in another tab needs you or finishes; check for updates every hour, asks GitHub for the latest release"
/>

| Row | What it sets |
| --- | --- |
| **sidebar** | How projects, workspaces and tabs are laid out: *projects_on_top* (the default) and *workspaces_on_top* stack both lists in one column, *side_by_side* gives each its own column, and *tree* shows one list with every project, its workspaces and their tabs. See [Arrange the columns](../../guides/projects-workspaces-tabs/#arrange-the-columns). |
| **inactive panes** | Dim the panes you aren't typing in, in a split tab. |
| **model** | Show the model of a Claude Code or Codex tab on a second line under its name, such as `Opus 5.5`. |
| **context** | Show how full its context is on that line, such as `23%`. With the model off too, and the memory off, every tab takes one row. See [How full the context is](../../guides/projects-workspaces-tabs/#how-full-the-context-is). |
| **memory** | Show how much memory a Claude Code or Codex tab uses at the end of that line, such as `1.2 GB`. Off by default. See [How much memory an agent uses](../../guides/projects-workspaces-tabs/#how-much-memory-an-agent-uses). |
| **desktop notifications** | How your terminal tells you that an agent in another tab needs you or finished: *auto* picks what your terminal understands, *osc777*, *osc9*, *osc99* or *bell* force one, *off* sends none. The toast in cornercase shows either way; see [Notifications](../../guides/projects-workspaces-tabs/#notifications). |
| **check for updates** | *Every hour*: ask GitHub for the latest release when the server starts and then hourly, and offer to [update](../../installation/#update) when there is a newer one. *Never*: don't ask. |

### Keys in the settings modal

| Key | Does |
| --- | --- |
| `Enter`, `Space` | Change the selected row. |
| `↑` `↓` | Select a row. The mouse wheel does the same. |
| `Tab`, `→` / `Shift+Tab`, `←` | Next / previous tab. |
| `Shift+↑` `Shift+↓` | Move the selected source up or down. |
| `Delete`, `Backspace` | Remove the selected saved token. |
| `Esc` | Close the modal, or leave a list or a text field. |

In a list, type to filter it and press `Enter` to pick. In a text field, `Enter` saves and `Esc` cancels.

## config.json

| | Path |
| --- | --- |
| Usually | `~/.config/cornercase/config.json` |
| With `XDG_CONFIG_HOME` set | `$XDG_CONFIG_HOME/cornercase/config.json` |
| With `CORNERCASE_SOCKET` set | `config.json` next to the socket |

Every key is optional: a missing key takes its default. Here is a complete file, as the settings modal writes it after choosing Claude Code in plan mode as the default agent:

```json title="config.json"
{
  "worktrees_dir": "~/.cornercase/worktrees",
  "fetch_minutes": 5,
  "issue_tabs": ["all", "github", "shortcut", "linear", "jira"],
  "jira_site": "",
  "jira_email": "",
  "jira_jql": "",
  "agent": "claude",
  "agent_args": {
    "claude": ["--permission-mode", "plan"]
  },
  "agent_modes": {},
  "agent_commands": {},
  "prompt": "{url}",
  "submit": false,
  "auto_accept_trust_prompt": true,
  "trust_prompt_pattern": "trust the files|trust this (folder|directory|workspace|repository)|do you trust|yes, proceed",
  "gh": "gh",
  "sidebar": "projects_on_top",
  "dim_inactive_panes": true,
  "model": true,
  "context": true,
  "memory": false,
  "desktop_notifications": "auto",
  "check_updates": true
}
```

### Keys

| Key | Type | Default |
| --- | --- | --- |
| [`worktrees_dir`](#worktrees_dir) | string | `"~/.cornercase/worktrees"` |
| [`fetch_minutes`](#fetch_minutes) | number | `5` |
| [`issue_tabs`](#issue_tabs) | array of strings | `["all", "github", "shortcut", "linear", "jira"]` |
| [`jira_site`](#jira_site) | string | `""` |
| [`jira_email`](#jira_email) | string | `""` |
| [`jira_jql`](#jira_jql) | string | `""` |
| [`agent`](#agent) | string | `"auto"` |
| [`agent_args`](#agent_args) | object | `{}` |
| [`agent_modes`](#agent_modes) | object | `{}` |
| [`agent_commands`](#agent_commands) | object | `{}` |
| [`prompt`](#prompt) | string | `"{url}"` |
| [`submit`](#submit) | boolean | `false` |
| [`auto_accept_trust_prompt`](#auto_accept_trust_prompt) | boolean | `true` |
| [`trust_prompt_pattern`](#trust_prompt_pattern) | string | see below |
| [`gh`](#gh) | string | `"gh"` |
| [`sidebar`](#sidebar) | string | `"projects_on_top"` |
| [`dim_inactive_panes`](#dim_inactive_panes) | boolean | `true` |
| [`model`](#model) | boolean | `true` |
| [`context`](#context) | boolean | `true` |
| [`memory`](#memory) | boolean | `false` |
| [`desktop_notifications`](#desktop_notifications) | string | `"auto"` |
| [`check_updates`](#check_updates) | boolean | `true` |

#### `worktrees_dir`

The folder for new worktrees, checked out in `<worktrees_dir>/<repository>/<branch>`. An absolute path, or one starting with `~/`.

#### `fetch_minutes`

How often, in minutes, each project's remotes are fetched to show the [commits to pull](../../guides/worktrees/#commits-to-pull) on its workspaces. A whole number; `0` turns fetching and the counts off.

#### `issue_tabs`

The tabs of the issue browser, in order. Accepts `all`, `github`, `shortcut`, `linear` and `jira`, in any case; unknown names and repeats are ignored, and a list with no valid name shows all five. A list saved before Jira existed gets `jira` added at the end once.

#### `jira_site`

Your Jira Cloud site, as a host name such as `acme.atlassian.net`. Set from the issue browser or the settings modal, which also accept a URL or a bare name.

#### `jira_email`

The email of your Atlassian account, sent with the API token to sign in to Jira. The token itself is never stored here: it goes in `secrets.json` or comes from `JIRA_API_TOKEN` (see [Files and environment](../files-and-environment/)).

#### `jira_jql`

A [JQL](https://support.atlassian.com/jira-software-cloud/docs/what-is-advanced-search-in-jira-cloud/) condition added to every Jira list, such as `project = SHOP` or `project in (SHOP, API) AND labels = backend`. The list is always sorted by last update, so an `ORDER BY` in it is dropped.

#### `agent`

The default agent: an agent kind such as `"claude"` or `"codex"`, or `"auto"` for the agent running in your current tab, and otherwise ask.

#### `agent_args`

The arguments each agent kind starts with, including those of its mode. For example `{"claude": ["--permission-mode", "plan"]}` starts `claude --permission-mode plan`.

#### `agent_modes`

Extra or replaced start modes for an agent kind: `{"kind": {"mode name": ["args"]}}`. A mode with the same name as a built-in one replaces it; an empty list hides it.

#### `agent_commands`

The program to run for an agent kind, a name on your `PATH` or a path: `{"cursor": "/opt/bin/cursor-agent"}`. A kind that cornercase doesn't know adds a new agent.

#### `prompt`

The [prompt template](../prompt/) handed to an agent started on an issue. Placeholders such as `{url}`, `{title}` and `{branch}` are filled in.

#### `submit`

`true` sends the prompt for you; `false` leaves it typed at the agent's prompt for you to send.

#### `auto_accept_trust_prompt`

Whether cornercase answers the agent's "do you trust this folder?" question when it starts one.

#### `trust_prompt_pattern`

The regular expression, matched without regard to case against the agent's screen, that recognises a trust question. The default is:

```text
trust the files|trust this (folder|directory|workspace|repository)|do you trust|yes, proceed
```

#### `gh`

The GitHub CLI to run for GitHub issues: a name looked up in your `PATH`, or a path, which may start with `~/`.

#### `sidebar`

How projects, workspaces and tabs are laid out: `"projects_on_top"` and `"workspaces_on_top"` stack both lists in one column, the first one named on top; `"side_by_side"` gives each its own column; `"tree"` shows [one list](../../guides/projects-workspaces-tabs/#the-tree) with every project, its workspaces and their tabs. An unknown value counts as the default, `"projects_on_top"`; before 0.9.0 the default was `"side_by_side"`, and a `config.json` that already names it keeps it. It applies from 90 columns up; below that the [compact layout](../../guides/small-terminals/) shows one list at a time.

#### `dim_inactive_panes`

Whether panes you aren't typing in are dimmed, in tabs split into several panes.

#### `model`

Whether a Claude Code or Codex tab shows its model on a second line under its name, such as `Opus 5.5`. When the file has no `model`, it takes the value of [`context`](#context), so a line turned off in 0.6 stays off.

#### `context`

Whether that line shows how full the agent's context is, such as `23%`, after the model. With `model`, `context` and [`memory`](#memory) all `false`, every tab takes one row. cornercase 0.6 called it `context_line`, and it hid the model too; that key is still read.

#### `memory`

Whether a Claude Code or Codex tab shows how much memory its processes use at the end of its second line, such as `Opus 5.5 · 23% · 1.2 GB`, or `1.2 GB` alone with `model` and `context` off. While it is `true`, the agents of the project on screen are measured every 2 seconds; in the [tree](../../guides/projects-workspaces-tabs/#the-tree), those of every open workspace. See [How much memory an agent uses](../../guides/projects-workspaces-tabs/#how-much-memory-an-agent-uses).

#### `desktop_notifications`

How cornercase asks your terminal for a desktop notification when an agent in another tab needs you or finishes: `"auto"` picks it from each terminal, `"osc777"`, `"osc9"`, `"osc99"` or `"bell"` forces one, and `"off"` sends none. An unknown value counts as `"auto"`. The toast inside cornercase shows either way; see [Notifications](../../guides/projects-workspaces-tabs/#notifications).

#### `check_updates`

Whether cornercase asks GitHub for the latest release, when the server starts and then every hour, to offer an [update](../../installation/#update). Only a request for the latest release is sent, and, once a newer one is out, a download of its changelog for the update dialog; nothing about you. Builds made with `cargo run` never check.

[Agents](../agents/) explains `agent`, `agent_args`, `agent_modes`, `agent_commands` and the trust prompt in depth.

### A customised example

```json title="config.json"
{
  "worktrees_dir": "~/work/trees",
  "issue_tabs": ["github", "linear"],
  "agent": "codex",
  "agent_args": {
    "codex": ["--sandbox", "workspace-write"],
    "mine": ["--fast"]
  },
  "agent_modes": {
    "claude": { "auto": [] }
  },
  "agent_commands": {
    "mine": "/opt/bin/my-agent"
  },
  "prompt": "Work on {url} ({title}). You are on branch {branch}; start with a failing test.",
  "submit": true,
  "dim_inactive_panes": false
}
```

This keeps worktrees in `~/work/trees`, shows only the GitHub and Linear tabs, starts Codex in its *workspace write* sandbox by default, hides Claude Code's *auto* mode, adds a custom agent called `mine`, sends a fuller prompt for you, and keeps every pane equally bright.

<Aside type="caution" title="Editing the file by hand">
The server reads `config.json` once, when it starts, and the settings modal writes its own copy back whenever you change something there. Edit the file while no server is running, or run `cornercase kill-server` after editing so the next `cornercase` reads it. If the file isn't valid JSON, cornercase falls back to the defaults.
</Aside>
