# Keyboard shortcuts

Code: `shortcuts.rs`, `app/shortcuts.rs`, `ui/keys.rs`

- **Opt-in, behind one prefix key** (#31): the mouse stays the default and nothing changes for whoever does not turn it on. It is for people whose hands stay on the keyboard, and for clients the mouse does not reach (some mobile SSH apps, a terminal with mouse reporting off).
- **The prefix** is `prefix_key` in `config.json`, set in Settings → UI → **prefix key** by pressing it (`Settings::capturing`: the next key is taken, `Backspace` turns it off, `Esc` keeps the old one). No default is shipped: `Ctrl+b` is tmux's (and `e2e::input::ctrl_b_reaches_the_shell`), `Ctrl+Space` switches the input source on macOS, `Ctrl+]` needs AltGr on Spanish and German layouts. It must be `Ctrl` or `Alt` with a character, or a function key with any modifiers; `Ctrl+c`, `Ctrl+d` and `Ctrl+z` are refused, since every one of them would open the menu instead of reaching the program. Known clashes (`Prefix::clash`: `Ctrl+b`, `Ctrl+a`, `Ctrl+Space`, …) are named in the row and the notice, not refused. `Prefix::normal` makes a key match however a terminal sends it: the legacy bytes for `Ctrl+4`…`Ctrl+7` are `Ctrl+\` `Ctrl+]` `Ctrl+^` `Ctrl+_`, an upper-case letter is the letter with `Shift`, and `Shift` on a symbol is dropped (it made the symbol). The string form (`ctrl+]`, `alt+k`, `f12`) is what the file and the row show.
- **Where it works**: while no overlay but a right-click menu is open, also while a panel's field has the keys (the files search or find field, the changes filter, a TODO field: none of them takes `Ctrl` with a character; a field takes `Alt+b` and `Alt+f` for word moves (Option+arrows as `Esc b` `Esc f`), but the prefix is checked first, so it wins when it is one of them; `Ctrl+←` `Ctrl+→` and the `Shift` selection keys are not characters and cannot be a prefix). Dialogs keep it: they already take arrows, `Enter` and `Esc`, and the settings must get the key to capture it.
- **The menu** (`Overlay::Keys(Option<Group>)`) works like Neovim's which-key: the prefix opens it, the next key runs an action or opens a group (`f` find, `g` git, `w` workspace), whose menu replaces it. A key is either an action or a group (`shortcuts::Step`), never both, so nothing waits for a timeout. `Esc` or a key the menu does not list closes it and is dropped, since it was meant for the menu; the prefix again closes it and types the prefix in the pane, for programs that use that key; a paste closes it and goes to the pane. A click on an entry runs it, a click elsewhere closes it; entries naming several keys (`1-9`, the arrows) are not clickable. It is drawn at the bottom of the pane, in columns filled top to bottom, over the whole screen when the pane cannot hold it, and dims nothing (like the row menus, it belongs to what is behind it). Like every overlay it is shared by every client. It shows at once: which-key's delay (draw only after ~300 ms without a key) needs a timer wake-up and was left for later.
- **What the keys do** (`shortcuts::items`, `App::shortcut`): tabs (`n` `p`, `1`-`9`), workspaces (`]` `[`) and projects (`}` `{`) wrap around; workspaces skip one being removed, projects follow the sidebar's order (every group open) and skip one closing. Arrows focus the pane on that side among the shown ones (`project::split::beside`: the nearest that shares part of that edge, then the one sharing most). `a` jumps to the next agent pane, in the agents section's order after the focused one, whose status needs you (waiting or done), or toasts `no agent needs you`. `x` asks first: `Overlay::ClosePane` in a split tab, `CloseTab` for its last pane (a key is easier to press by mistake than `×`); `w x` asks like the compact `×`, and a worktree gets the removal dialog. A panel opened from the keyboard takes the keys where it has a field, or the mouse would be needed right after: `f s` opens the search in sessions (see Search) and `f f` and `f w` open the files panel with its search focused in that mode (closing an open file, `files::Panel::search`), `g d` focuses the changes filter, `t` opens a new TODO field; `f e` only opens or closes the files panel, `g b` opens the changes and their branch picker; `g p` opens the workspace's pull request (see Pull requests) or toasts why there is none; `o` turns away on or off on every chat app at once (see Telegram). `w s` opens the start dialog for the project on screen, `w f` the Flow panel of the workspace on screen or toasts `this workspace runs no flow` (see Flows); the Workspace group reads `n s r f a o x`: `w a` closes the agents of the workspace on screen (asking as the menu does, or toasting `no agent to close in this workspace`) and `w o` reopens them (or toasts `this workspace has no closed agents`), see Saved session. `g` outside git and a split without room toast why. Restart, kill-server and closing a project were left out (destructive and rare), and so was remapping the actions: the menu is on screen, so there is nothing to memorise.
