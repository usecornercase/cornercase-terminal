# Agents

Code: `agents.rs`, `agents/known.rs`, `agents/{claude,codex,gemini,opencode,grok,cursor}/`, `agents/launch.rs`, `app/launches.rs`

- **One identity per supported agent** (#198, PR 2): `agents/known.rs`, re-exported as `agents::Known`, replaces the string constants, `stats::Kind` and `usage::Agent`. Its exhaustive dispatch arms call a rule or read a constant from the agent's folder: names, titles, modes, argument normalization, resume arguments, wrapper detection, input-box and survey checks, prompt queuing, local commands, missing-record explanations and optional usage specs. The folders also state their unsupported capabilities explicitly. Resume and input-box callbacks keep optional return types even when one agent always supports them, so every dispatch arm remains a direct folder call; local `unnecessary_wraps` expectations record that interface choice. `Known::of` searches `Known::ALL` rather than repeating the names in another match. Config and serialized reports still use strings, so custom launch agents and older server reports remain supported. `OTHERS` keeps the launch-only catalogue after `Known::ALL`, preserving the lists' order; the four known binaries still default to their names. Codex's npm wrapper suffix is defined once in its folder and shared by process detection and rollout discovery.
- **Adding an agent**: create `agents/<agent>/` with its rules, readers, counting, last-message reader, fake and optional plan probe; declare its module in `agents.rs` and remove it from `OTHERS` if present; add its `Known` variant last in `Known::ALL` and fill every dispatch arm. Add its `Reader` and `Record` variants and fill their exhaustive arms in `agents/context.rs`. State the constants every folder has: `COMMAND` (the binary typed when `agent_commands` names none: `Known::command`, since the launch-only catalogue is the only other source and an agent that leaves it must keep its command, as `cursor-agent` shows), `MODEL_FLAG` and `MODEL_ALIAS` (how a model is given and every spelling `with_model` replaces), `UNATTENDED` (the mode that never asks, which every flow role runs in), `MODELS` (model ids the Flows dialog offers, none rather than invented ones), `CATALOGUE` (a reader that lists more on a job, or `None`), `EFFORT` (its effort switch and levels, or `None`), `ADD_DIR` (the flag that gives it one more folder, or `None`, see Flows) `RECORD_BY_FOLDER` (its records are found by its folder rather than its pid, so another of its kind there hides them) and `STATUS_BY_FOLDER` (its status too, so a flow gives it one role; a test pins both sets, see Flows). Extend `app::tests::agent_status::Watched` and the applicable parameter lists, add fixtures under `tests/fixtures/<agent>/<version>/`, and update the texts the title tests guard (`SEND_HELP`, `READ_HELP`, `WAIT_HELP`, `cli::SKILL` and the control refusals). Update `RESUME_NOTE` if it resumes, these design decisions and the docs. `Known` is public because the e2e stats test names a variant; its methods and constants remain crate-visible. No agent-specific arm is needed in `app`, `term`, `stats`, `usage`, `settings` or `restart`; extensible stats persistence belongs to PR 4.

- Config: `agent` (`auto` = the one running in the tab, else ask), `agent_args`, `agent_modes`, `agent_commands`, `prompt` (placeholders like `{url}`, `{key}`, `{title}`), `submit`, `accept_trust_prompts`, `trust_prompt_pattern`.
- `agents::launch::Launch` types the command once the shell is quiet, waits until the agent is in the foreground, has drawn something and its screen is quiet, waits for the trust prompt to be answered (or answers it), then pastes the prompt. Readiness is a heuristic. "Drawn something" means the screen is no longer the shell's screen plus the command's echo (or part of it), compared without whitespace (`Launch::echo`): the quiet second used to count from the echo, so an agent that took over a second to draw (a loaded machine, a cold start) got the prompt before its trust question and read it as the answer (#34). A screen that is not the prompt plus the command (zsh's `RPROMPT` on the same line, a line scrolled off the top) counts as drawn, as before. `AGENT_LATEST` (30 s) still types the prompt into an agent that never draws.
- **The trust prompt is left to the user by default** (`accept_trust_prompts`, off). It is the agent's guard against running a repository's own agent config (project settings, hooks, MCP servers) before anyone looked at it, so answering it for the user would run a hostile repository's config as soon as an issue starts. It used to be on by default, as `auto_accept_trust_prompt`; the key was renamed so every saved `true` (settings save the whole file) falls back to off once, and turning it on again is one click. A per-project "trust this project for agents" was left out: off costs one Enter per issue started, and agents remember the folders already trusted. Whatever the setting, the prompt is detected: a launch that may not answer it parks (`Launch::waits_for_you`) until the agent prints again, which the answer does; its clock restarts from that output, so `AGENT_LATEST` never types into the question, and once the screen is quiet without the question it pastes the prompt. A parked launch is not polled: `App::tick` asks for the 100 ms launch wake-up only for launches that are not parked, since the user may take hours to answer and every wake-up draws every client. Before, a launch with answering off typed the prompt into the question, and Enter picked Claude's highlighted "No, exit". If the user says no, the shell comes back and the launch is abandoned as usual. A flow's launches answer it whatever the setting (`launch::Spec::trusted`, see Flows). `trust_prompt_pattern` is matched only against the last 15 non-blank lines of the screen (`agents::asks_trust`), where an agent draws the question, so older output above cannot match; the regex is compiled once per pattern (`agents::TrustPrompt`).
