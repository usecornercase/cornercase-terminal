# Layout › Resize pointer

Part of [Layout](../layout.md).

- **Resize pointer** (`host/pointer.rs`, #168): a border that drags lit up cyan under the mouse, but the pointer stayed as it was, so nothing said it could be dragged until one tried. The outer terminal is asked for a pointer shape with OSC 22 (`ESC ] 22 ; <name> ESC \`, kitty's spec, with CSS names): `ew-resize` on the column borders (projects, workspaces, the right panel's) and on dividers between panes side by side, `ns-resize` on the stack line, the agents section's line and dividers between panes one above the other. `App::pointer` works the shape out from the state on demand, like the cyan: a border or divider being dragged (`Drag::Border`, `Drag::Divider` in `App::drag`) keeps its shape wherever the pointer is; otherwise the border or divider under `hover`, unless an overlay is open, another drag or a selection is going on, the pointer is in the side panel, or the compact menu covers the pane; anything else is the default. The server asks for it in `Server::flush`, every turn, per window, and sends it only when it differs from what that window was last told (`Client::shape`, unknown at attach, so a window starts with the default: a remote window that lost its link mid-drag gets its pointer back on reconnecting). Pushing it as a host write from the code paths that change hover or drags was rejected: every way the state changes (a release, `Esc`, an overlay opening, a panic resetting the interaction) would have to remember it, and host writes go to every window alike. `Esc` now ends a border or divider drag where it is (it used to reach the pane), as it cancels row drags, and before the `Esc` that closes a side panel, so dragging the panel's own border and pressing `Esc` keeps the panel open; going back to the width before the drag was left out, since the panes already followed it live. The prefix key ends border, divider, row and pane drags too as it opens the keys menu: these drags would otherwise go on under the menu, keeping the resize arrow over it (the mouse goes on reaching a drag while an overlay is open). Text and file-line selections continue.
  - **Which terminals** (checked in the sources and docs, October 2026; not live): Ghostty (from 1.0; CSS names, an unknown or empty name is ignored with a warning, and its default shape with mouse reporting on is `text`), kitty (from 0.31; CSS names, an empty name resets to its configured default) and foot (from 1.12; CSS and X cursor names, an empty or unknown name resets). Those three get it; everything else gets nothing (`host::pointer::detect` answers `None`). iTerm2 (3.5) and xterm (367) honour OSC 22 but with X11 cursor names of their own, which would mean a name per terminal and checking how each resets; WezTerm, Konsole, Alacritty and VTE do not implement it. Unknown OSCs are dropped by the terminals we know, but a pointer left as a resize arrow over the panes is worse than none, so the rule is the one `host::notify::detect` follows: only where it is known to work. The reset therefore depends on the terminal (`Terminal::reset`): Ghostty gets `text`, since an empty name leaves its pointer stuck and `default` would show an arrow where it showed an I-beam; kitty and foot get the empty name, which brings back their own configured default.
  - **Deciding**: from the XTVERSION reply only (`ghostty …`, `kitty(…)`, `foot(…)`, each at least the version above), the same reply the images and notifications read; all three answer it, also over ssh. The environment is not used: `TERM_PROGRAM=ghostty` is inherited by terminals started from Ghostty. The client decides (it also needs the answer to reset on exit) and sends it in `Hello` (`pointer`, `protocol::VERSION` 3).
  - **Multiplexers**: never inside tmux, screen or Zellij (`detect::in_multiplexer`, or XTVERSION naming tmux). tmux drops OSC 22, so it would need passthrough, which is off by default and, under `on`, dropped while the pane is not visible, so a reset could be lost and the arrow stay; the outer terminal's pointer also belongs to every tmux pane, so an arrow left by cornercase would show over the user's other panes. A pointer is a hint, not worth that risk.
  - **Leaving**: the client writes the reset with the kitty image deletes on every way out (quit, detach, restart, kill-server, a signal, a remote window giving up, a panic on the main thread), since the server may be gone and cannot send it. A window killed outright (`SIGKILL`) can leave the arrow, as it leaves its images; the next window resets it when it attaches.
