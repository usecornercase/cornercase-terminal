# Layout › Tabs above the pane, the icon bar and icons

Part of [Layout](../layout.md).

- **Tabs above the pane** (`tabs` in `config.json`, Settings → UI: `sidebar`, the default, or `top`; `config::Tabs`; #119): with `top`, the active workspace's tabs leave the sidebar for a bar of `tab_bar::HEIGHT` (2) rows on top of the pane (`Areas::tab_bar`, cut off `Areas::pane` by `Areas::with_tab_bar`, which `App::layout` and `ui::draw` both apply, so the PTYs are sized without it). Tabs in the sidebar only mattered for the workspace on screen, yet took a row each (two with the details line) plus `+ Tab`, pushing projects and workspaces off the list. `sidebar` is the default so nobody's layout changes on update. The first row is the tabs (`tab_bar::Strip`: status icon, name cut at 24, a split tab's muted `+n` as on its row (`TabEntry::others`), then a ` ⋯ ` and a ` × ` whose cells are always reserved and that show on hover, lit like the rows' (`Strip::menu`, `Strip::close`; `ui::row_menu_button` is not reused, since it leaves out rows under `MIN_MENU_ROW_WIDTH` and a tab is usually narrower), ` + ` after them), the active one on the surface and bold; the second is the details of the focused pane (`App::tab_bar_view`, not the tab's: in a split it follows the pane you are in; a shell pane shows only its memory, and nothing with the memory off), in the muted grey, with the same `model`/`context`/`memory` switches. A path there for shells was rejected: the prompt already shows the folder. Both rows are always there, even with one tab or a shell, so switching tabs never resizes the PTYs. Too many tabs reserve ` ‹ ` / ` › ` at the ends (` + ` goes to the right edge); they and the wheel scroll by one tab, `follow` brings the active tab into view when the focus changes (and starts over at the first tab when the workspace changes), and a drag held on an arrow scrolls like `↑ n more`. A press grabs a tab as a `Target::Tab` row (`RowDrag`), so click, drag and `Esc` work as in the lists; the landing (`Strip::drop`) is a cyan `│` between tabs (`ui::Drag::Bar`), and the drop goes through `move_before` like `Spot::Tab`. The sidebar learns the tabs are elsewhere from `Areas::tab_bar` (`App::drawn`, as with the tree): `ui::TabLines::new(lines, listed)` leaves out tab rows and `+ Tab` from the workspaces list, and `TreeShape::tab_bar` ends the tree at workspaces, which lose their fold arrow (nothing to fold) and show `agents::activity::attention` like folded ones. Compact mode ignores the setting: its bar already names the tab and its menu keeps listing them, and two bars would cost rows a phone does not have. No project, no bar (the rows stay, so the pane does not jump when the first project opens).
- **Icon bar** (`icon_bar` in `config.json`, Settings → UI, off by default; `ui/activity.rs`, `ui/icons.rs`): from 90 columns up, the buttons under the lists (` Issues `, ` Changes `, ` Files `, ` TODO `, ` Settings `, ` Usage `, ` Quit `, and ` Remote ` and the update when they show) become a column of `activity::WIDTH` (4) cells on the left edge, like an editor's activity bar, and the footers go, so the lists reach the bottom. The footer cost every layout four to six rows and spelled out seven buttons in words. `full_layout` carves the bar off before the columns (`Areas::activity`); `projects_column` and `workspaces_column` give the footer rows no height, `one_column` and `stack_room` no footer, so every other rect keeps its meaning and an empty `Areas::settings` (or `issues`, `todo_button`…) simply hits nothing. Border drags subtract the bar's width (`App::drag_border`). Off by default, like `tabs`, so nobody's layout changes on update, and because the icons need a font the program cannot check for.
  - **Icons** are Nerd Fonts' codicons, VS Code's own: Ghostty, kitty and WezTerm include them, other terminals need a Nerd Font set as their font, else they show as boxes. Whether a font has a glyph cannot be asked (a missing one still takes a cell), so the switch is the user's. The bar's own buttons always draw them, since they have no plain form. The compact bar's `≡ ± ▤ ☐ ⌕`, the search bar's `⌕`, the changes filter's `⌕` and the files panel's `▤ ▢ ❐` take the same set (`icons::Glyphs`, `PLAIN` or `NERD`) only where the `icons` setting says so (see Icons below): `icon_bar` only shows the bar, and under `auto` turning it on counts as saying the font has the glyphs, so nobody who saw them loses them. Each icon sits in a 3-cell slot (`▌`, icon, blank): a blank after it lets Ghostty and kitty draw it over two cells, the largest a character gets. Ghostty sizes icons to its icon height (1.2 times the height of capital letters, its `adjust-icon-height`), which no program can change: a terminal has no font size per cell. Larger icons would need pictures through the kitty graphics protocol, which tmux, a cornercase pane and most terminals would not show; left out.
  - **Places** (`activity::items`, which drawing and `activity::hit` share): Issues, Changes, Files, TODO and Flow (codicon `type-hierarchy`, while the active workspace has a run) from the top, one row apart; Quit, Settings, Usage, Help (codicon `question`, always), then Remote and the update from the bottom (see Tour). After Flow, one slot per plugin button (`activity::Item::Plugin`, #435, see Plugins › A button of its own) with its `[button]` icon, or its title's first letter, and its title as tooltip; the footer's ` ⋯ ` for buttons that do not fit has no slot of its own, since a short bar drops them instead. A button that does not apply (Changes outside git, Issues and Files without a project) is left out and the others close up. A short bar drops the plugin slots first (the user's own extras, while the built-in places are what the bar is for), then the top buttons, then the bottom ones from the update down, so Quit and Settings are the last to go; a bar under five rows has room for Quit alone.
  - **Indicators** keep the footer's: the number of changed files (a filled circle with the number, Material Design's `numeric-N-circle`, `9+` from ten), TODO's grey dot (`todo_dot`) and Remote's green one, at the icon's bottom-right corner, the cell under its second half. The bar's border follows them, so Ghostty draws them in one cell, smaller than the icon; under the icon, followed by a blank, they were as large as the icons. The exact count is in the tooltip.
  - **Names on hover**: the button under the pointer is named beside the bar, on the surface (`activity::draw_tooltip`, drawn after everything but overlays), not while an overlay is open or a drag goes on (`sidebar_hovered`), since icons alone are guessed. An open panel or dialog gets the selection's cyan `▌` and a cyan icon; hover fills the slot like a row, Quit turns red, the update is always cyan.
  - **Colours** (#275): an icon at rest is `View::soft` (see Soft text), a step brighter than the muted grey so the bar does not read as disabled; hovered, and in its tooltip, it is the terminal's own foreground (`Color::Reset`), bold, which is readable on its background by definition. They were `Color::Gray` and `Color::White` (ANSI 7 and 15), which nothing checked: on light themes they were light greys or white on white, and Solarized Light's ANSI 7 is its own highlight background (1.1:1). Icons are thin strokes, so they need more than letters: soft text asks 3:1, WCAG's minimum for non-text components, where grey text asks 2:1. The cyan of an open panel, Quit's red, the update's cyan and the counts' cyan and green stay the theme's own accents: light themes draw them for their background (measured: GitHub Light's cyan 4.9:1, One Light's 4.0:1, Tokyo Night Day's 4.3:1, Catppuccin Latte's teal 3.3:1, Solarized Light's cyan and green 2.9:1), and an open panel also has its `▌` and bold, so its state never rests on colour alone. Swapping them for fixed palette colours was left out: cyan is the selection colour of the whole UI, and changing it in the bar alone would make the bar disagree with the rows.
  - The simulation lists the row and says it needs a real cornercase: the icon bar itself is not simulated.
- **Icons** (`icons` in `config.json`, Settings → UI: `auto`, the default, `on` or `off`; `config::Icons`; #450): the files tree, the changes panel's file rows and the files search results show an icon per file type, and the panels' own glyphs (`icons::Glyphs`) follow the same choice. Editors and file managers show them, and the terminals most people use already draw them, but whether a window can is a fact of that window, not of the user: a Ghostty window and a phone can be attached at once.
  - **Per window.** `auto` is decided for each window (`App::icons_in(sight)`, from `Config::icons`, `Support::nerd_font` and `icon_bar`) and `ui::View::with_icons` hands it to the files and changes views, so two windows of one server each get their own drawing. The fact travels inside `graphics::Support`, so the client's probe, `Hello`, the tmux re-check that sends `ClientMessage::Graphics` and the server's per-client state carry it with no new path (`protocol::VERSION` went to 8, since both messages changed shape). `on` and `off` force every window; `off` also makes the panels' glyphs plain with the icon bar on. Hit testing builds its views with `icons: false` and never depends on where a name starts, which is why a row's icon cannot move a click.
  - **Which terminals** (`graphics::detect::nerd_font`, reusing the brand logic of the images): Ghostty and WezTerm, which bundle the symbols and fall back to them; kitty from 0.36.0, which added them (its changelog, 2024-08-17), a known older one is off and an unknown version on. Behind tmux the outer terminal decides (`Outer::Local`'s name or `Outer::Probed`'s), and no passthrough is needed, since the glyphs are plain text. Zellij, screen, a nested tmux and every other terminal are off: the outer one cannot be named, or it needs a Nerd Font the program cannot check for. A WezTerm older than 20230712 bundles Nerd Fonts 2 and shows boxes for some icons; `off` is the fix, a version gate was left out. The images' override `CORNERCASE_IMAGES` does not touch the icons, but with it set the client skips its tmux check (`client/probe.rs`), so behind tmux the outer terminal is unknown and `auto` is off: `on` is the way out. The browser window says it has them (`web/bridge.rs`), since the page ships the subset (see Browser access). Both facts are in `server.log` (`icons=`) so a wrong decision can be fixed.
  - **The table**, not a crate (`ui/icons/kinds.rs`): an exact file name first (`Cargo.toml`, `package-lock.json`, `.gitignore`…), then the last extension, both ignoring ASCII case, then a generic file icon, and two folder icons (special folders such as `src` or `node_modules` were left out to keep the table at about 60 entries). Every glyph is from Nerd Fonts' "Seti and original" set, which was drawn for file trees (MIT), and exists in Nerd Fonts 3.1.1, the oldest a current WezTerm stable bundles (checked by name against `glyphnames.json` of 3.0.1, 3.1.1, 3.2.1 and 3.5.1; `custom-astro` was left out because 3.1.1 lacks it). `tests/fixtures/icons/table.txt` is the shared truth of this table, the simulation's and the font's; `symbols.txt` lists every Nerd code point `ui::icons` can draw and the font script subsets from it.
  - **Colours**: an entry is one of ANSI 1-6 (red to cyan), never RGB and never 0, 7, 8 or 15, so it follows the host's theme; neutral types (the generic file, locks, config, fonts) use the view's soft grey (`ui::soft`), which is the readable grey of the icon bar (#275) and not ANSI 7, which light themes draw as a highlight. A test enforces both rules. The name keeps its git status colour and the changes panel's style: the icon says the type, the name says the state; a muted changes row (viewed, large, binary) mutes its icon too.
  - **Layout**: each icon takes its cell plus a blank, as in the icon bar, since Ghostty and kitty draw a Nerd icon over two cells when the next one is blank. In the tree the arrow stays where it was and the icon sits at the name's old column for folders and files alike, so icons line up per level and the name moves two cells right; a search result's icon goes before its path (names and text results by file) and its matched lines move right by the same two, so the numbers stay under the path. In the changes panel the icon sits between the status letter and the path and comes from the file's current name (a rename's new one). The rows have two cells less for the name, which is cut as before.
  - **Left out**: icons in the sidebar, workspaces, tabs, pull request states, menus, dialogs, the issues modal and the viewer's header (each can be its own change); a per-window override variable (`on` and `off` cover it); larger two-cell glyphs in the browser and the site (the Mono variant of the font keeps each icon in its cell); the window's decision on the socket (it is drawing, exempt from the contract; the setting itself is in `config`).
