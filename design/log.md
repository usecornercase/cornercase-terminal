# Log

Code: `log.rs`, `paths.rs`, `time.rs`, `app/trace.rs`

- **Who reads it**: whoever fixes a bug, most often a coding agent told to look at the log. So it is a timeline of what the server did, detailed enough to turn into steps or a failing test; the user only sees it through `cornercase logs`. Before (#114) the server wrote only panics and about 15 failures, and bugs were found by reproducing them by hand.
- **Where**: `server.log` next to `session.json` (`$XDG_STATE_HOME/cornercase`, else `~/.local/state/cornercase`; a debug build's `cornercase-dev/<key>`), or next to the socket when `CORNERCASE_SOCKET` is set (`paths::log`). It used to sit next to the socket in `$XDG_RUNTIME_DIR`, which is cleared at logout and reboot, so the log of the crash that matters was gone (the socket followed it there in #355). The client opens it as the server's stdout and stderr (early failures still land there), and `log::start` reopens it and `dup2`s it onto stderr, so panics, a stray `eprintln!` and Ghostty's own output share the file and the rotation.
- **Format**: one line per event, `2026-10-07T21:09:51.482Z INFO  worktree: add done ms=812 branch=fix-login`: UTC time (local time needs a time zone database; `time::Stamp` does the calendar by hand), level, target (`server`, `client`, `app`, `ui`, `control`, `launch`, `activity`, `worktree`, `changes`, `git`, `issues`, `files`, `images`, `usage`, `stats`, `awake`, `update`, `pr`, `star`, `search`, `accounts`, `log`, `panic`), a message, then `key=value` fields; a value with spaces, quotes or control characters is quoted with Rust's escapes, so a line never breaks. Panic reports are the one exception: their first line has the time and `ERROR panic:`, and the message and backtrace follow on lines of their own, since a backtrace escaped onto one line cannot be read. Text rather than JSON lines: it reads well in a pane with `tail -f`, and `grep` and agents take it as is.
- **Own writer, not `tracing`**: `log::info!` and friends (`warning!`, since `warn` clashes with the built-in attribute) check the level, format the line on the caller and `try_send` it to a writer thread through a bounded queue (4096 lines); a full queue drops the line and the writer says how many it dropped, so a stuck disk never blocks the server loop. Rotation has to move stderr with the file, which `tracing-appender` cannot do, and spans were not needed: `log::Job` gives a background job its start, end, duration and error. A job logs at its level; a failed `Info` one becomes `WARN`, and a `Debug` one that took a second or more (`log::SLOW`) becomes `INFO`, so slow git runs stand out without debug.
- **Size**: past `MAX_BYTES` (8 MiB) the writer renames the file to `server.log.1` (replacing the older one) and starts a new one, `dup2`ing it onto stderr again, so the log stays under 16 MiB however long the server runs. When the rename fails the file is emptied instead, with a line saying why, so the cap holds anyway. The panic hook's throttling stays.
- **Levels**: `info` by default, cheap enough to be always on; `CORNERCASE_LOG=debug` (read by the server when it starts) adds every event the loop handled (keys as their name only, `a character` for text; mice without moves; pastes as their length), connections, frequent jobs (the diff every second, `↓n`, the files panel) and frames slower than 16 ms. A config key was left out: it is a switch for a bug hunt, set when starting the server.
- **What is logged**: `config.json` changed outside (the keys) or why it cannot be read, the server's start (version, build, pid, OS, socket, session path, level) and stop, clients attaching (size, the terminal's XTVERSION name, now sent in `Hello`, the notification channel, whether its background is known), rejected and gone, the shared size changing, kill-server, restart and signals; the restore (how many projects, complete or not, each tab that failed and why) and saves (debug); every command for scripts with its safe fields (at debug for `input`, `scroll`, `selection`, `resize` and `ratio`, which come as fast as someone types) (`Command::fields`) and its answer or refusal with the time it took and how a wait ended; each step of a `Launch` (stage before and after, bytes written, abandoned); every agent status change per pane, and each notification and the channel it went out on; background jobs; shell exits with their status; menu actions, moved rows and panes, renames, settings changed (keys only), issues started; the errors toasts show; panics and the step they hit, and any loop step slower than 100 ms.
- **Changes are found, not announced** (`app/trace.rs`): after every step that can change the app (a refresh, input, a request, a job's answer; not PTY output, drawing or saving) `App::trace` compares the hierarchy (groups, projects, workspaces, tabs, panes, with their parent and phase) and the focus, overlay, side panel, compact menu and toast with what it saw last, and logs what opened, closed, moved or changed phase, closed ones from the inside out. One place covers the UI, the commands and background answers alike, so a new code path cannot forget to log a tab it opens. It is a merge of two sorted lists of ids, with labels read only for new items (a workspace's label reads `.git/HEAD`), so a step costs about 6 µs with 80 items (release build). The same diff feeds `cornercase events` (see Commands for scripts and agents): it yields `Change`s, of which the log takes what opened, closed, moved or changed phase, and the events what opened, closed, changed agent state or ended a program. It runs while the log is at `info` (the default) or someone follows events.
- **Never logged**: typed characters (debug names only the other keys, such as `Enter` or `Esc`, and says `a character` for the rest), pasted text (only its length), PTY output, screen contents, prompts, issue texts and titles (the branch of an issue's worktree carries a slug of its title, and is logged like any branch: it is the workspace's name, its folder and its label everywhere else), search queries, TODO texts, agents' messages, the text a program writes to the clipboard (its size only), the cells a surface streams, tokens and environment variables. Commands log what they carry as sizes or yes/no (`send` its bytes, `start` whether it has a prompt, `wait --until text` without the pattern, `read --last-message` whether it found one), and a request that cannot be parsed logs only its size, since serde's error may quote it. Paths and the names of groups, projects, workspaces, tabs and branches are fine: they say where something happened, and the log stays on the user's machine, readable only by its owner (created `0600`, and set back to it when an older log is reopened). `e2e::server::the_server_log_tells_what_happened_but_never_what_was_typed` types, pastes and sends markers at debug level and checks the log has none of them.
- `cornercase logs [-n N] [--follow] [--path]` reads the file directly (no server needed): the last lines, from `server.log.1` too when the new file is short, then follows it across a rotation (`log::Follower` reopens when the inode changes or the file shrinks). The agent skill names it, so an agent debugging cornercase knows where to look. The client appends throttled `WARN` lines with target `client` for input errors and other threads' panics. For `cornercase remote`, these go to the log on the machine running the window. Left for later: a `bug-report` bundle.
