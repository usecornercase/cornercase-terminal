# Agent status › Background subagents

Part of [Agent status](../agent-status.md).

- **Background subagents keep the agent working** (#358, `Activity::Subagents`, `agents/context.rs`, `agents/claude/transcript.rs`, `agents/copilot/events.rs`): an agent can end its own turn while subagents it started in the background still run, and goes on when they report back. The tab then showed `✓`, notified "finished", and again when the work really ended; waits, `restart --when-idle` and the chat notices ended early. `Activity::Subagents` means "the agent's own turn is over (idle, or only a background shell left) but subagents it started still run". `context::Pane::activity` promotes the reader's `Idle` and `Shell` to it while `Reader::subagents()` is above 0; a question (`Waiting`) is never promoted, so `!` wins, and `Working` stays `Working`. Subagents beat a background shell: the agent wakes up for their results, so the turn is not over even for `--until turn-over`, the opposite of the shell. It maps to `Status::Working`, and `state()` stays `working`, so no new value reaches scripts or events: waits, `--when-idle`, keeping awake, stats and chat notices read `status()`/`state()` and needed no change. `Subagents → Idle` is a finish like `Working → Idle` (unseen `✓`, one notice after the settling second), and a pending mark stays through it like through a shell. OSC 7501 still comes first (`agent_in`), so a program that reports status decides, and the count stays. A turn with subagents is one turn that ends when the last subagent does, and its whole time counts as working time. The server log gets an `activity` line `subagents` when the flag flips (`state()` does not change between working and subagents, so the `status` line says nothing).
  - **Claude Code** (read from 2.1.302's code and the files it wrote on this machine, **not checked in a live session**): its session file already says `busy` while `local_agent`, `remote_agent`, `in_process_teammate` and `local_workflow` tasks run (`status = isLoading || delegatedActive ? "busy" : "idle"`), so cornercase's own check is a backup and what gives the count. The files are the ones `Subagents` already tails for stats: `<transcript without .jsonl>/subagents/agent-<id>.jsonl` and its `agent-<id>.meta.json`. A file counts as running when all hold: it was written since the pane first saw the process (a resumed conversation's finished subagents never count); it was written within 10 minutes (`SUBAGENT_STALE`, `context::fresh`, shared with Copilot: a subagent can wait minutes on one tool, and the agent's own status covers that wait; the guard only keeps one that died from holding the tab for good); its meta does not say `finished: true` or `stoppedByUser: true` (written since 2.1.301); the newest assistant line read from it is not a final reply (`stop_reason` `end_turn` or `stop_sequence`: how versions before 2.1.301 end it, and a revived subagent writes new lines and counts again); it was written after the newest `[Request interrupted by user` user line of the parent transcript (Esc aborts foreground subagents and parks background ones, which stop writing); and its meta says `requestShape: "background"` or the parent is busy or waiting (a foreground subagent cannot outlive the tool call that started it, so one that crashed without a final reply never holds an idle parent). The count is worked out when the subagent job answers (`Reader::children`, copied out before the state moves into the next job) and again each tick with the parent's activity. Teammates and workflows (`subagents/workflows/`) are not counted: Claude's own `busy` covers them. **Known limits**: a background subagent stuck in one long tool call for over 10 minutes writes nothing, so it stops counting; the parent then shows `✓` and notifies, and notifies again when the subagent really ends (the price of a guard that a crashed one cannot hold the tab for good; Claude's own `busy` still keeps the tab working while it reports it). After `/clear`, the reader keeps the old session's subagents until its next background job returns, so the count can be wrong for a tick or two. A resumed subagent counts again from its new `user` line, before it writes a reply. **Not checked live**: what Claude's session file and the meta say for a background agent parked by Esc (the interrupt rule and the 10 minutes are the backstop), found out as a known limitation rather than checked, since running it needs a live Claude with a held-open subagent.
  - **GitHub Copilot CLI** (schema and code of 1.0.98, **not a live run**; the fixtures were built from them): `Fold` keeps a set of open sub-agents by `toolCallId`: `subagent.started` opens one (an event without a time is ignored), `subagent.completed` (also with `cancelled: true`) and `subagent.failed` close it, and `session.start`, `session.resume` and `session.shutdown` clear them (a new process has none). Not `abort`: background sub-agents may outlive it and Copilot writes `subagent.completed` for the ones it tears down. Events that name one as `parentToolCallId` (`data.parentToolCallId`, or `data.usage.parentToolCallId`) refresh its time, so a long one stays fresh; the same 10 minutes apply. The backwards seed keeps the three kinds it meets. The presence flag (`working`) very likely stays true while they run, as Claude's does, and the promotion also turns `working: false` into `Subagents`.
  - **Not covered**: Codex (an experimental multi-agent mode whose child rollouts carry `source: {"subagent": …}`; whether the root wakes on a child's answer was not checked), Gemini CLI and opencode (their subagents run inside the parent's turn, whose title or message already shows working), Grok Build (subagent sessions never captured live) and Cursor CLI (no local subagents known). None runs subagents as child processes, so there is no process-tree fallback.
  - **Shown**: the second line gets a fourth part, `2 subagents` (`1 subagent`), after the percentage and before the memory, in the muted grey and never cut (the model goes first in a narrow column). It has no setting: it explains why a tab keeps its working icon, as the icon has none; with the model, context and memory all off, a tab grows its second line only while subagents run, which shifts the rows below it by one (accepted: the count is the point, and it is temporary). Scripts get `subagents` (a count, 0 for shells and agents without a reader) in `status --json`, `status --follow` and `view` lines, as the last column of `status --panes` and as `working (2 subagents)` in the text; the `watch` fingerprint includes it. Additive, so `CONTRACT` and the stream versions stay 1. **No "parent idle" flag**: Claude writes `busy` while its background agents run, so its own turn cannot be told from theirs; `subagents` says some still run, which is what a script needs. `wait`'s timeout names them (`ended its turn, but 2 subagents it started still run`).
