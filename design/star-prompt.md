# Star prompt

Code: `star.rs`, `app/star_prompt.rs`, `ui/star.rs`, #276, #582

- **Why**: stars are how most people find and judge cornercase, and people who use it every day rarely think to give one. cornercase asks once, for one click: nothing is sent and no agent is interrupted.
- **Once, after the 5th prompt** (#582, `star::ASK_AT`): the count is the prompts Stats counts (every known agent; `Round::sample` hands the round's prompts to `App::count_star_prompts`), so it measures real use. It lives in `star.json` and is not seeded from `stats.json`, so people who used cornercase before are asked at their 5th prompt after updating, not the moment they update. Prompts cornercase sends itself (an issue, the TODO panel, the queue, flows, `cornercase send`) are in the agents' records like typed ones and count; a flow can reach 5 while the user is away, and the dialog waits for them. The card of #276 (14 counted days of use, bottom right, again 90 days after **later**, closed by itself whenever an agent worked or a toast showed) was easy to miss: it waited two weeks, sat in a corner and often went away before anyone read it.
- **A dialog, not a card**: `Overlay::Star`, like the other dialogs: centered, the rest dimmed, shared by every window (answering in one closes it in all), and drawn in the compact layout too, since dialogs fit there. #276 rejected keeping the card until answered because it would sit over a working agent's output; the dialog accepts that because it shows once in a lifetime, and in the middle so it is seen. Accepted cost: while it is open keys do not reach the pane, so someone who presses `Esc` to interrupt the agent right after the 5th prompt closes the dialog instead and presses it again, once ever.
- **It never closes by itself**: no timeout, not when an agent works, waits or finishes, not on a toast. Only **star on GitHub**, **no thanks** and `Esc` close it. A click outside does nothing (`Overlay::closes_from_outside`, the other exception being a plugin's popup, see Dialogs), so a click meant for the pane cannot dismiss it unread; `Enter` does nothing, since the user just pressed it to send the prompt. Keys go through the dialogs' fallback (`form_key`), so `Enter`, `Tab`, the arrows and typing reach nothing.
- **When it opens**: on the refresh that counts the 5th prompt (a moment after `Enter`, when the agent's record shows it), if a window was drawn in the last 2 s (`App::draw` stamps it) and nothing is in the way: another overlay (a plugin's popup included), the compact menu, a drag, or a text field holding the keys (the tour's prompt, TODO, files, the changes filter), so it never eats what is being typed. Otherwise it opens as soon as nothing is, which covers prompts sent by scripts with no window attached.
- **Only once**: `shown` is written by the first frame that draws it, and after that it never opens again, whatever the answer, across restarts. A dialog closed before any frame showed it (the setting turned off) comes back. The buttons record `starred` or `never`; `Esc` records nothing.
- **star on GitHub** copies the repository's address through OSC 52 (`App::copy`) and toasts it (`copied https://github.com/usecornercase/cornercase-terminal`) so it can be read without clipboard support: the server may be on another machine and cannot open a browser on yours. Opening the page when the window can open things, as the Ports dialog's ` open ` does, needs a URL in `ServerMessage::Browse` and a protocol bump; left for later.
- **State** is `star.json` next to `session.json` (`paths::star`, version 2, plain pretty JSON, nothing sensitive): the prompts counted, when it was shown and the answer. A version 1 file (#276) keeps only a **star** or **don't show again** answer, which means it never shows; anything else in it starts the count from zero. A missing, corrupt or newer file starts over. It is written when a prompt counts (at most 5 times), when the dialog is first drawn and when it is answered. `star_prompt` in `config.json` (Settings → UI, on by default) turns it off: nothing counted, no dialog, no writes, and an open dialog closes on the next refresh. Logged as `star` (`prompts`, `opened`, `shown`, `answered`, `closed`), never anything but the counts.
- **TUI only**: an overlay, so nothing on the socket (AGENTS.md); `star_prompt` is reachable through the `config` request.
- **Tests and captures stay clear of it**: app tests run with it off (`new_app`) unless they test it; e2e sessions and the site captures start with a `star.json` already shown (the capture's `tour` screen and the e2e first-run test remove it, since `tour::first_run` needs an empty one).
- **Simulation**: only the settings row; the dialog needs five prompts.
- **Checked**: `star::tests` (counting, schedule, version 1), `app::tests::star_prompt` (opening, waiting, staying open, answers, restarts, version 1 files, wide and compact snapshots), `ui::tests::star` (geometry, buttons, hover, narrow wrapping), and `app::tests::control_requests::agents` for a prompt recorded by a fake agent reaching the count.
