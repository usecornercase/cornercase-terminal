# Star prompt

Code: `star.rs`, `app/star_prompt.rs`, `ui/star.rs`, #276

- **Why**: stars are how most people find and judge cornercase, and people who use it every day rarely think to give one. A small card asks now and then, in a way that never costs the user anything: no keys taken, no agent interrupted, nothing sent.
- **A card, not an overlay**: it is drawn like the toast (bottom right, shared by every window, `View::star`) and is not an `Overlay`, since an open overlay stops every mouse event from reaching the columns and the pane. It takes only the left press on its three buttons; any other mouse event inside its rect is consumed so nothing reaches the pane beneath; keys are never touched (`app::tests::star_prompt` checks they reach the pane). Without a star glyph: `★` is ambiguous-width in CJK locales.
- **When** (`star::Saved`, constants `FIRST_AFTER_DAYS` 14 and `LATER_FOR` 90 days): a day counts once when a window was drawn in the last 2 s (`App::draw` stamps it, the server draws every attached window at least each 500 ms tick) and some pane runs an agent, so it measures real use, not calendar days since install; UTC days, and a clock set back never counts twice. People who already use cornercase start counting from this release: seeding the count from `stats.json` would make the first thing after an update a request for a star. The first ask is due at 14 counted days, later asks 90 days after the last one was shown, never after **star** or **don't show again**.
- **Never in the way**: it shows only while nothing else wants the user's attention (no overlay, compact menu, drag, toast, TODO or files field, changes filter, and no agent working, waiting or failed; a pending or done mark does not count, or anyone with old review marks would never see it), and closes by itself the moment one of those holds. An unanswered card counts as **later**, with the 90 days counted from when it was first drawn (a card that closes before any frame showed it uses none), and the release of a press that answered it is swallowed with it, so it never reaches the pane, which also gives at most one ask per window session. The compact layout (below 90 columns) skips it, judged from the last drawn client like every other shared layout decision: the server cannot tell a `cornercase remote` window from a local one (the proxy forwards a plain `Hello`), and phones are compact. Keeping the card until it is answered was rejected: it would sit over a working agent's output.
- **Star on GitHub** copies the repository's address through OSC 52 (`App::copy`) and toasts it (`copied https://github.com/usecornercase/cornercase-terminal`) so it can be read without clipboard support: cornercase never opens a browser, since the server may be on another machine and cannot open one on yours, as with the pull request's link.
- **State** is `star.json` next to `session.json` (`paths::star`, version 1, plain pretty JSON, nothing sensitive): the first counted time, the days, the last counted day, when it was shown and the answer. A missing, corrupt or other-version file starts over. It is written on the server loop when a day counts, when the card shows and when it is answered (a few times a day at most). `star_prompt` in `config.json` (Settings → UI, on by default) turns it off: no counting, no card, no writes, and an open card closes on the next refresh. Logged as `star` (`active day`, `shown`, `closed`, `answered`), never anything but the counts.
- **Simulation**: only the settings row; the card needs 14 days of use.
