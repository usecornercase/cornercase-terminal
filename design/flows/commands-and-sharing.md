# Flows › Commands and sharing

Part of [Flows](../flows.md).

- **Commands** (`cli/flow.rs`, `app/control/flow.rs`): `flow list` and `flow run`, request names of their own (`flow-list`, `flow-run`) so an older server refuses them. **The lookup order** is yours, then the built-in flows, then the project's (`Origin::rank`, names compared trimmed and ignoring case): a flow of yours with a built-in's name is how a built-in is edited, while a project's flow still never runs instead of one you know, since it comes with a cloned repository and would run its `env` and `args` unattended. Built-in flows came first at the start, which kept them read only in practice. `store::list` applies the rule once (it drops each built-in yours replaces, then sorts by name and rank), so `flow run`, `flow list` and both dialogs share it; a project's flow named like another gets the problem `yours is also named X and runs instead`, drawn in red and not startable, and `flow run`'s note says which runs. `flow run` answers once the tabs exist, with each role's tab and pane.
- **Sharing** (`flows/share.rs`, `flows/dialog/import.rs`, `control/flow.rs`, `app/control/flow.rs`): a flow is shared as its own TOML, the file `flows/*.toml` already holds, under one comment line saying how to import it (`share::HEADER`), by **export** in the Flows dialog (OSC 52 through `App::copy`, like every copy, since the server may be on another machine), `cornercase flow export NAME > file.toml`, or a file committed to `.cornercase/flows/`. Not an opaque code (base64, a link): whoever imports a flow runs its `env`, `args` and prompts unattended, so the text must be readable before it is accepted, and a file also diffs and reviews in a chat or a repository. A hosted share link was rejected like the stats card's upload: cornercase never sends anything anywhere by itself. **256 KiB at most** (`share::MAX_BYTES`), checked on export, on import and on a paste, since real flows are a few KiB and the text travels through the clipboard (OSC 52 adds a third, under tmux's 1 MiB `input-buffer-size`); the CLI reads at most one byte more and refuses. `store::parse` reports `line N:` for a bad file, now also for a flow read from disk. The server does the work, since it knows `config.json`'s place (which follows `CORNERCASE_SOCKET`), the built-ins for this config and the project's path: `flow-export` and `flow-import` are commands of their own, so an older server refuses them by name instead of ignoring the fields. Moving the requests of flows into `control/flow.rs` was its own commit, since `control.rs` was at 951 lines.
  - **Every import is checked for risks**: only a project's flow had its `env` and `args` named in red, but an imported one is someone else's just the same. `share::risks` is the sentence (`project_risks` is its project wording, and `share::env_warning` the export's: check no secret goes with it). The dialog never saves an import: the page keeps what was pasted (a multi-line field like the prompt's, `Esc` goes back) and its `import` button opens the flow in the editor, unsaved (`Editing::imported`: an empty original, so leaving asks), with the red line and a note for agents not installed here, and a name made unique (`Quick` becomes `Quick 2`, ignoring case, built-ins counted); saving is the normal save, which refuses while there are problems. A paste on the list opens the page with the text, so the usual way is copy, open Flows, paste. The CLI lists the roles on stderr, and when the flow sets `env` or `args` asks `[y/N]` (after a `check` request, so collisions and problems fail before the question); without a terminal, or reading `-`, it refuses unless `--yes`, as the restart does.
  - **Names** (`share::collision`, compared as `store::same_name`: trimmed, case-insensitive): into yours, a name of yours is refused, or overwritten with `--replace`; a built-in's is refused without `--replace` (yours would take its place and be tagged `edited`) and allowed with it; a project's is allowed, since yours runs first. Into the project (`--to project`), a name of yours or a built-in is refused even with `--replace`, since the project's flow would never run, and another project flow's is refused unless `--replace`. Every refusal suggests `--name`. `flow-import` refuses a flow with problems, listing them: the dialog shows them in the editor instead. The log has `flow imported` and `flow exported` with sizes and the place, never the text (`Command::fields` gives `text_bytes`).
