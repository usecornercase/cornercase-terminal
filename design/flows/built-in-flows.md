# Flows › Built-in flows

Part of [Flows](../flows.md).

- **Built-in flows** (Full issue, Cross review, Quick, Bug test first, Arena) ship with cornercase, so improvements reach everyone with each update, and **can be edited**: one opens like any other flow, and saving it writes your version under the same name into your folder, where it takes the built-in's place (tagged `edited`) and stops getting updates. For it, ` restore default ` asks first, deletes your file and unhides the name, so the built-in comes back (`Action::Restore`, not a plain delete: a built-in that is also deleted must not vanish). Restore is a delete under another name on purpose: there is nothing else to undo, and the built-in improves with updates where your copy does not.
  - **Built-in flows can be deleted** (#322): they live in the binary, not in a file, so deleting one **hides** it by name (`hidden_flows` in `config.json`, `Vec<String>` compared with `store::same_name`, trimmed and ignoring case): your choice, kept across updates, which a file in `flows/` would not be (it would shadow the built-in as an edit). A built-in added by a later release still shows, and a renamed one comes back. ` delete ` on a built-in asks, then hides it; on an edited one it deletes your file and hides the built-in too (` restore default ` stays beside it, and the `Delete` key asks the delete question, since a keypress should not pick the gentler one). `store::list` takes the hidden names and moves those built-ins out of `Listing::flows` into `Listing::hidden`; `Listing::builtins` keeps **every** built-in name, so a deleted one stays reserved: `unique()` never gives its name to a duplicate or an import, `share::collision` refuses it, and a project's flow named like it gets the red problem `the deleted built-in … keeps its name` and does not start (`store::conflict` takes the built-in names). If yours has a deleted built-in's name it is listed (tagged `edited`) and the built-in is in neither list. `flow run` and `flow export NAME` refuse a deleted built-in's name, even when a project's flow has it, and say where to bring it back; `flow list` omits it, and no request or contract changed. Hiding the built-in that is the default flow clears `default_flow` (#445), and restoring it keeps the default, since the name resolves to the built-in again. A run already going keeps its flow: the session holds it. The list ends with a muted, foldable entry `▸ deleted built-ins (n)` (click or `Enter` to expand; each hidden flow muted with its diagram and a ` restore ` button, no question since it is not destructive). `flow delete`, `flow hide` and `flow restore` commands were left out at first, and exist since #342 (see Through the server below), one meaning each. They were read only at first (duplicate one to change it), until the user asked to change them in place after trying flows. They are built from the installed agents (`builtin::for_config`): the default agent orchestrates and codes, and reviewers take other installed agents, so a review comes from another provider when there is one; then the agents are given out under the rule above, roles that edit first and the orchestrator last. No model is named: each agent's own default.
