# Flows › Agents never ask, and starting a run

Part of [Flows](../flows.md).

- **Agents never ask** (the user's decision): every role starts in its agent's mode that skips permission prompts (each folder's `UNATTENDED`), since a team that stops to ask defeats the point and the orchestrator must not answer another agent's prompt. A run's launches answer the trust prompt whatever `accept_trust_prompts` says (`launch::Spec::trusted`). The dialogs said `N agents run without asking for permission` in red at first; the user had it removed, since it is the premise of flows and the docs keep the caution. What stays red is what a flow could not show otherwise: a project's `env` and `args`, the not-a-repository line, the flow's problems and Claude Code's consent below. Its limits:
  - **Claude Code's one-time Bypass Permissions consent is the user's**: the launch recognises the screen (`agents::claude::screen::bypass_consent`, whitespace ignored, since a narrow pane wraps it) and parks there like an unanswered trust prompt, with a toast and a desktop notification naming the role; the orchestrator, which starts after its members, waits. Typing the prompt into it could pick "No, exit".
  - **A project's flow comes with a cloned repository** and would run its own `env` and `args` unattended: both dialogs spell them out in red for each role (`flows::dialog::project_risks`), and a project's flow never stands in for yours or a built-in one of the same name (see Commands below).
- **Starting a run** (`App::start_run`, `open_run`): refused before anything opens on the flow's problems, an agent not on the server's `PATH` (it would type a command that fails), an empty task or branch, a project that is not a repository root or is closing, or a branch that already has, or is starting, a run in that project. One worktree per run, made by the existing worktree job and shared by the command and the window; a role can ask for a worktree of its own (#313, below).
  - **The branch**: when nobody chose one (`flow run` without `--worktree`, or the start dialog's branch still the one it derived), cornercase takes the slug of the task's first eight words (`flows::branch`), or that slug with four hex digits when it is empty (a non-Latin task), reserved (`main`, `master`, origin's `HEAD`, the branch of the project's own folder) or taken (by a workspace, a local branch read from `refs/heads` and `packed-refs` without git, or a run starting on it), so two runs of one task never share one. A branch someone chose is refused only when it is the project folder's or a default branch; a workspace on it is reused when it is a linked worktree with no run.
  - **All tabs or none**: one tab per role, named after it, orchestrator first. Every shell is spawned before a tab is added, and a workspace the worktree hand-off added is removed again, so a failure leaves nothing half open. A run never opens in a project or workspace that is closing or being removed, checked again when git answers: the team's shells would keep a closing project open, or work in a folder git is deleting.
  - **The orchestrator starts last** (`Launch::after`: its launch waits while a member's is going) and its brief begins with a `wait --all … --until turn-over`. Both: starting last means every pane it addresses has its agent in front; the wait covers members still in their first turn. The instruction alone was rejected: a wait on a pane whose agent has not started fails, and a model may skip it.
  - Members are in `App::runs` as soon as the tabs exist, so the panel draws the run from the first frame. A run ends when its workspace goes or none of its panes is left.
- **Refused while a run's agents are closed** (#430): a workspace, or the branch of one, whose run's agents are closed (see Saved session) takes no new run (`workspace N has a flow's agents closed: reopen or forget them`), from `flow run` before any worktree is made and from the start dialog through `open_check`; it is accepted again after a reopen ends nothing or a forget ends the run.
