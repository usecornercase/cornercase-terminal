# Search

Code: `project/search.rs`, `project/search/said.rs`, `list.rs`, `app/search_dialog.rs`, `app/search_dialog/sessions.rs`, `app/control/search.rs`, `cli/search.rs`, #272

- **Candidates are built outside `App`** (#195): `project::search::candidates(groups, projects, config, home)` takes what it reads, so its tests need no `App`; `App::search_candidates` passes its fields. Ties among projects keep the order of `projects`, not the sidebar order the next bullet describes: they differ after **move to group** or **add project**, and changing the order is a visible change that needs its own issue.
- One global search across groups, projects, workspaces (label and branch) and tabs (label and their workspace's keys). Ranking: exact, prefix, substring; ties by kind (group, project, workspace, tab) then sidebar order. A group result expands it and activates its first project. Results are recomputed on every key and draw; the query is never kept after closing.
- **In sessions** (#272): the search has a second mode, `project::search::Mode::Sessions`, that looks in what was said instead of in names. `Overlay::Search` holds a `project::search::Finder` (the field, the mode and an `Enter` waiting for an answer, as the files search's `Query::enter`). It opens in names, from `/` or a click, and in sessions only from `f s`: the mode is not remembered, so the bar always starts as it did, and a second way to type queries (the issue offered a `>` prefix) was left out. `Tab` and the 3-cell button at the right end of the bar (`ui::mode_button`, the geometry drawing and hits share, lit cyan in sessions like the files panel's `▤`) switch it and clear the selection. An empty bar says what it searches (a muted placeholder). The glyph is `❯` (plain) or the codicon `comment-discussion` (Nerd): `“` and `»` are ambiguous width.
- **What is searched** (`project::search::said`, pure, no `app` or `ui`): per pane, its agent's transcript (`agents::context::Record::said`, newest first, the same seven records `read --last-message` reads: Claude Code's human prompts and queued prompts and its text blocks, Codex's `UserMessage` items and replies, Gemini CLI's real prompts and replies, opencode's text parts that are not synthetic or a compaction summary, Grok Build's `chat_history.jsonl` with its `<user_query>` wrapper stripped, Cursor CLI's turns from its chat store: user text and assistant steps, never thinking or tools, GitHub Copilot CLI's prompts and main-agent replies from its `events.jsonl`) and then the pane's whole history, shells included, from the bottom up (`Emulator::text`: the formatter's plain, unwrapped text of the active screen with its scrollback, so a query cut by a soft wrap still matches; the same call `last_lines` makes). Codex's role-user `response_item` is not read: it also carries the injected AGENTS.md and environment context, and repeats each prompt that its `item_completed` event already holds. Tool results, sidechains and meta prompts are left out. Matching is `text::Needle`, a literal compiled case-insensitive (like names, always, and with Unicode folding), one match per message or screen line, `MAX_PER_PANE` (20) per pane and `MAX_MATCHES` (300) in all, in sidebar order (`project::sidebar_order`, then workspaces, tabs and panes), skipping projects closing and workspaces not `open()`. `Found::capped` says a match was really left out (one more was seen), not that the count reached the cap. A screen line that the transcript's matching messages already hold (normalised: whitespace collapsed, leading `●⎿>›-*` marks dropped, lower case) is dropped, since Claude Code and Codex print their replies and prompts on screen too.
- **Off the UI thread, with the corpus on it**: `Emulator` is `!Send` and lives on the server's main thread, so the text of each pane is read there (`App::build_sources`) and only the matching runs in a job (`App::spawn_job`, `search sessions`, up to 8 scoped threads pulling sources from an atomic index as the files text search does, a cancel flag checked between messages and lines). Formatting tens of MB on every key would be the cost, so the corpus (`said::Sessions::corpus`) is built on the first non-empty query and reused for `CORPUS_FOR` (5 s), and each pane's text is cached by `Term::output_at` and its size, so an idle pane is formatted once. A newer query cancels the running one and its answer is dropped by its generation; a job that never answers is given up on after 30 s, as the files text search. The answer is kept for its query only (`Sessions::answer`), the list shows `searching…` meanwhile, and an `Enter` pressed before it comes opens the first match when it does. The query never reaches the log (`job.note` says only how many matched), and the cache is dropped as soon as no sessions search is open (`ask_sessions`, every refresh), since it can hold megabytes per pane.
- **Results and the reveal**: two lines per result (`ui::SESSIONS_PITCH`, geometry and hit testing take the pitch): the snippet (the matching line, control characters as spaces, about 160 characters shifted so the match shows, with `…` at the cut ends) with the match in cyan, then `who · prompt|reply|screen` and `project › workspace › tab` cut at the start. Choosing one goes to the pane (`jump_to_pane`) and reveals the match (`Emulator::reveal`): it formats the text again and takes the occurrence whose line is nearest the one found, since history trimmed at the top shifts lines in between (the newest when the match came from a transcript, so a reply the screen also shows is highlighted, else the pane is only focused), maps the logical line to its rows by walking `is_wrap_continuation` over `Point::Screen` rows, turns character offsets into rows and columns with `unicode-width` (a wide character that does not fit wraps early), selects through Ghostty's own selection, which already draws as the selected cells, checks the selected text is the match (else it clears and answers false) and scrolls the viewport to a third of the pane's height above it. A press in the pane starts a new selection and removes it. Limits: a full-screen program's pane is searched as shown, since the main screen's history is unreachable while the alternate screen is up; and a program that reads the mouse is put back at the bottom by `snapshot`, which loses the reveal.
- **`cornercase search TEXT…`** (`control/search.rs`, `app/control/search.rs`, `cli/search.rs`) answers with the same matches: a `search` request (an older server refuses it by name, as every new command) builds the same sources without the cache, runs the job without a cancel flag and answers when it ends (`Stage::Reading`, so a client that leaves drops it). Text is one tab-separated row per match under a header (`pane who source place line text`, `-` for a missing value, control characters as spaces, new columns only at the end, written through `print_out`); `--json` prints `{"matches": [...], "capped": bool}` with each match's tab, workspace and project ids and, for a transcript message, when it was written. No match prints the header alone and exits 0: the repository keeps exit 1 for errors, and an empty answer is not one (grep's convention was rejected for that). An empty query is an error. The query is logged by its size only.
