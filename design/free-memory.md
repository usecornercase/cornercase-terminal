# Free memory

Code: `os/memory.rs`, `host/memory.rs`, `machines/memory.rs`, `app/machine_memory.rs`, `app/control/auto.rs`, `app/machine_links/run_on.rs`, `machines/run_on.rs`, #539, #662

How much memory this computer and each machine has free, and what reads it: `--machine auto`, the `run on` row's `auto` and the queue's entries that wait for room (see [Queue › Waiting for room](queue/free.md)). Not the memory a tab uses, which is [Memory](memory.md).

- **Available, not free** (`os/memory.rs`): Linux reads `MemTotal` and `MemAvailable` from `/proc/meminfo` (on a kernel older than 3.14, without `MemAvailable`, `MemFree + Buffers + Cached`); macOS adds the free, inactive and purgeable pages of `host_statistics64` (through `libc`, with `mach_host_self` declared here since `libc` marks its own deprecated) and reads the total from `hw.memsize`; Windows reads `ullAvailPhys` and `ullTotalPhys` of `GlobalMemoryStatusEx`. Free memory alone was rejected: the file cache keeps it near zero on every busy system, so every machine would always read as full. `vm_stat` was rejected for macOS: a subprocess where one system call does. On macOS `free_count` already holds the speculative pages, and purgeable pages may also be counted as inactive, so the figure can be a little high; it is what Activity Monitor's "memory available" approaches, and the picker only compares machines. Read on the server's loop: one system call or one small file.
- **`CORNERCASE_MEMORY=total,available`** (`host/memory.rs`, amounts such as `32GB,9GB`) replaces the reading, for the e2e tests and for trying `auto` on one computer, as `CORNERCASE_PHONE_ADDRESSES` does for the phone app. App tests set `Machines::memory.read` (a `fn`), so no test that asserts an amount reads the real host's. Not in the website's docs.
- **Amounts** (`text::parse_size`): `3GB`, `512MB`, `1.5GB`, `4 gb`, `2GiB`, `8G`; the units are powers of 1024 (KB, MB, GB, TB and their `i` forms), as memory is sold and as `text::size` shows it, so `16GB` is the 16 GB a machine reports. Zero, a sign or another unit is refused. Shown with `host::memory::shown` (`text::size` without a `.0`: `32 GB`, `9.2 GB`).
- **How a machine reports it**: in the `machines` answer, as `here.memory` (`{total, available, read_at}`, left out when it cannot be read), so asking a machine for its memory is asking it `machines` (`impl Asked for MemoryInfo`, `app/machine_usage.rs`, 5 s), with the per-machine `Cache` of stats and usage, and no new request: an older server answers without `here.memory`, which reads as unknown. Each machine's last reading is `memory` (with `read_at`) on its row of `machines` and on Settings › Machines (`linked · 0.13.x · 9.2 GB free of 32 GB`), and this computer's on the first row there. Feature `memory`. Putting it in the `Watch` snapshot was rejected: it changes all the time, and every change would send a snapshot to every window that watches the machine.
- **When it is asked**: never on its own, only on demand: by `--machine auto` and the `run on` row's `auto`, every 30 s while Settings › Machines shows (`refresh_machines_page`), and every 30 s while a queue entry waits for room. A reading less than 30 s old is not asked again (`REFRESH`), and one being asked is not asked twice. Asking on every link up was tried and dropped: it added a question to every machine of every test, and a reading nobody looks at goes stale anyway.
- **Who can be picked** (`machines::memory::pick`, pure, its cases in `machines/memory/tests.rs`): this computer, and every machine in `machines_in_order` (shown and accepted) that is linked, has sent its snapshot, has the project (paired by repository identity, as the `run on` row does) and has a reading less than 60 s old (`FRESH`). Each other one is left out with why: `unreachable`, `connecting`, `has no web-shop`, `memory unknown` (an older cornercase, or a reading that failed), `memory not read lately`. The winner has the most available memory after reservations; on a tie, this computer, since nothing goes through ssh. Its answer is the winner and its room, or that nothing fits, with the best candidate and why the others were left out.
- **Reservations** (`Reservations`, in memory): a run takes minutes to grow to its full memory, so for 5 minutes after a start (`RESERVED_FOR`) the picker subtracts the memory it counted for each start it sent to a machine. Without it, three starts in a minute all went to the machine that had room for one. They are per machine name, lost on a restart, and counted by `--machine auto` and the queue; a start whose machine was chosen by hand, in a dialog or with `--machine NAME`, reserves nothing.
- **How much a start needs**: a flow's `memory` key (see Flows › A flow's memory), else `default_memory` in Settings › Machines (`config.json`, `4GB` by default; `Config::default_memory` falls back to it when the text cannot be read). The setting is not shared with a colleague (`settings::share::LEFT_OUT`): it depends on your machines.
- **`--machine auto`** (`app/control/auto.rs`): `start`, `start-with` and `flow run` take it. The request's ids are this server's: `auto` picks among machines, so the ids cannot be a machine's, and `machine_boot` with `auto` is malformed. The project is `project`, else `workspace`'s, else the caller's. Readings older than 30 s are asked first: the request waits (as `Stage::Reading`, its client parked in `MemoryState::waiting`) until no machine is being asked, at most 8 s, then picks once. This computer runs the request as if it had no `machine`; a machine gets it relayed as `--machine NAME` would, with its own project id and no `workspace` (a workspace here has no pair there, so it stands for its project, as in the dialogs). The answer adds `auto` (`auto → torre (11.3 GB free)`), which the CLI prints on stderr; `machine` names the machine as for any relay. When nothing fits the request fails with the new code `no-room` and the reason (`no machine has 6 GB free (best: mac, 4.1 GB)`), and the CLI exits 8, so a script can tell it from a failure and try later. Feature `machine-auto`; `client::use_machine_auto` checks it and asks for structured errors, since the code is what the exit status follows. A machine can no longer be called `auto` (`machines::valid_name`); one that was is a problem in Settings and has no link.
- **The `run on` row's `auto`** (`machines::run_on::Auto`): the last choice, `○ auto`. It is not a place but a one-shot choice: choosing it reads the stale readings, then chooses this computer or the machine with most room as if it had been chosen by hand, so the dialog's checks of that machine run as before, and says why after the row, with what it asked for (`auto → vps (11 GB free, needs 6 GB)`, or in red why nothing had room). Keeping `auto` chosen until ` start ` was rejected: the dialogs show a machine's accounts, tracker and flows, and those can only be checked once the machine is known. Choosing a machine by hand forgets what `auto` said. **What it counts is what the start would count**: Start flow the selected flow's memory, through the one function `flow run --machine auto` and the queue use (`App::flow_needs`, the flow found by name in this computer's listing, else the listed flow's own `memory`, else `default_memory`), so the dialog and the command line never disagree; Issues and New workspace start a plain agent or a workspace, so they count `default_memory`. A choice that came from `auto` is made again when the user selects another flow (`Start::choose_flow`, not when the listing reloads, which would move between machines in a loop), and Issues' ` start a flow ` hands its `auto` to Start flow, which picks again with the flow's memory. Counting `default_memory` in Start flow was the first version, a bug: a flow that needs 12 GB was placed on a machine with 11.
- **Left out**: swap, the CPU, and the memory a run already uses (only what was reserved); a machine is never asked to free memory; a reading is not taken more often while a run starts.
- **Checked**: the readers on macOS (this Mac, 16 GB) and through the tests on Linux and Windows in CI; `auto` with the fake machines of the app tests (answering `machines` with a fixed reading). No real second machine was used.
