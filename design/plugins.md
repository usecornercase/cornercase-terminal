# Plugins

Code: `plugins/`, `app/plugins.rs`, `app/plugin_popup.rs`, `ui/dialog/popup.rs`, `cli/plugin.rs`, `client/window.rs`

- **What a plugin is** (PR 1 of 3 is the core; PR 2 adds installing, below; the catalogue is PR 3): a folder with `cornercase-plugin.toml` that declares argv commands, modelled on herdr's plugins (`herdr-plugin.toml`). The plugin's API is the existing commands for scripts and agents: it calls `$CORNERCASE_BIN status --json`, `events --json`, `send`, `notify`… No SDK and no runtime inside cornercase (WASM, Lua, JS were rejected): every improvement to the commands is one to plugins at no cost, and a plugin can be written in any language. TOML, like herdr's, so plugins port easily; it costs the `toml` crate (parse and serde only). Entries: `[[actions]]` (one-shot, in the menus, on the plugin's own button, as a job or in a popup), `[[events]]` (one-shot per event), `[[service]]` (kept running by the server), `[[window]]` (kept running by each local window), `[button]` (the title and icon of its button, #435), and for installing `[[build]]` and `[download.<target>]` (see Installing). Left out: `[[tab]]` (`new-tab --command` covers it), link handlers, per-entry `platforms`, plugin-defined settings, declarative dialogs (a list or form schema) and areas of the TUI drawn by the plugin (sidebar sections, panel tabs).
- **What a plugin shows in the window** (#435): a button of its own and a popup terminal, as herdr does with `placement = "popup"`, rather than a schema of widgets cornercase would draw. A popup is a PTY in a bordered dialog, so a plugin draws anything a terminal program can (fzf, a curses menu, a TUI written in any language) and cornercase keeps one surface to maintain, the emulator it already has; a schema would be a second UI toolkit with its own versions, and would still not cover what a program in a terminal does. Sidebar areas and panel tabs stay out: they would hold a plugin's process for as long as they show and share the columns' room with the built-in lists. The popup's content for other UIs (`surface` and `input` on it) is a follow-up issue (#456); this change gives clients its state, opening and closing (see Through the server).
- **Tests**: fake plugins are `/bin/sh` scripts in temporary folders (`plugins::*::tests`, `app::tests::plugins`, `e2e::plugins`); supervision is tested on the real thread with a service that records its pid, killed, disabled and dropped.
