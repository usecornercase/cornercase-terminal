# Windows

Code: `os.rs`, `os/` (`os/fs/windows.rs` for files, `os/fs/windows/acl.rs` for owners, DACLs and a process's user, `os/socket/windows.rs` for the socket, `os/process/windows.rs` for the server's process: starting it in the background, its Ctrl events, the restart in place; and for stopping a process: its windows, its end, Job objects; `os/process/windows/session_end.rs` for the window that hears a logoff or a shutdown), `protocol.rs` (the socket's folder and its peer), `paths.rs` (the folders), `client/server_process.rs` (starting the server), the `imp` pairs in `client/requests/watch.rs`, `client/input.rs`, `client/probe.rs`, `client/window.rs`, `cli/config.rs`, `cli/requests.rs`, `highlight/limit.rs` and `term.rs`, `term/shell.rs` (the default shell), `client.rs` (keeping and restoring the console's modes), `process.rs` (its Windows `imp`, `program_name`, `is_shell`, `signal_group`), `script.rs` (what runs a script: Git's `sh` or PowerShell), `process/handles.rs` (the files a process holds open, and the proxy's handles kept from the server), `agents.rs` (`basename`), `os/random.rs` (the system's random bytes), `web/tailscale.rs` (where Tailscale's CLI is), `cli/reach.rs` (a path given with `--remote`), `remote/shell.rs` (a Windows machine at the other end: cmd's and PowerShell's lines), `.github/workflows/ci.yml` (the `windows` job)

- **Native, not WSL** (#586): inside WSL cornercase already runs, but on another machine's files, `PATH` and agents. The port runs it on Windows itself, one step at a time in small pull requests to `main`, each one tracked under #586.
- **Possible** (spike on 2026-11-02, Windows 11, Rust 1.99.0, Zig 0.15.2, Visual Studio Build Tools 2022 with MSVC 14.44): `libghostty-vt` 0.2.2 builds for `x86_64-pc-windows-msvc`, and a `Terminal` parses VT input and formats it back as text. Every dependency checks, portable-pty included (its Windows backend is ConPTY). What does not compile is ours: the socket, the console, processes, file modes, git paths as bytes and the host helpers, all on Unix-only APIs.
- **Every step keeps Linux and macOS as they are**: their code is only moved behind a per-OS layer, a `mod imp` per OS with a fallback, as `process.rs` already does. Windows can be incomplete, never half-working: what is not ported returns `Unsupported`, and the window says so.
- **Releases and updates** (#602): a release builds `x86_64-pc-windows-msvc` on `windows-2025` into a `.zip` with dist's PowerShell installer, and `usecornercase.dev/install.ps1` runs the latest one, also over a running cornercase; there is no arm64 build yet, and Windows on Arm runs the x64 one under emulation (see Releases). An update renames the running `cornercase.exe` to `cornercase.old.exe` before writing the new one, since Windows refuses to overwrite or delete a running program's file but lets it be renamed, and a later start deletes the old copy once nothing runs from it (see Updates › On Windows); `update::INSTALLER` is the PowerShell line there. The website's install page, FAQ and Known limitations say how it installs on Windows and what does not work yet (the list below), and `AGENTS.md`'s known limitations point here.
- **What does not work on Windows yet**: the Clone on machine dialog offers no git-ignored files, `cornercase clone --file` and `--list-ignored` refuse, and a `clone` writes none of the `files` it carries (see Git's paths and canonical folders › Copying files into a clone is refused); a machine's link is not remade at a wake (see Network paths › The remote hosts' code); there is no arm64 build (see Releases); a Windows machine at the other end of `cornercase remote` or `--remote` was checked only against a stand-in for its sshd, and killing a `--when-idle` command here leaves its wait there, since Windows cornercase does not watch its input yet (see Remote windows › A Windows machine at the other end), and the Telegram and Discord bots and Tailscale's `serve` were not tried live (#603, see Beyond this machine); an agent whose `.cmd` or `.bat` launcher cornercase cannot read as an npm shim (pnpm's, an older npm's, one of your own) is not started when its launch line holds one of cmd's metacharacters (`& | < > ^ % !`), and no agent is started in a PowerShell pane with a word that is `--%`, or holds `"`, or holds a space and ends in `\`, which Windows PowerShell 5.1 would split, nor in a `cmd.exe` pane with a line holding one of cmd's metacharacters or a word with a space (see The coding agents); PowerShell's default prompt reports no folder, and a background job counts as the foreground (see Panes in ConPTY); and the harmless gaps of the audit (see Lifting the refusal). Done since this list was first written: a Windows machine as the other end of `cornercase remote` and `--remote`, through cmd or PowerShell (#603, see Remote windows), a pane program's mouse (#616, see The mouse needs nothing of ours), a clean stop at a logoff or a shutdown (#617), the files a process holds open for the context line (#618), folders without the `\\?\` prefix (#613), the test suite in the Windows CI job (#601), and releases, the installer and updates (#602).
