# Windows

Code: `.github/workflows/ci.yml` (the `windows` job)

- **Native, not WSL** (#586): inside WSL cornercase already runs, but on another machine's files, `PATH` and agents. The port runs it on Windows itself, one step at a time in small pull requests to `main`, each one tracked under #586.
- **Possible** (spike on 2026-11-02, Windows 11, Rust 1.99.0, Zig 0.15.2, Visual Studio Build Tools 2022 with MSVC 14.44): `libghostty-vt` 0.2.2 builds for `x86_64-pc-windows-msvc` in about a minute, and a `Terminal` parses VT input and formats it back as text. Every dependency checks, portable-pty included (its Windows backend is ConPTY). What does not compile is ours: the socket, the console, processes, file modes, git paths as bytes and the host helpers, all on Unix-only APIs.
- **Every step keeps Linux and macOS as they are**: their code is only moved behind a per-OS layer, a `mod imp` per OS with a fallback, as `process.rs` already does. Windows can be incomplete, never half-working: what is not ported returns `Unsupported`, and the window says so.
- **CI** (#587): a `check (windows-2025)` job runs `cargo check --all-targets --all-features --locked` with the same toolchain, Zig and cache as the other jobs. It is `continue-on-error` until the build compiles (#588), so it shows where the port stands on every pull request without blocking one; its step summary repeats cargo's `could not compile … due to N previous errors` lines. Once it compiles it becomes required and runs clippy.
- **Long paths**: Ghostty's sources hold files about 216 characters deep inside `target/` (its fuzz corpus), which passes Windows' 260-character `MAX_PATH` on the runner's `D:\a\cornercase-terminal\cornercase-terminal\`. Git cannot check them out without `core.longpaths`, so the job sets it before anything clones. A short `CARGO_TARGET_DIR` was not needed: the deepest file the linker writes (a build script) stays near 145 characters there, and the default `target/` keeps `Swatinem/rust-cache` working without a mapping. Locally, the spike's first build failed with `LNK1104` only because its `target/` sat about 150 characters deep.
