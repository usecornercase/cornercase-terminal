# Telling a client the accounts changed

Part of [Accounts and profiles](../accounts-and-profiles.md). Code: `control/app_state.rs`, `app/control/status.rs`, `app/control/accounts.rs`, `accounts/mod.rs`, `control/contract.rs`, #665.

- **Why**: a client that draws cornercase follows the window's rule, no switcher or mark until there is an account, and reads that from `account list --json`. `account rename`, `account use` and profiles write `config.json`, so `config.revision` tells it to read again, but `account add` only makes a folder, and removing an account with no label that is nobody's default leaves `config.json` as it was: on 0.13.1 neither printed a line on `view`, `status --follow`, `status --app --follow` or `events`. So a first account added by a command typed in a pane showed in another window only when that window happened to ask.
- **`accounts_revision` in `status --app`** is `Logins::generation`, which moves when the listing differs from the last one, whichever step listed it: the 1 s sync step (a folder another program made or deleted) or an `account-*` request. It costs nothing new: the modification times were already watched and the `app` stream already compares whole snapshots, so a move prints a line and no code path has to mark it. It moves for the names only; a label, a default and a profile stay `config.revision`'s, and a login stays `account list --check`'s. It starts again on a restart, like every revision.
- **The first listing is not a change**: `accounts::list` always holds a row for each agent that takes accounts, also when it has none, and `listed` started empty, so the first sync step (the server's first step, since `Clock::sync_due` is true before anything synced) moved the generation of every server to 1, with or without accounts. The key would then have been there on every server, and a first account would have read as a move from 1 to 2. `listed` now starts as `accounts::no_accounts()`, the listing of no accounts, so the generation stays 0 until there is something to tell. A server that starts with accounts has 1 from its first line, whatever the number was before its restart, which is why it only compares within one `boot`.
- **Left out while 0, and the feature `accounts-revision`**: leaving it out keeps a server without accounts as it was. It also reads the same as an older server, which never moves it, and a client that drops its other reasons to list (connecting, becoming active, `config.revision`, a pane using an account it had not seen, closing its Accounts sheet) must tell the two apart, so `contract` lists the feature. No command needs it: `status --app` prints whatever the server sends.
- **Left out**: asking `account list --json` on a timer from every client (a process per poll, over ssh too, for something that rarely changes); the names themselves in `AppState` (a client needs what `account list` answers anyway, with paths, labels and `unshared`, and the snapshot would grow for what its list already holds); a line on `events` (it keeps no state, so a client that was away would miss it, where the stream's first line holds the number); `watch` and `view` (a whole session snapshot every agent read, and their shape stays as it is, see Following the rest of the app); a revision in `account list`'s answer (a change after a listing always prints a line, so a client that lists on each line is at worst too fresh, never stale).
