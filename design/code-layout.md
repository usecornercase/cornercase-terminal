# Code layout

Code: `src/`, `tests/layers.rs`

- **By domain**: code is grouped by what it is about. Each domain has one folder (or a file and its folder), named like its section in this file. A domain holds its model (its data and pure rules) and the background jobs that feed it (git, HTTP, reading files). Its drawing lives in `ui/` and its wiring into `App` in `app/`. The tree moves there one step at a time, and new code goes where these rules say. Left out: folders by layer (domain, infrastructure, app, ui), a crate workspace, and a rewrite of `App` as traits, plugins or messages. Each would change every file at once, when the only problem is where code goes. Modules are not renamed for taste: `control` stays `control`, `state` stays `state`, and a module keeps its form (`foo.rs` beside `foo/`, or `foo/mod.rs`).
- **`lib.rs` in five groups** (#197): its `pub mod` lines form five blocks, separated by blank lines and unnamed in the code, which has no comments. (1) The shared leaves: `error`, `gh`, `http`, `list`, `log`, `panics`, `paths`, `persist`, `process`, `text`, `time` and `version`. (2) The domains, each a model and its own I/O jobs: `accounts` (`links`), `agents` (the known agents, and `activity`, `awake`, `context`, `launch`, `stats`, `tree` and `usage`), `changes`, `config`, `discord` (`gateway`, `markdown`), `files`, `flows` (`brief`, `builtin`, `dialog`, `folder`, `progress`, `registry`, `run`, `share`, `start`, `store`), `git` (`remote`, `upstream`, `worktree`), `graphics`, `highlight` (`markdown`, `syntax`), `host` (the outer terminal: `clipboard`, `notify`, `open`, `pointer`, `sound`, `theme`), `issues` (`secrets` among the trackers, `html`, shared by Plane and Asana, and `locate`, which turns a key or a URL into the issue, shared by the queue, `start`, `flow run` and `issue read`), `messenger` (`link`, `markup`), `plugins` (`manifest`, `registry`, `run`, `supervise`), `project` (`group`, `hierarchy`, `picker`, `search`, `split`, `view`, `vscode`), `pull_request` (`merged`), `settings`, `shortcuts`, `star`, `state`, `telegram` (`html`, `link`), `term` (`emulator`, `keys`, `memory`, `mouse`), `todo`, `queue` and `update` (`restart`). (3) The view, `ui`. (4) The application, `app`. (5) The processes: `cli`, `client`, `control`, `protocol`, `remote`, `server` and `web` (`tailscale`). `web` sits with the processes rather than the domains: it serves the window to a browser from inside the server as one of its clients (its bridge sends `Hello` and decodes input with `client::input::Parser`), and only browser access uses `tailscale`. A child module keeps its folder, which holds its tests and, for `agents/context/` and `agents/usage/`, its children; every item stayed as reachable as before, through a longer path, until the next step narrowed `pub` (below). Only one file was renamed in that move, `host_theme.rs` to `host/theme.rs`; its types kept their names (`HostTheme`, `ThemeProbe`). The move was made by a script, kept in the description of its pull request, so that a branch open at the time could run it over its own changes.
- **`pub` is what the binary and the e2e tests use** (#197): every module, item and field is `pub(crate)` or narrower, except what `src/main.rs` (`cli::{run, Cli}`, `error::Error`) and `tests/e2e/` reach, with the modules on its path and the types in its signatures and fields: `agents::claude`'s Claude variables, `agents::stats` and `agents::Known` (the e2e test writes a `stats.json`), `control`'s status report and pane rows, `paths::SOCKET_ENV`, `protocol::{NESTED_ENV, own_uid}`, `project::split::{Dir, Node}` and `project::group::GROUP_STYLES`, `host::clipboard::osc52`, `update::{LATEST_ENV, target}`, `version::CURRENT`, `config::Sidebar`, `state::Widths`, and the `ui` geometry the e2e tests click by (`layout`, `Areas`, the buttons, rows and `todo::rows`). The compiler never reports a `pub` item of a library as unused, since another crate could use it, and with everything `pub` (about 1,040 items, 680 methods and 1,100 fields) dead code stayed. `unreachable_pub = "warn"` in `Cargo.toml` keeps it so: a new item is `pub(crate)` unless the binary or the e2e tests need it, and `dead_code` then reports what nothing uses. Narrowing found little dead code, deleted in the same change: `files::Panel::indexed_files`, `Lines::is_empty` in `files`, `shortcuts::Prefix::event`, `todo::Removed::is_empty`, `web::Web::browsers`, `ui`'s `list_item_at`, and re-exports nothing read (`app::Start`, `ui::{AGENTS_LABEL, TODO_LABEL, files_button, scrollback_label}`). What only the tests use (some `ui` geometry, `git::main_worktree`, `graphics::decode::HEAD`, `web::Web::listening`, a few methods) stays where it is under `#[cfg(test)]`, so tests keep taking positions from the geometry next to the drawing code. Variants and fields of serialized types would keep an `#[expect(dead_code, reason = "…")]` rather than go, since they are read by other programs or older versions; none was reported. Clippy's `avoid-breaking-exported-api` (on by default) skipped some lints on exported items; once crate-private they apply: `term::mouse::encode` takes its `MouseEvent` by value (`trivially_copy_pass_by_ref`), and the keys request's `keys` field keeps its JSON name under an `#[expect(clippy::struct_field_names)]`.
- **One folder per agent** (#198, PR 1; `grok/` in #241, `cursor/` in #290 and `copilot/` in #330 followed the same shape): `agents/{claude,codex,gemini,opencode}/` holds each agent's existing activity rules, record readers, last-message readers, plan probes where supported, and test fake. Whole files move with their tests; mixed files are cut by ownership. `agents.rs` keeps the catalogue, modes, arguments, detection, trust and resume rules; `activity.rs` keeps shared activity, status, notifications and rollups; `context.rs` keeps its existing pane state and update methods. Discovery, JSONL, counting and backwards-message helpers stay in `context/`, and the probe runner and dialog state stay in `usage/`. Item names and bodies stay unchanged; callers use the new paths without compatibility re-exports. Claude's module exposes the two environment constants the e2e tests need; the other agent modules are crate-visible. `activity` is also crate-visible now that those constants moved out and no external caller needs it. Helpers shared only within agents use `pub(in crate::agents)`; plan-probe fixtures used by app tests and fake modules are crate-visible under `cfg(test)`. Tests follow their subject; the record-selection and subagent-counting tests remain beside `context::Pane` to check shared dispatch and its counting ledger. The session helper used by activity tests stays with Claude's tests, and the writer used by both message readers stays with the shared backwards tests. Fixtures and snapshot files keep their paths and bytes. Identity dispatch and reader ownership are described under Agents and Context use.
- **Shared leaves** (`error`, `gh`, `log`, `panics`, `process`, `version`, `paths`, `time`, `persist`, `text`, `list`, `http`) import only the standard library, external crates and other leaves. `tests/layers.rs` checks their production files and allows their tests to use domains. Helpers move with their callers, so domains import the leaves directly, and so do the e2e tests (`version::CURRENT`, `paths::SOCKET_ENV`). `persist::Saver` has no default type because a leaf cannot name the session model; its server field names `State` explicitly. `CORNERCASE_SOCKET` is read in one place (`paths::custom`, behind `custom_socket`, used by `socket`, `earlier_sockets`, the files that sit next to the socket and `protocol::Folder::current`), `config` and `session` share one `$XDG_*_HOME`-or-`$HOME` fallback and a debug build's `cornercase-dev` folders (Client / server), and each file keeps its own name rule. `time.rs` holds one calendar (`days_from_civil`, `civil_from_days`); `Stamp::parse` still answers `None` before 1970. OSC 52 and Jira's Basic header use the `base64` crate, as the kitty, iTerm2 and stats code already did, so `host::clipboard` no longer has an encoder of its own. The savers keep their policies.
- **Models never use `app` or `ui`**: only `app` and `server` use `crate::app`. Only `ui`, `app`, `server` and `client` (the reconnecting notice) use `crate::ui`. A model that needs something from `ui` (a label helper, a preset, a width) moves it into the model or into a shared module. A view built from a model's state is built in `app`. ratatui's own types (`Style`, `Color`, `Rect`, `Line`) are not `ui`, so the modules that use them keep them: the emulator, highlighting, Markdown, the diff, and split and pane geometry. Before this rule, `settings` and `usage` imported `ui` while `ui` imported them, and `term` and `web` imported `app`. So a dialog's model and its drawing could only change together.
- **Dialog models own state and rules**; the TODO panel, settings input and the issues browser show the pattern. Models take sizes and semantic hits, and `app/<name>_dialog.rs` builds and hit-tests the `ui` view. Texts decided by the model stay plain strings there; a view built in one piece and the tests that read it move together. The remaining dialog view builders migrate one model at a time.
- **Session and config types belong to models** (#193): `project/group.rs` owns `Group`, `GroupEntry` and group styles; `config.rs` owns `Sidebar` and `Tabs`; `state.rs` owns the serialized `Widths` fields; `agents.rs` owns `AgentState`. Their derives and serde attributes stay unchanged, and config keeps storing strings. `ui/widths.rs` keeps the width default and geometry impls, which need its constants and `ui::Border`; Rust permits those impls elsewhere in the same crate. Models, the app and the e2e tests import them from their owners; the re-exports in `ui.rs` and `state.rs` that kept the old paths went in #197.
- **`impl App` only in `app.rs` and under `src/app/`**: Rust lets only the module that defines a struct, and that module's child modules, see its private fields. An `impl App` in, say, `changes/` would need `App`'s fields to be `pub(crate)`. `app.rs` keeps the struct, `App::new`, the methods the server calls, the refresh pipeline, and dispatchers whose arms are one call each. Everything else goes in one child of `app` per concern. The split keeps item bodies and public paths unchanged. Private items shared by children or tests use `pub(super)` (nested children use `pub(in crate::app)`); fields of moved structs use `pub(super)` because siblings cannot see private fields. The fields of `App` stay private. Children import moved items from their defining module, so the switchboard does not become an import registry for the whole app.
- **A feature is three files with one name**: its model (`todo/`), its wiring (`app/todo_panel.rs`, or `app/<name>_dialog.rs` for a dialog) and its drawing (`ui/todo.rs`). The suffix also keeps a child of `app` from taking the name of a module that `app.rs` imports by name (`todo`, `changes`, `files`, `search`, `settings`), which Rust refuses (E0255). In `ui/`, a widget keeps its view types, geometry, hit testing and drawing in one file. Drawing and hit testing share the geometry (see Layout), and a widget spread over three places in `ui.rs` was hard to change in one go.
- **State goes in its concern's file; a background job starts through `App::spawn_job`** (`app/jobs.rs`): the work, and the closure that turns its result into an `AppEvent`, are all a feature writes. Three kinds of thread stay by hand: the file read, which answers twice, the Tailscale worker, which runs its orders one after another on purpose, and the plugin supervisors, which run for as long as the server or the window (see Plugins).
- **App state belongs to its concern** (#194, PR 3): `App` holds six groups instead of listing each concern's fields centrally. Each group owns its original defaults and environment reads; list scrolls and upstream pacing use `Default`. The rest of the core state, the panels and test knobs stay flat.

  | Field | Type and owner | State |
  |---|---|---|
  | `issues` | `IssueConnections`, `app/trackers.rs` | Issue and people caches, accounts, connection epochs, API endpoints, token variables and secrets path, remembered browser tab, closed switch and people filters. |
  | `update` | `UpdateState`, `app/update_dialog.rs` | `updates`, changelog `scroll`, `restart_list` and when it was `listed`. |
  | `agents` | `AgentRuntime`, `app/agent_watch.rs` | Pending launches, cached trust pattern, last `watched` time, awake lock, `claude_dir` and stats. |
  | `outbox` | `Outbox`, `app.rs` | Host writes, notifications, detach and restart requests taken by the server. |
  | `scroll` | `Scrolls`, `app/layout.rs` | Projects, workspaces, agents and tab-bar offsets, and the `followed` focus. |
  | `upstream` | `Upstream`, `app/worktrees.rs` | Fetch times, projects being counted and the last count time, and the projects whose linked worktrees could not be read. |

  The child types and their fields are `pub(super)`; `App`'s fields and its `Outbox` fields stay private. Nothing becomes visible outside `app`. The two `Outbox` types have different owners: the app queues effects, while `server::Outbox` writes one client's messages, so their module context keeps them distinct. Functions keep borrowing individual fields, such as `agents.stats` and `agents.claude_dir` during a mutable walk of `projects`; adding helper methods to these groups would borrow a whole group. Copying now uses `App::copy` after a pane lookup returns a plain reference (see Hierarchy). Server-facing signatures stay the same (`take_host_writes`, `take_notifications`, `take_detach`, `take_restart`, `stats`, `set_stats`, `set_issue_cache`). Test edits only follow the new field paths; their behaviour, names and snapshots stay the same.

- **One drag at a time** (#194, PR 4): `App::drag: Option<Drag>` replaces the independent drag fields, including the files panel's line-selection anchor. `Drag` lives in `app/interaction.rs` beside its payloads and is `Clone`, not `Copy`; its variants are `Border`, `Divider`, `Row`, `Pane`, `Selection`, `Link` and `Lines`. Starting one replaces the previous drag and resetting interaction clears it once. Dispatch, key cancellation, pointer shapes, link hover and the view exhaustively decide which variants they handle; the row accessor does the same for tick and auto-scroll readers. `Selection` carries an optional path press so selecting text and opening an unmoved path share one state. `Link` passes through drag dispatch to pane mouse handling, retaining the underline while a mouse-reading program's press waits. `Esc` and the prefix key cancel only border, divider, row and pane drags; text and file-line selections continue. Border and divider double-click history stays separate because it outlives the drag. The enum and payloads are visible only inside `app`; server methods, serialized state and `ui::Drag` keep their signatures and paths.

- **One side panel at a time** (#194, PR 5): `App::side: Option<Side>` replaces the three panels' independent `open` flags. `Side` lives in `app/layout.rs` and is visible only inside `app`. `show_side` closes the previous side through its existing close method before selecting the next; selecting the same side does nothing, so opening a path in an already open Files panel keeps its search state. Switching commits a TODO edit and unfocuses a changes filter or files search. `close_panel` drops the TODO field first so `Esc` still cancels it. The panel models keep their contents and places without owning visibility. `refresh_files`, before `refresh_changes`, sets `changes.watched` when Changes is selected or Files is visible, preserving the one-second refresh pace. Restore prefers Files, then TODO, then Changes when saved flags conflict; save keeps the existing three booleans, omission rules and session version. Trace still logs `panel shown=changes|todo|files|none`. `Side::Flow` (#263) came later as a fourth side, with a fourth flag of its own (see Layout).

- **Dialogs dispatch once per overlay** (#194, PR 6): a dialog is an `Overlay` variant with its view and mouse handling in its own `app/` file. `overlay_view`, `overlay_mouse` and `submit_form` keep one-call arms or plain values, so adding a dialog adds its variant and a line to each dispatcher. The name forms and closing confirmations share `app/dialogs.rs`; confirmations use one builder with their own title, message and labels. Menus live in `app/menus.rs`, usage clicks and sharing in `app/usage_dialog.rs`, and remote clicks in `app/remote_access.rs`. Mouse dispatch matches a borrowed overlay, so it neither clones state nor removes the dialog before hit testing. It checks a left press outside first, then delegates; a menu closes on any press and acts only on a left one, while forms act only on left presses. Submission takes the overlay and each working arm returns its successor, including workspace validation and creation in `app/worktrees.rs`; a busy or otherwise unhandled overlay is returned unchanged. Helpers shared between children stay `pub(super)`, and submission helpers used only by `dialogs.rs` stay private. Server methods, keyboard dispatch, snapshots and serialized state keep their existing contracts.

- **Job answers belong to their domain** (#194): `AppEvent` (`app/event.rs`) wraps `WorktreeEvent`, `IssueEvent`, `ChangesEvent`, `FilesEvent` and `UpdateEvent`, defined and answered in `app/worktrees.rs`, `app/issues_dialog.rs`, `app/changes_panel.rs`, `app/files_panel.rs` and `app/update_dialog.rs`. Adding an answer changes only its domain's enum, `name()` and handler. Each enum is `pub` and derives `Debug`, since it is a payload of the public `AppEvent`; `app.rs` imports their names for `app/event.rs` and the app tests. `AppEvent::name()` delegates to the nested enum and keeps the existing words on `server.log`'s `job answered` lines. Every `handle_event` arm is one call; input filtering and PTY output stay in methods in `app.rs`, keeping the server's `Input`, `Output` and `Exited` variants and the mappings from `term::Event` and `web::Event`. Issue epochs are checked in `issue_answered`: stale lists, reads and people are dropped, while a stale token check still answers an error so its form stops waiting. `IssueEvent::Replied` (#340) carries the answers of the requests (`issue-list`, `issue-read`, `issue-people` and the lookup behind `start --issue` and `flow run --issue`) to `app/control/issues.rs`, which checks the epochs it was started with; its payload is boxed so `AppEvent` stays small.
- **Models send their own events** (#193): `term` and `web` do not name `AppEvent`. `term::Event` (`Output`, `Exited`) and `web::Event` are theirs, and `Term::spawn` and `Web::new` take a `Sender<E>` for any `E: From<…>`; `app/event.rs` maps them onto `AppEvent` with `From`, so `Server` and `App` still match `AppEvent::Output`. `web`'s `Context` holds the sender as an `Arc<dyn Fn(Event)>`, so it and the bridge stay non-generic. The server's identity in every shell (`CORNERCASE`, `CORNERCASE_PANE`, `CORNERCASE_SERVER`) is built by `App::pane_env` and passed in `SpawnOptions::env`, ahead of the caller's own entries; `term` only sets `TERM` and strips Claude Code's session variables, which apply to any shell.
- **Tests in a file of their own**: the tests of `foo.rs` (or `foo/mod.rs`) go in `foo/tests.rs`, declared with `#[cfg(test)] mod tests;`. Large ones keep their shared helpers there and put each group in `foo/tests/<group>.rs`. They stay child modules because they use private fields and methods, which the integration tests in `tests/` cannot see. A snapshot lives in `snapshots/` next to the file whose test calls `assert_snapshot!`, which is where insta looks for it. Its name comes from the module path, which a move keeps. A file that still holds an inline `mod tests { … }` keeps it until its tests move out, in a commit that changes nothing else.
- **At most 1,000 lines per file**, in `src/` and `tests/`, tests included. `app.rs` grew to about 17,000 lines and was touched by half of all commits, so branches working on unrelated features kept meeting there.
- **Moving is not changing**: a commit that moves code changes no behaviour. The same tests pass, and snapshots keep their names and what they render. Duplicates that differ on purpose stay apart. Old paths keep resolving through `pub use` until their callers move. So a move can be reviewed as a move.
- **`tests/layers.rs`** checks the imports and the line limit on every `cargo test`. It reads the sources under `CARGO_MANIFEST_DIR` and leaves out comments, strings and test code (`#[cfg(test)]` items, `tests` modules, `test_util`), since tests may take positions from `ui`'s geometry. It resolves each `crate::`, `super::` and `self::` path to the module it reaches, inline modules included. The files that broke a rule when the check was added are its exceptions. The lists only shrink: an entry that no longer applies fails the test until it is removed, and nothing is ever added (a file that moves renames its entry). An import exception covers its file and the folder of the same name next to it, so splitting `foo.rs` into children under `foo/` needs no new entry, while an entry for `foo/mod.rs` covers only that file and the rest of `foo/` stays checked. A size exception covers its own file only: every file a split creates must already be under the limit. A parser crate (`syn`) was left out: as a dev-dependency it would change `Cargo.toml`, which makes a pull request a release, and a small scanner does the job.
- **jscpd sees every file**: `.jscpd.json` sets `maxLines` and `maxSize` far above any file. By default jscpd skips files over 1,000 lines or 100 KB, and it counts lines with `split("\n")`, so a 1,000-line file ending in a newline is already over. That left out the 14 largest files, `app.rs` and `ui.rs` among them, which hold more than half of the lines. So jscpd reported 0.43 % of duplication where there was 0.87 % (October 2026).

- **`ui/` is one file per part of the screen** (#191): `ui.rs` keeps `View`, `draw()` and the `mod` and `use` lines, and each child (`sidebar`, `workspaces`, `tree`, `agents_section`, `drop`, `chrome`, `pane`, `toast`, `dialog` with `dialog/`) holds its part's view types, geometry, hit testing and drawing, so a widget is no longer spread over three stretches of one file. The children are private modules and `ui.rs` re-exports every public name from them, so `ui::X` stays the one public path. Helpers several parts share live in `widgets.rs`, `theme.rs` and `rows.rs`; the older children (`changes`, `files`, `todo`, `tab_bar`, `remote_access`) keep reaching them as `super::X` through a private `use` in `ui.rs`. Items other files use are `pub(super)` (`pub(in crate::ui)` in `dialog/` when `ui.rs` or another part uses them), the rest stay private; the few fields and methods of `Rows`, `Band`, `Tags`, `Spot` and `Search` that other parts reach are widened the same way. The tests stay grouped by behaviour in `ui/tests/`, not by file, so a move never renames a snapshot.
