# The trust prompt

Part of [Agents](../agents.md).

- **The trust prompt is left to the user by default** (`accept_trust_prompts`, off). It is the agent's guard against running a repository's own agent config (project settings, hooks, MCP servers) before anyone looked at it, so answering it for the user would run a hostile repository's config as soon as an issue starts. It used to be on by default, as `auto_accept_trust_prompt`; the key was renamed so every saved `true` (settings save the whole file) falls back to off once, and turning it on again is one click. A per-project "trust this project for agents" was left out: off costs one Enter per issue started, and agents remember the folders already trusted. Whatever the setting, the prompt is detected: a launch that may not answer it parks (`Launch::waits_for_you`) until the agent prints again, which the answer does; its clock restarts from that output, so `AGENT_LATEST` never types into the question, and once the screen is quiet without the question it pastes the prompt. A parked launch is not polled: `App::tick` asks for the 100 ms launch wake-up only for launches that are not parked, since the user may take hours to answer and every wake-up draws every client. Before, a launch with answering off typed the prompt into the question, and Enter picked Claude's highlighted "No, exit". If the user says no, the shell comes back and the launch is abandoned as usual. A flow's launches answer it whatever the setting (`launch::Spec::trusted`, see Flows). `trust_prompt_pattern` is matched only against the last 15 non-blank lines of the screen (`agents::asks_trust`), where an agent draws the question, so older output above cannot match; the regex is compiled once per pattern (`agents::TrustPrompt`). Since Claude Code 2.1.326, each folder given with `--add-dir` that the session has not worked in gets its own start-up question (title `Adding a new directory:`, options `No, exit` and `Yes, add it`, `Esc` exits), asked again on every resume, and every flow role gets the run's folder that way. On 2026-11-17 all 7 agents of a run waited at it, each got its prompt pasted blind and 5 Enters, and none started until answered by hand (#905). None of the default phrases is in it, and changing the default alone reaches nobody who ever saved a setting (settings save the whole `config.json`), so `agents::claude::screen::adds_directory` recognises it whatever the pattern and the launch treats it as a trust prompt: answered for a flow and with `accept_trust_prompts` on, parked otherwise. The default also gained `yes, add it` for new configs. The check wants the option line, the title without whitespace (or the ` Adding: ` line when the top scrolled off) and no input box below the option; it reads the whole screen, since below 30 rows the question is about 16 lines. While Claude Code's input box is drawn the pattern is not looked at (`Known::input_box`): its questions come before its box, and a resumed conversation printed above the box can hold the pattern's words, which a flow's resume would have answered with keys typed into the box (checked live: `--resume` prints the conversation). The bundle's guards: the options take no key for 500 ms and an answer within 250 ms is dropped (the launch's quiet second covers both), Yes is taken only from an `Enter` right after `Down` (a key reaching Claude Code between them, someone typing in that tab, makes it refuse, and the launch gives up as today), text typed while the question shows is kept and `Down` stops counting, and a question taller than the pane can refuse Yes (`first make the window taller`), which stays a limit. Checked live on Linux with 2.1.326 (scratch config, fake API key, tmux, 2026-11-17): the folder question first in an untrusted repository, its new wording still matched by the pattern; a resume asks before printing the conversation. macOS and Windows were not checked; it is the same code.
- When answering, the prompt may highlight "No" by default (Claude Code does), so `answer_keys` moves the selection to the "yes" option before pressing Enter. The menu is the **last** line on the screen that starts with a marker, since a shell prompt starting with `❯` stays above the agent's question: the first marked line found no "yes" near it and pressed `Enter` on Claude Code's highlighted "No, exit" (checked live with 2.1.326's screen under a `❯ ` prompt). A menu that defaults to No takes two answers (the arrow, then `Enter`), so `MAX_TRUSTS` is 8: an untrusted repository's folder question plus the run folder's already take four, and the bound only stops a screen that keeps changing from being answered forever.
