# Changes panel

Code: `changes/`, `ui/changes.rs`, `app/changes_panel.rs`

- Git workspaces only: ` Changes n ` next to ` Issues ` (` ± ` in the compact bar) opens a fourth column right of the pane (full screen in compact mode). Its border drags; its width is `Widths::changes` (`None` = half the free space, at most `DEFAULT_WIDTH`).
- Tabs: uncommitted (`git diff HEAD` + untracked), commits (`git diff <merge-base> HEAD`), all (`git diff <merge-base>` + untracked). The base is `Workspace::base` (saved per workspace) or the default branch: `origin/HEAD`, else `main`/`master`. Comparing from the merge-base keeps commits made on the base later out of the diff.
- Git runs on a thread, one job at a time, every second while it or the files panel is open (`Panel::watched`, for its marks) and every 3 s while closed (for the button's count). Flags matter: `--no-optional-locks` and `-c diff.autoRefreshIndex=false`, because a plain `git diff` rewrites `.git/index` (takes `index.lock`) even with `--no-optional-locks` and would fight an agent's `git commit`. `--relative` keeps paths inside the workspace folder. Untracked files are read directly (never `git add -N`), capped at 1 MiB, NUL in the first 8000 bytes means binary; a symlink shows its target path, like git, never the file it points to. The branch list and "unchanged lines" also run on threads and answer with `AppEvent::Changes(ChangesEvent::Branches { … })` / `AppEvent::Changes(ChangesEvent::Gap { … })`.
- The job hashes git's output; an unchanged hash answers without a diff, and files whose patch section did not change are reused, so highlighting runs only for what changed. syntect costs ~150-200 µs per line, far more than computing the diff.
- Rendering: lines paired delta-style (word tokens, changed share ≤ 60 %) get word emphasis; each hunk side (context + removed, context + added) is highlighted separately. Tints blend the host background with palette red/green when the client has `COLORTERM=truecolor` and the background is known; otherwise palette colours, and on dark themes only the `▎` bar, coloured numbers and word emphasis (palette greens and reds are too loud as line backgrounds).
- **Filter** (`changes/filter.rs`, pure): ` ⌕ ` left of the panel's `×` opens a field under the tabs (the header grows a row, so the summary and the base selector stay) that filters files by path only; searching the lines was tried and dropped as not useful. While it is focused (`Filter::focused`, and only while the panel shows and no overlay is open) keys and pastes go to it, like the global search: `Enter` keeps the filter and unfocuses, `Esc` or its `×` closes and clears. Any press outside the panel gives the keys back and keeps the query; a click on the field or ` ⌕ ` takes them again; closing the panel unfocuses it. Each word is an include, or an exclude with `!`; a file stays if it matches any include (or there is none) and no exclude, by its path or its old path. A word without `*`/`?` is a substring of the path; with them a `.gitignore`-like glob (no `/`: any path component, a trailing `/` only folders; with `/` or a leading `/`: the whole path, also everything under it; `*` and `?` stop at `/`, `**` crosses it). Smart case per word. Folds are untouched; typing resets the scroll. Shared by clients, never saved; switching tab or workspace keeps it. `Esc` on an empty field closes the panel (see TODO panel).
- Hunk actions on hover: open (new tab running `/bin/sh -c 'exec ${VISUAL:-${EDITOR:-vi}} "+$1" "$2"'`), ask agent (pastes `path:lines ` into the workspace's agent pane, found with `agents::detect`; without one it copies the reference), copy (the hunk as a patch, OSC 52). Viewed marks use a separate review identity, so they clear when the file changes while patch reuse and unchanged-line gaps follow its patch digest.
- **Scope** (#159): a row above the modes uses the dialogs' `tab_style`. The first tab is the active project's name, with ` › workspace` only when it has several workspaces, as in the agents section; `truncate_right` reserves the entire ` Every project ` tab and the filter/close buttons even at the minimum width. Project is the default and keeps its selected mode and base when another scope is chosen. Every project shows only uncommitted changes, with a muted `uncommitted` in place of the modes and no base selector: one base cannot describe unrelated repositories. Scope is shared and saved as an optional, defaulted field beside mode; session version remains 5.
- **Targets and grouping live in `changes/every.rs`** (#195): `targets` and `group` take the projects, the `sidebar_order` and the panel, and use neither `app` nor `ui`; `Body` moved into `changes` and `Header` into `every.rs`, where the app and `ui/changes.rs` import them. `App::every_targets` and `every_body` pass `sidebar_order`; `panel_view` keeps the folds, viewed marks, gaps and filter.
- **Grouping**: Every project follows `project::sidebar_order` with groups treated as open, then workspace order, so rows do not move according to how recently an agent saved. Only open git workspaces with changed files are listed; clean projects, plain folders and workspaces being closed or removed disappear. Each view resolves its scan targets once and shares them between grouping, the loading state and the live indicator, avoiding repeated reads of every checkout's HEAD during drawing and mouse handling. A project header carries its total files and line counts. Workspace headers appear only when several of that project's workspaces have changes, and use the workspace's label/branch. Clicking either header hides or reveals its file rows without switching focus or changing each file's fold. Project arrows sit one cell in, workspace arrows three and file arrows four, so files always read as children of their headers; project scope keeps its existing indentation. Scope tab drawing and clicks reserve the label's full cell width, including its trailing space, in the app and simulation. Headers whose files all fail the path filter are hidden; their totals still describe the complete group, like the panel's line totals. Until the first scan finishes an empty list says `reading changes…`; a completed empty view says `no changes in any project`. An open Every project view stays visible when the user switches to a plain folder or closes the last project; its entry buttons remain git-only.
- **Lazy patches**: Every project has separate file folds, initially folded, so opening it never inherits an expensive unfolded project view. Viewed marks and unchanged-line gaps remain keyed by workspace and path. A viewed file that changes loses its mark and opens again, as in project scope, so its new work becomes reviewable. The worker asks for porcelain v2 status and NUL-separated numstat, preserving renamed paths, binary files and workspace-relative paths. Untracked text uses the same byte, line and binary caps, without constructing hunks for the folded list. Patch parsing, tracked summaries and untracked reading share one fold classifier: binary first, then more than 3000 added and removed lines, then lockfiles, then ordinary text. The summary marks oversized tracked files as Large from numstat, before any unfold request, so they keep their counts-only state and never alternate between loading a large patch and discarding its hunks. Only unfolded files that can show lines and are visible under their headers and path filter get a patch and highlighting; their patches refresh on each visit. Folded headers therefore stop patch reads too. `collapse all` / `expand all` act across the collection; expanding all also reveals its headers. File actions carry their own workspace id and folder. Open and ask agent reveal the owning project, workspace and destination tab through the same navigation used by search and the agents list, unfolding the tree and closing the compact menu while keeping Every project open, so the user can immediately work in the editor or type a question after the reference. Copy keeps focus; ask agent without an agent keeps its clipboard fallback. An unfolded rename's patch request includes both its old and new paths: selecting only the destination prevents git from pairing the rename and incorrectly turns it into an added file.
- **Pacing and caches**: one shared worker slot serves both scopes, with a separate summary model per workspace so overview results cannot replace the project-mode diff used by the Files panel's git marks. Completion starts the next workspace immediately; each workspace waits at least three seconds between scans, and an unfold invalidates its wait. A worker holds the shared slot for up to 30 seconds, including across scope switches. After that both scopes can request another job, retaining the existing give-up behavior so one hung git cannot freeze every workspace's changes indefinitely; late answers are still accepted without releasing a newer job's slot. Closing Every project stops the sweep and resumes the existing active-workspace job. The Changes button still counts only the active workspace (uncommitted while Every project is visible), never the collection. Summary jobs use the same index-lock-avoiding flags and `log::Job` timings, labelled `summary`, with a workspace id; failed workspaces are omitted from the grouped files and follow the existing debug job logging policy. If the collection would otherwise be empty, its first scan error is shown instead of claiming every project is clean. A workspace fold only stops patch reads while its sub-header exists, so the fold cannot conceal the sole changed workspace after the others become clean. Closing a workspace or project, starting worktree removal, and discovering an externally removed worktree forget their models, request pacing, file folds, viewed marks, gaps and header folds. Late results for forgotten workspaces are ignored, keeping a long-running server from retaining removed checkouts' parsed diffs. Workspace-relative status prefixes are derived from the nearest checkout's .git entry, including linked worktrees, avoiding an extra rev-parse process on every scan.
- **Digests**: the summary hashes status, numstat, untracked bytes/metadata, HEAD, open paths and their patch bytes before constructing its diff; an unchanged digest skips numstat parsing and highlighting. For uncommitted files, review identity combines HEAD, path, status, counts and the checkout file's size, modification time and change time, shared by both loaders. Metadata catches edits with the same line counts without reading folded tracked files; change time also catches replacements or restored modification times. Every materialized file retains its patch-section hash for reuse and gap caching, separate from its metadata-based viewed identity. A write between git reading a patch and the metadata stat can give old and new patches the same review identity; their distinct patch hashes still replace the old highlighted hunks and discard stale gaps. Folded summaries use the metadata fingerprint until a patch is materialized. The full project loader still hashes patch output and reuses unchanged highlighted files. A scope switch preserves review marks for the same uncommitted file. Commits and All retain their patch digests: a committed comparison can change without touching the checkout file, so metadata cannot identify its patch.
- **Models per (workspace, mode)** (#339): `Panel::models` held one model per workspace, the one of the panel's mode, so two readers of one workspace in two modes would have replaced each other's result every second. It is now keyed by `(workspace, mode)`, with `model_in(workspace, mode, base)`, `label_in` and `request_in(target, mode, every, now)` beside the old `model`, `label` and `request`, which are those at `Panel::mode`, so every call of the window keeps its meaning. Memory stays where it was for window-only use: `loaded` prunes a workspace's models to the window's mode, the one just read and the ones some stream follows (`Panel::follow`, which also drops the `requested` entry of a pair no stream wants, so a late answer for it is ignored). One worker slot still serves everything: the window's own request first, then the followed pairs, least recently asked first (`request_followed`, so a slow worker never starves the last pair), then, only when a stream wants Every project and the window does not show it, a counts-only sweep (`request_sweep(.., expand: false)`, which asks for no patches and does not read the window's folds or filter, since `folded()` with the Project scope would expand every file). No stream means no request beyond today's.
- **Demo regression coverage**: website checks run the simulation on its virtual clock in wide and compact layouts, exercising the full scope-tab label, header indentation, action focus and the hero tour. The existing esbuild version is a direct development dependency for bundling those tests with the same image imports as the demo, keeping the checks independent of a browser and wall-clock timers.
- **Discard (#421)**: hovering a file row shows `↺` left of `✓` in Uncommitted and Every project (`view.mode == Uncommitted`, which Every sets); Commits and All have no slot, no glyph and no hit, because their changes are already in commits. The 3-cell slot is reserved whenever discard applies, like `✓`'s, so the tags never jump on hover, and they sit three cells further left for good. `↺` has East Asian width N (narrow, not an emoji); the site's JetBrains Mono subsets lack it, so `site/src/lib/term/glyphs.ts` draws it as a shape. A `Confirm` with `dangerous` (red submit) names the file; the texts differ for modified or deleted, added (it is deleted), untracked (`Delete …`) and renamed (old name comes back), and live in `changes/discard.rs`, shared with the CLI.
  - **The job** runs on a thread, logged at info like worktree removal, since it is deliberate and destructive. It resolves HEAD first (`git::head`: the sha, or the empty tree on an unborn branch), then looks the file up among git's own listing (summary loader, no patch, so no highlighting is paid for a file about to go) and compares its review digest with the one the person saw: not listed is `Gone`, a different digest is `Changed`, and nothing is touched in either case. Only `file.path` and `file.old_path` from git's listing reach git or the disk, never the request's path (a `../` path would restore a file outside the workspace). HEAD comes first so that if it moves between the two, the lookup's digest (which hashes HEAD) differs and the discard is refused, and if it moves after, `restore` still uses the commit that was compared.
  - **How**: an untracked file (a symlink included: only the link goes) is unlinked, and folders it leaves empty stay; everything else is `git --literal-pathspecs restore --source=<sha> --staged --worktree -- <path> [<old path>]`. `--literal-pathspecs` because `star*.txt` would otherwise restore `starA.txt` too; `--source` with a sha because `HEAD` does not resolve on an unborn branch; both paths of a rename because one alone makes git see an added file. A file added in a new folder takes the folder with it, as `restore` does. Submodules: `restore` does not recurse, so a submodule's row stays, on purpose: it never touches another repository.
  - **Limits**: the digest is the review identity, which is metadata (size, mtime, ctime), so a same-size write inside a coarse filesystem's timestamp resolution could be missed; the check and the git command are a few milliseconds apart and git has no compare-and-restore. `restore` takes `index.lock` even with `--worktree` alone; its message goes in the toast and nothing retries. Afterwards the file's viewed mark, folds and gaps are forgotten and the workspace's request pacing is dropped (`Panel::discarded`), so the next refresh rescans at once and the row goes when that answers; nobody edits the model by hand.
  - **Rejected**: an undo (the two mistakes it would catch are covered by the confirmation naming the file and by the digest check; a faithful one needs the index entry and the worktree file for both paths of a rename, somewhere to keep the content (loose objects outlive the toast until `git gc`, a copy grows with every discard) and its own changed-since check, and the socket would need a `changes-restore` with a token; if it is asked for later, keep the content under a ref such as `refs/cornercase/discarded/…`), and a busy note in the dialog. **Left for later**: discarding one hunk, and a whole workspace from its Every project header.
