# Test helpers

Code: `test_util.rs`, `test_util/program.rs`, `agents/{claude,codex,gemini,opencode,grok,cursor,copilot,vibe}/fake.rs`, `app/tests.rs`

- **A test that runs the binary without `CORNERCASE_SOCKET` isolates everything the default socket depends on** (#355): it sets `HOME`, `XDG_STATE_HOME`, `XDG_CONFIG_HOME`, `XDG_RUNTIME_DIR` and `TMPDIR` to temporary folders and never removes one. Removing `XDG_RUNTIME_DIR` makes the earlier-socket probe guess `/run/user/<uid>`, and an unset `HOME` makes the default socket the developer's real one, which in a cornercase pane is the server the agent runs in (`tests/e2e/socket.rs::Home`).
- **No test reads a real agent home**: `new_app` points the default homes (`App::set_default_homes`) at a folder that does not exist (`cornercase-test-no-default-homes` in the temp dir), so `App::default_home` gives `<root>/<agent>` and a new account links nothing from the developer's `~/.claude`; `App::set_default_homes` (`cfg(test)`) points it at a `TempDir` for the test that checks the links. In production it is `None` and the server's environment decides (`accounts::default_home`). Accounts live under the test's session (`set_accounts_dir`), and the e2e tests give the server a `CLAUDE_CONFIG_DIR` inside the session folder. Paths are compared canonical, since macOS' temp dir is behind a symlink and accounts are canonical.
- App tests share event draining, drawing, config writing and mouse geometry at the top of `app::tests`, so those helpers can move together when the test modules move into their own files. `drain_in` takes an explicit area; each caller keeps whether it refreshes before or after draining. `render_frame` clones the completed frame's buffer, since cells marked to skip a backend diff never reach `TestBackend` and the image tests inspect those cells.
- `FakeCodex` appends the turn fixtures to its rollout and its script sets the title it finds in a `title` signal file (OSC 0). `FakeOpencode` is a script named `opencode` that holds a database built from the fixture schema, whose rows the test writes. `FakeGemini` writes a session JSONL under a temporary `GEMINI_CLI_HOME` and sets OSC 0 titles from a signal file.
- `agents::cursor::fake::FakeCursor` builds a chat store (the SQLite blobs and meta row, with a test-only protobuf encoder and `sha2`) and a transcript under temporary config and data folders, and a script named `cursor-agent` that holds the store open (`exec 3<`, so `open_files` sees it, as for opencode) and sets OSC 0 titles from a signal file; its helpers write turns, replies, thinking and tool steps, the context, the model and the turn endings. No test runs the real Cursor or reads the real `~/.cursor`.
- `agents::copilot::fake::FakeCopilot` is a `/bin/sh` script named `copilot` with the home, the signal folder and the default session id baked in (it re-`exec`s itself with `COPILOT_HOME` when the variable is unset or empty, so a resume line that passes no environment still reaches the fake's home, and a developer's own `COPILOT_HOME` never does): it holds `inuse.$$.hold` on fd 3 and writes `inuse.$$.lock`, takes the lock only after a `prompted` signal when started with `--resume=<id>` (as the real one does, live), and moves to a new session on a `clear` signal. The presence file and the events are written from Rust (`working`, `prompt`, `queued`, `reply`, `usage`, `permission`, `ask`, `shell_started`…), and `loader()` builds an `npm-loader.js` that runs the fake as a child, for the family walk. Tests use `FakeCopilot::spawn`, which removes `COPILOT_HOME` from the child's environment.
- `agents::vibe::fake::FakeVibe` writes a unified session store under a temporary `VIBE_HOME` from Rust (`meta.json`, `CURRENT`, one generation's projection, runtime and checkpoint files, the journal, a lease); app tests point the runtime at it with `set_vibe_dir`. The process is a `/bin/sh` script named `vibe-rs` that writes its lease with its own pid and sleeps until the pane's hangup ends it, and status is fed as Vibe's own OSC 7501 reports, since Vibe has no status reader.
- **Every fake's loop also ends once its signal folder is gone** (`while [ -d "$dir" ] && [ ! -e "$dir/quit" ]`), not only on `quit`: `Drop` writes `quit` and the `TempDir` removes the folder right after, well inside the fake's 20 ms poll, so a fake waiting for `quit` alone misses it and outlives its test for good, reparented to `init`. The Copilot fake did, and each one left behind forked `mv` and `sleep` about 50 times a second; a few dozen runs of the suite added up to a thousand processes a second and took a machine's CPU.
- Each agent's `fake.rs` owns its fake: `agents::claude::fake::FakeClaude` owns the temporary config and script folders for both status and command tests. Generic helpers (`TempDir`, `Sleeper`, `Running`, executable writing, append and title signals) stay in `test_util` because several agents share them. Its four scripts keep their original bytes. Starting it stays in an app test trait, since calling `agents.set_claude_dir` and typing into a pane need the app's private state. The command harness keeps `app` first so its panes stop before the fake's folders are dropped. Probe, issue-launch and integration scripts stay with their tests because they serve different protocols.
- `test_util::fixture!` resolves from `CARGO_MANIFEST_DIR`, so moving a test one folder deeper cannot change what fixture it reads. The saved-session and config fixtures pin both the loaded structs and the exact serialized text, including omitted defaults and enum names. A format change updates them together; an older session fixture stays as a migration test when the version changes. The restore round trip uses canonical folders, waits for every shell's live cwd and covers each side panel separately, since `App::state()` reads live panes and only one panel can be open. Fixtures use synthetic paths and accounts and restore tests launch no agent.
- **`cat -v` and UTF-8**: GNU `cat -v` prints a byte above 127 as `M-`, but macOS' `cat -v` prints a valid UTF-8 character as it is in a UTF-8 locale (CI's macOS runner), so a test that reads a fake program's `cat -v` output for typed non-ASCII text accepts both forms of the same bytes (`app/tests/plugin_popup/external.rs`, `E_ACUTE_SHOWN`: `M-CM-)` or `é`, both `c3 a9`); either one proves the bytes the program read, which a bare `contains("llo")` would not.
- **A full pane** (#615): a test that needs a pane whose program reads nothing runs `stty -icanon -echo; sleep 30` before writing past `term::MAX_QUEUED`. In canonical mode the kernel takes and drops what does not fit in the line (see Terminals), so the writer never blocked and on a fast runner the 17 MiB drained within the 300 ms of quiet a `send --enter` waits for before its Enter. With canonical mode off the write blocks until the pane closes, on Linux and macOS alike.
- **`test_util::child_running(parent, program)`** (#615) waits until a child of `parent` has become `program` and gives its pid: right after `fork` the child is still a copy of its shell (`bash` on macOS), so a test that reads its name, or stops it and reads the name back, saw the shell.
- **A server test whose connection holds a view reads its answers past the view's snapshots** (#615): the `view` stream sends a snapshot whenever the status it carries changes, and a pane whose shell is still starting changes it within the step that opened the view (its program goes from the forked test binary to `sh`, and on macOS on to `bash`). A snapshot sent right after an answer can reach the test after `ask` took that answer, so the next `ask` took it, or the answer it pushed back, for its own: `using_the_window_takes_back_the_tab_a_view_sizes` read the controller from before the key. `server::surfaces::tests::reply` waits for the line without a `revision`, which only stream lines carry.
- **`context::Pane::claude_in(home, id)`** (#664): a pane's reader that knows a Claude Code conversation, from a session file and a transcript written in `home`, with no process behind it, for a test of what a pane says that runs on every OS (the app tests' `FakeClaude` is a `/bin/sh` script).
- **`test_util::Checkouts`** (#252): a `git_repo` with linked worktrees added by `add(branch, from)`, each in its own `TempDir` that lives as long as the value does. The overlap scan, the merge check and their app and request tests need two checkouts of one repository, and building them by hand in each test was the same ten lines.
- **`test_util::NPM_SHIM` and `npm_install`** (#632): the `claude.cmd` npm 10.9.9 wrote for Claude Code's `cli.js`, byte for byte (`\r\n` line ends and all; checked against a shim its `cmd-shim` 7.0.0 wrote), kept as a string rather than a fixture file so that no checkout can change its line ends; `npm_install` writes a shim and empty files at the given paths into a folder. The shim's reader and the launch line's tests share them.
- **`FakeClaude::PROBE`** (#585): a `sh` script for `agent_commands.claude` that stands in for the second `claude` of the context probe. It appends `"$*"|$PWD|$CLAUDE_CONFIG_DIR` to `$0.args`, answers `initialize` and `mcp_status` and prints `$0.answer` (a fixture of `tests/fixtures/claude/2.1.316/`) for `get_context_usage`, exits at once when `$0.fail` exists, and touches `$0.done` when its input closes. The pane's own fake and the probe share the command, so the tests put a wrapper named `claude` in front that runs the probe for `-p` and the pane's script otherwise (`app::tests::control_requests::context_read`).
- **Fakes on Windows: one compiled program** (#601): `test_util::fake_program(dir, name)` puts a small Rust program (`test_util/program.rs`, std only) in `dir` as `name` (`name.exe` on Windows). It reads what to do from files beside it, named after itself: it appends its arguments to `<name>.args` (joined by spaces) and to `<name>.argv` (as Rust's `{:?}` of the list, one call per line, so a test sees where each argument ends), prints `<name>.out` and `<name>.err`, waits while `<name>.hold` exists and exits with the number in `<name>.code` (0 without one). It is built once per test run with `rustc` (the rustup proxy on the `PATH`, which runs the pinned toolchain), beside the test binary (`target/debug/deps/`) under a name with the hash of its source, so later runs reuse it (about 0.3 s to build, 200 KB) and a changed source builds anew. Not in the temp folder: on a shared Unix machine `/tmp` is everyone's, and a file planted there under that predictable name would have run as the developer; `target/` is the tree's own and the user's. It is compiled in a folder of its own beside it and renamed into place, so two test runs of one tree never see half a file. Each fake is a hard link to it, or, where the test's folder is on another volume (`/tmp` on a tmpfs, `%TEMP%` on another drive than the checkout, as on GitHub's Windows runners), a copy made by `cp` on Unix, so no test process writes an executable it then starts (`ETXTBSY`). It works the same on every OS and its tests run everywhere (`test_util::tests` as a process: found on a `PATH` by its name, shown under its own name while held; `test_util::program::tests` for the logic in-process, which also keeps the file linted). Why a program rather than a script: Windows starts by itself only an `.exe`, and std's `PATH` lookup finds only `name.exe`; a `.cmd` runs as `cmd.exe`, so agent detection, which reads the process's own name, never sees it, and a `.ps1` needs PowerShell and its execution policy. Rejected: the test binary started again as the fake (libtest reads the fake's arguments as its own), and a `[[bin]]` or an example (`cargo test --lib` builds neither, `CARGO_BIN_EXE_*` reaches only integration tests, and both add a target to the package). The `#!/bin/sh` fakes (`fake_gh`, `fake_glab`, the agents', the probes', `fake_ssh`) and the tests that use them stay Unix-only for now: each porting step moves its own fakes to `fake_program`, adding a file beside it for what it needs, when it moves its tests back to every OS.
- **`write_executable` on Windows** writes the file as it is, since a file has no mode there: what runs it is its extension (a `.cmd` for a `PATHEXT` lookup) or the interpreter a test names (Git's `sh`, see Windows). On Unix it still writes through a `/bin/sh` child, against `ETXTBSY`. `a_written_executable_runs` runs both forms.
- **`test_util::sign_head_and_show_signatures(dir)`** (#671) gives `HEAD` a signature header by writing the commit object by hand, turns on `log.showSignature` and makes `git` itself the checker (`gpg.program`), so `git log` prints lines before its format on any system. Nothing here may run the real `gpg`: it needs no key to fail, but it creates `~/.gnupg` in the real home. A checker that cannot start is no stand-in, since git then prints no signature lines.
- **`test_util::link_folder(target, link)`** (#671) is a link to a folder on any system: a symbolic link on Unix, a junction on Windows, which needs no privilege where a symbolic link needs Developer Mode or an administrator. `canonicalize` follows both and `symlink_metadata` says `is_symlink` for both, so a test of what a link leads to runs on the three.
- **`test_util::os_path("/srv/a")`** is that absolute path in this system's form (`C:/srv/a` on Windows, the same on Unix), for tests of platform-neutral logic that take an absolute path literal (`config`'s worktree folder, `cli::config`, `cli::flow`, `project::vscode`, `settings`). A path a test compares with what the code builds from parts is built with `Path::join`, so its separators are the system's (`files::link`, `files::search`).
- **`FakeHttp` logs a request before it answers it** (#601), so a test that saw the app act on an answer always finds the request in `requests()`. Logging after the write let the app read the answer, and the test count the requests, before the server's thread had logged it. A test that counts requests waits for what the app shows after it read the answer, never for something it shows before (see Windows, Tests on Windows).
- **`fake_program` records its folder** (#656): beside `.args` and `.argv` it appends the current folder to `<name>.cwd`, so a test can check where an agent ran. The recap's agents are faked with it (`claude` and `codex` with the canned stream of a real run in `.out`), the same on every OS.
- **`test_util::http_get(port, path)`** (#669): a plain `GET` on loopback that reads the answer to its end, for the tests that take or refuse a pairing code on `Web`'s port (`app::tests::remote_access`, `app::tests::control_requests::pair`), on every OS. The e2e crate has its own in `tests/e2e/browser.rs`, since `test_util` is the library's.
