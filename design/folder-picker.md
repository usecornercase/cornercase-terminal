# Folder picker

Code: `project/picker.rs`, `list.rs`, `app/picker_dialog.rs`, `app/control/create.rs` (`open` on a `.code-workspace`)

- Starts in the parent of the active project (of the group's first project for **add project**). `Enter` goes into the selected folder (or imports the selected `.code-workspace`), or opens the current one when nothing is selected. Typing a path walks it; a paste goes through the same path (e2e opens projects this way). Folders are read on the main thread.
- **Typing a path on Windows** (`Picker::push`): a separator is whatever `std::path::is_separator` takes, so `\` and `/` both go into the selected folder there, and `/` alone on Unix, as before. With the filter empty a separator goes to the root of the current folder (`root`, the last of its ancestors), where Unix goes to `/`: its drive's (`C:\`), or, in a folder on a share (a project opened there), that share's (`\\server\share\`); a filter that is a drive (`d:`) and then a separator goes to that drive's root (`D:\`). So a typed or pasted `C:\Users\ana\code\web` walks as `/home/ana/code/web` does. The picker never reaches a share the user did not open: a share's root is on the share the picker already lists, which `..` and Backspace climb to anyway, so no other host or share is asked; and a typed or pasted `\\server` goes to the current root twice (a separator there stays) and then filters for a folder named `server`, so typed text never becomes a share. Rejected for a folder on a share: a drive's root (the picker has no current drive there, and the home drive would leave the user's folder for an unrelated place) and doing nothing (a key that silently does nothing).
- **One import, two callers** (#673): choosing a `.code-workspace` here and `cornercase open FILE` decide with the same `vscode::is_workspace` (the name's extension, and a file, on the path as it was given, so a folder named `x.code-workspace` stays a folder) and run the same `App::import_workspace`, so the rules of Hierarchy › VS Code workspaces cannot drift. It only opens folders and fills the group: it takes each project from `open_folder` and touches neither the shown project nor the toast. What the window adds is in `show_imported`, which the picker alone calls: the first project shown, leaving a machine's tab, the group unfolded and the toast, whose text is `ImportedWorkspace::message`. See Commands for scripts and agents › Opening a VS Code workspace.
