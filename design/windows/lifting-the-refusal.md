- **On Windows, cornercase said so** (#588 until the refusal went): while the port went step by step, `cli::run` refused every command with `Error::NotOnWindows` (cornercase does not run on Windows yet, with a link to #586) and exit status 1, before anything reached the server, the socket or the console; `--help` and `--version` worked, since clap answers them before `run`. One check in one place rather than one per command, so nothing half-worked over the socket. It went, with the error, once the socket, the server's process, the console, the panes, processes, ports, scripts and agents were ported (#591 to #599) and an audit found no stub left that fails open (see Lifting the refusal).
- **Lifting the refusal** (#586): `cli::run` runs every command on Windows, and `Error::NotOnWindows` is gone. Before that, every stub, `Unsupported` and `cfg(not(unix))` fallback a command or the window reaches was audited.
  - **Fixed, since they failed open or misbehaved**: random bytes came from `/dev/urandom`, which on Windows is `\dev\urandom` on the current drive, a folder any signed-in user may make at a drive's root, so browser pairing tokens and secrets and the chat bots' pairing codes could have come from another user's file: `os::random` asks `BCryptGenRandom` (the system's preferred generator) there, Unix keeps `/dev/urandom`. `plugins::manifest::platform` said `linux`, so a plugin for `linux` only loaded: it says `windows`. The painter's wait (`highlight/limit.rs`) was the stub of What the stubs answer: every highlight started a worker and killed it at once, for each hunk of the changes panel, with no colours; an anonymous pipe has no overlapped I/O to wait on, so it peeks the pipe every millisecond (`PeekNamedPipe`) until data, an error (the worker ended: broken) or its deadline (a timeout, as on Unix). `HOME` read as is (status's and worktrees' `~`, a plugin spec's `~`, a plugin action's folder without a project, a sound file's `~/`) is `paths::HOME_VAR` now, `USERPROFILE` there; git's user name looks for `.gitconfig` where Git for Windows does (`git::git_home`: `HOME`, else `HOMEDRIVE` and `HOMEPATH` when that folder exists, else `USERPROFILE`; Unix still reads `HOME` alone). A sound file given as `C:\…` was refused by the setting's check (only `/` and `~/`): a drive path is taken (see Network paths). The socket's advice (too long, cannot listen) named `XDG_STATE_HOME`, which Windows does not read: it names `paths::STATE_VAR`.
  - **Harmless, left**: streams (`watch`, `events`, `logs --follow`, `--follow` lists) and `wait` notice a reader that went away only when a write fails (`client/requests/watch.rs`), and `restart --when-idle`'s tied input is for `cornercase remote` (#603); `console::BorrowedFd::try_clone_to_owned` stays `Unsupported`, reached only after `watched`, which answers `None`; the server ignores `setsid`'s `Unsupported` (its hidden console stands for a session); `paths::earlier_sockets` is empty; a plugin's clone sets `core.hooksPath=/dev/null`, which Git for Windows reads as `nul` (`git rev-parse --git-path hooks/post-checkout` gives `nul/post-checkout`, 2.39.2) and never checks out, so no hook runs, and `git hash-object -t tree /dev/null` is read the same way; the queue reads `/etc/timezone` only when jiff names no zone, which it does from Windows' own; a `.code-workspace` folder given as a `file://` URI (`/c:/…`) names no folder, failing closed (`plugin install` took a local folder only as `/…` until #642); the logs help and the flow help's examples name Unix folders, and `status` shows `~/` before a Windows path.
