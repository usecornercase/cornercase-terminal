# Windows › Network paths

Part of [Windows](../windows.md).

- **Network paths** (`os::fs::reaches_network`, `drive_path`): on Windows opening a UNC path (`\\host\share\…`, `//host/share/…`) makes an SMB connection, and Windows answers that host with the user's NTLM credentials (the pattern of CVE-2023-23397, an Outlook reminder sound on a share), so a path that came from someone else and would be opened without the user choosing it is refused before anything touches it. `reaches_network` is any path that starts with two slashes of either kind (UNC, `\\?\UNC\…`, `\\.\…` and `\\?\Volume{…}\…` devices, `//?/…`) but a verbatim drive (`\\?\C:\…`); it is false on Unix, where nothing changes. A mapped drive letter of a share is taken: its host is the user's own mapping. Checked, every user-supplied or shareable path:
  - **Sound files** (shared settings, Settings, `config.json`): the setting's check, which an import also runs, takes only a drive path (`C:\…`, `C:/…`, `\\?\C:\…`) or `~/…` there, and `host::sound::resolve` plays nothing else, so a value written by hand or by an older build is not opened either.
  - **Shared settings**: the import refuses `gh`, `glab` and an agent command whose program reaches the network, since they run without a click (pull request checks, usage probes); the preview never looks a network path up (worktrees folder, sound files, programs) and names it as a risk. `worktrees_dir` is still taken: nothing reaches it until a worktree is made or the Worktrees dialog opens.
  - **Path links in a pane**: hovering resolves a link, so one that reaches the network (`//host/share/x.rs`, or `\\host\share\x.rs` now that a backslash is part of a path there) in a program's output is no link.
  - **Plugin folders**: `plugin install` refuses a folder on the network, or one on a drive that leads there through a symbolic link (`os::fs::network_link`, which reads each link without following it), before its CLI canonicalises it and before git clones it (see Plugins, Installing); `plugin link` is left as it is.
  - **`.code-workspace` folders** that reach the network are skipped, as `file://server/share` URIs already were; opening one would open projects the user did not name.
  - **Left as they are**, since the user names the path: a project, the folder picker, `plugin link`, a file opened in the panel, Settings' worktrees folder, `gh`, `glab` and agent commands written into `config.json` by hand, and the `PATH`. The editor (`VISUAL`, `EDITOR`), images and plugin programs come from the user's environment or from inside a folder already checked.
  - **The remote hosts' code** (audited when this note met the branch of #539, 2026-11-04): nothing a machine sends is opened here. A machine's workspace paths are only copied as text (its row's menu offers **copy path** alone), its files, diffs and images come over the stream as bytes, a notice from its agents plays this computer's own sound setting, and a link skips `Open`, `Browse` and `Sound` (see Remote windows › Machines' links). A `clone` request's `url` and `parent` are named by the user, as `open`'s path is. It reads no `HOME` (its `~` is `App::home`, from `paths::HOME_VAR`), makes no random bytes, names no platform and passes ssh no control socket. A gap, left: the wake check (`machines/wake.rs`) compares the wall clock with `Instant`, and on Windows `Instant` is `QueryPerformanceCounter`, which keeps counting through sleep, so a wake is never seen there; each link finds its dropped connection by ssh's keep-alives (about 15 s) and reconnects as after any drop. Counting the sleep there (`QueryUnbiasedInterruptTime`) is left for later. The clone's names also read `\` as a folder separator there and take a drive or a share (`C:\…`, `\\host\…`) as a local path (`git::clone::folder_name`, `is_local_path`).
