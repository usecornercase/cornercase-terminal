# Windows › Program names and the coding agents

Part of [Windows](../windows.md).

- **Names without `.exe`**: Windows names a process `node.exe` and a command line starts with `C:\…\claude.exe`, while every comparison (`process::is_shell`, `agents::detect`, `term::program`'s interpreters) holds Unix names. `process::program_name` drops a last `.exe` in any case, on Windows only: the Windows `imp`'s `name` goes through it, and so does `agents::detect` for each argument and for the configured command, so `claude.exe` is `claude` and `node.exe` is the `node` interpreter, whose script argument then reaches the agents' `runs_as`. `agents::detect` then compares the names in any case on Windows (`process::same_file_name`, Unicode lowercase), whose file names ignore case, so `CLAUDE.EXE` is Claude Code too, and so do the agents' `runs_as` rules for each path component they look at (`agents::named`: Copilot's `@github\copilot\npm-loader.js`, Cursor's `cursor-agent\versions\…\index.js`, and the npm scripts of #599 below; `agents::is_program`, a name without its `.exe`, for Vibe's `vibe-rs` and Codex's `codex`). The Unix side is untouched (`program_name` returns the name as it is and `same_file_name` compares exactly), so a Linux program really named `foo.exe` keeps its name. `cmd` and `powershell` are shells on Windows only; `is_shell` compares through `program_name` and `same_file_name` (#594), so `pwsh.exe` and `BASH.EXE` are shells there (`pwsh`, `nu`, `bash` and `sh` were already in the list every system shares). An agent installed with npm runs as `node.exe` with its package's script (`…\npm\node_modules\@anthropic-ai\claude-code\cli.js`) rather than a `claude` link, so it is seen only where its `runs_as` knows that path (see The coding agents).
- **The coding agents** (#599, `paths::HOME_VAR`, `process/program.rs`, `agents::typed_line`, `agents::context::discovery::npm_script`): their default folders come from `USERPROFILE`, never `HOME`; a program cornercase starts itself (a usage probe, a login check, Claude Code's context breakdown) or looks for (`agents::installed`) is found through `PATHEXT`, the openers' lookup moved to `process::program` and shared, so npm's `.cmd` shims are found and started through `cmd`; a launch is typed with PowerShell's quoting (with the Unix one in a Git Bash pane), and in a PowerShell pane refused when a word is `--%` or holds `"`, or whitespace and a last `\`, which Windows PowerShell 5.1 would pass on to the agent in pieces (a Git Bash pane passes them whole, a `cmd.exe` pane is refused any character `cmd.exe` reads and any word with a space, and a pane of any other shell (`nu`, `fish`, chosen with the `shell` setting, #712) any word that is not made of letters, digits and `-_./:+=,@`, since cornercase cannot quote for it, and fish reads a backslash as an escape); when PowerShell would run a `.cmd` or `.bat`, the shim npm wrote is read and passed over, so the line starts `node` and the package's script with the words, which never reach `cmd.exe` (#632), and any other batch file is refused a line with a character `cmd.exe` reads (pnpm's shims and older npm ones among them); and the script an npm shim runs with `node.exe` names its agent. So no step of Claude Code's, Gemini CLI's, Grok's or Vibe's is Unix-only any more (none was run live), while Codex, Copilot, Cursor and opencode find their records through the files their process holds open (#618). The sources, the checks and the limits are under Agents (On Windows).
- **The files a process holds open** (#618, `process/handles.rs`): `process::open_files`, how Codex, Copilot, Cursor and opencode find their records, reads the process's own handle table on Windows, naming each file on a worker thread with a timeout, since a name can hang on a handle another thread is reading (topic: The files a process holds open).
- **Bots** (#844): a Codex bot is `full` only on Windows, since its sandbox was not tried there (`why: its sandbox is not known to reach cornercase on this system`). A Claude bot builds the rule path of its folder as `//c/Users/u/…` (`rule_path`), the form Claude Code's documentation gives and **not checked on Windows**; `PATH` is built with `std::env::join_paths` from the folder of the server's own binary (`cornercase.exe`), and the 0700/0600 modes are Unix only (`os::fs`). Not checked live.
