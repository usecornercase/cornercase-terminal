# Keeping awake

Code: `agents/awake.rs`, `app/agent_watch.rs`

- **`keep_awake`** (`config.json`, Settings → Agents, off by default; #160): while at least one agent works, the server holds the system's lock against idle sleep, and lets it go once none has worked for `agents::awake::KEEP_FOR` (30 s), so agents that end and start turns back to back do not take and drop it every few seconds. An agent left working used to stop with the machine: its process froze, its API call or build timed out, and the way around it was `caffeinate` or `systemd-inhibit` by hand. Off by default: it costs battery, and an update should not change how a laptop sleeps. Claude Code already keeps a Mac awake while it works (it runs `caffeinate -i -t 300` itself while it works; seen on 2.1.296), so the setting matters for Codex, opencode and Gemini CLI, which do not, and on Linux; it is kept for every agent rather than per agent, since one rule is easier to explain and the two locks do not conflict.
- **What counts as working** (`App::keep_awake`, after `watch_agents` on every refresh): `Status::Working` without a background shell, the same rule as `--until turn-over` and `restart --when-idle`, so a dev server an agent left running does not keep the machine up all night. Waiting does not count (the agent has no request in flight); agents cornercase cannot read never hold it; opencode never reports waiting, so one at a permission prompt holds it until it is answered. An agent waiting on subagents it started counts as working (#358), unlike a background shell: it wakes up for their results.
- **In the app feed** (#338): `keep_awake` is in `status --app` too, built by the function `status` uses.
- **Only idle sleep is blocked**: the display still turns off, the screen still locks, and sleep chosen on purpose (the menu, the lid) still happens. Keeping a Mac awake with its lid closed needs root (`pmset disablesleep`) or clamshell mode and stays out. It is the server's machine that stays awake; with `cornercase remote` the laptop showing the window may still sleep and reconnects when it wakes.
- **How**: no crate and no `unsafe`: the server spawns the system's own tool (`agents::awake::tools`) and kills it to let go. macOS: `caffeinate -i -w <server pid>` (a `PreventUserIdleSystemSleep` assertion, also on battery; `-w` ends it with the server). Linux: `gnome-session-inhibit --inhibit suspend … cat` first when the session bus is reachable, since gnome-settings-daemon only reads gnome-session's own inhibitors, never logind's locks; then `systemd-inhibit --what=sleep:idle --mode=block … cat`, then `--what=idle`, which polkit allows from an SSH session where it refuses the `sleep` block lock, and which still holds back logind's `IdleAction`. The tool's stdin is a pipe the server holds, so when the server dies, even from `SIGKILL`, `cat` reads its end and exits and the lock goes with it.
- **Failures**: a tool that cannot start (`not installed`) or exits while it is wanted (a refusal: polkit, no gnome-session) gives way to the next one, its last stderr line kept as the reason; when none is left the lock is unavailable until the setting is turned off and on again (or the server restarts), with one `WARN` in the log, so a machine that cannot hold it does not retry and log every turn. After a normal release the next take starts from the tool that worked. The settings row's note says whether the lock is held and by which tool, or why it cannot be taken (`agents::awake::State::note`); `status --json` has `keep_awake` (`held`, `by`, `unavailable`) while the setting is on; `server.log` says when it is taken (with how many agents work) and released.
- **Rejected**: IOKit (`IOPMAssertionCreateWithName`) would name `cornercase` in `pmset -g assertions` instead of `caffeinate`, at the cost of CoreFoundation FFI; `caffeinate` is enough. Insomnia (a macOS menu bar app) was looked at as an alternative: it keeps a Mac awake with its lid closed through a `sudoers` rule for `pmset` and stops other apps with `SIGSTOP`, which is more than a terminal should ask of its users, and it is a Swift app, not a library. Holding the lock only on power (`caffeinate -s`, `/sys/class/power_supply`) and a mark in the window while it is held were left for later: the settings row, `status` and the log say it.
- Not checked live: GNOME, KDE Plasma (whether PowerDevil honours logind's lock; if not, `org.freedesktop.PowerManagement.Inhibit`), and a server started over SSH. Tests use fake tools: scripts that record their arguments and `exec cat`, or refuse like polkit (`agents::awake::tests`), and the fake Claude Code working and finishing (`app::tests::control_requests::agents::keeping_awake`).
