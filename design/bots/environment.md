# Bots: the environment of a turn

Part of [Bots](../bots.md). What a turn's agent finds in its environment, and why.

## The environment of a turn

- **Working folder**: the bot's folder.
- **`CORNERCASE_BOT=<id>`** (`bots::BOT_ENV`). The command line reads it (see the guard), and so does the server, as a fallback to tell a bot's commands (The boundary).
- **`PATH`** is a folder of the server's own that holds only a link named `cornercase` (`cornercase.exe` on Windows) to the server's binary (`paths::bin`, `bin/` beside `session.json`, `x.bin/` for a private instance), then the server's `PATH` unchanged (#892). Only `cornercase` must come first, so it is the binary of the server that runs the bot (a dev build, Windows). The first version put the whole folder of the binary first; with Homebrew that is `/opt/homebrew/bin`, whose `gh` (not logged in) shadowed the user's own `~/bin/gh`, with no hint in the chat. The link is made by `os::fs::link_to` (`turn/link.rs`): a symbolic link on Unix, a hard link or else a copy (given the binary's write time) on Windows, to `own_binary()` as given, not canonical, so Homebrew's `bin/cornercase` outlives `brew upgrade`. The folder is made absolute when the server sets it (`App::set_bots_bin`, as the runs, pasted and setup folders are), since `CORNERCASE_SOCKET=x.sock` may be relative and the child runs in the bot's folder. It is checked before every turn (on the job thread, not the server loop) and made again when it no longer leads to the binary (another symlink target, another hard link, a copy of another length or write time), under a temporary name (`persist::temporary`) and renamed over the old one, so a concurrent turn never sees it missing. A server that runs from the link (macOS' `current_exe` names it, as when a bot's command starts a server) leaves it alone: no loop. If the link cannot be made (or no folder is set, in unit tests) the binary's folder goes first, as before, with a `bots` warning in the log. On Windows a stale hard link keeps an old binary's data on disk until the next turn links again, and renaming over a running `cornercase.exe` fails, which is that fallback. The folder lies outside every bot's folder: a `cornercase`-access bot writes in its own, and a replaced `cornercase` would run anything under `Bash(cornercase:*)`. Rejected: skipping the link when the user's first `cornercase` is already ours (the issue's smaller option; it fixes neither a dev build nor a shared folder that is not first, and one rule is simpler), a folder per turn (churn, left behind by a crash), the binary's folder last (the installed `cornercase` would win in a dev build). Not checked live: whether Claude Code's own shell snapshot rewrites `PATH`. Codex runs its commands through a login shell (`zsh -lc`), which re-prepends the user's own folders: its `cornercase` may be the installed one rather than this server's, another reason Codex stays `full` only.
- **`GIT_OPTIONAL_LOCKS=0`, `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=diff.autoRefreshIndex`, `GIT_CONFIG_VALUE_0=false`** (#893, `turn::QUIET_GIT`), on every turn, `full` included: a bot's `git status` and `git diff` in a project must not rewrite its index or take `index.lock` while an agent there commits (see The boundary › A project's git): `GIT_OPTIONAL_LOCKS=0` stops `status`, the config pair stops `diff`; both were checked with git 2.50.1, and `GIT_OPTIONAL_LOCKS=0` set on `claude` reached its Bash tool, where `git -C <repo> status` left the index's mtime alone. A `GIT_CONFIG_COUNT` the server inherited is replaced for the turn. The key stays index 0 because `headless::Env` takes `&'static str` names.
- **`CORNERCASE_SOCKET`** is set from `App::shells.pane_socket()` when there is one (a dev build), as Recap's `Ask::socket` is; otherwise the child inherits the server's environment, and a release server's binary finds the default socket. (The issue named `CORNERCASE_SERVER`, but that variable is the boot token that validates `CORNERCASE_PANE`, not the socket.) `CORNERCASE_PANE`, `CORNERCASE_SERVER` and `CORNERCASE_REMOTE` are removed: there is no pane.
- **A `cornercase`-access turn runs contained** (#856): on Linux the turn's root is a child subreaper, so what a command sends to the background and orphans is adopted by it; on Windows the root is in a Job object (`KILL_ON_JOB_CLOSE`, no breakaway). The server tells a bot's commands by this (The boundary), and what a contained turn started is stopped when it ends. A `full` turn, Recap and the usage probes are not contained.
- **Account**: as Recap's `Call::home` (the account's folder in the agent's environment variable, and the variables it lists removed), through `App::account_home`, which Recap now shares.
