# Hierarchy

Code: `project.rs`, `project/group.rs`, `project/hierarchy.rs`, `app/hierarchy.rs`, `app/tabs.rs`, `app/menus.rs`, `app/sidebar/drag.rs`

- Optional group > project (a canonicalized folder) > workspace (the project folder, or its own git worktree) > tab > panes. Every level has an id from one counter; menus, forms and background jobs refer to ids, never indices.
- **Lookups and project order belong to the model** (`project/hierarchy.rs`, re-exported from `project`): `Hierarchy` on `[Project]` finds projects, workspaces, tabs and panes by id and walks all children. Each level also has `index_of`, and a tab has `pane_by`, `pane_by_mut` and `layout_by_index`; `Project::label` owns the project label. A trait gives method syntax without wrapping the project's vector or changing indexed access: Rust allows no inherent impl on a slice. Calls on `self.projects` borrow that field alone, so callers can still write launches, the toast and host output. Trait methods avoid names of slice and vector methods, whose inherent methods would silently win. The module stays private because `app` already has a child named `hierarchy`. Lookups return positions for callers that then change `App`; those positions are used within the event, never stored in menus, dialogs or jobs. Lookups never filter closing projects or removing workspaces; each caller keeps its own eligibility checks. `workspace_in` and `tab_in` also check the named parent. `tab_index`, `tab_in` and `tab_of_pane` share one walk.
- **Plain references end lookup borrows when their last use ends**: an `if let` or `match` over an iterator's `find` can keep its opaque iterator temporary alive until the block ends, borrowing `projects` even after the pane's last use. That made copying a free function taking host writes and the toast separately. `pane_by_mut` returns an `Option<&mut Term>`, so the output handler can call `App::copy` once the pane is no longer used. New code uses these lookups instead of finding ids inline, including through the flat iterators. `split_pane` still looks its tab up twice: shared `tab_with_pane` reads the pane's folder before `spawn`, then `tab_with_pane_mut` inserts it afterwards. `spawn` borrows all of `App` for ids and sizing, so neither a reference into `projects` nor an unchecked position is carried across it. A spawner borrowing separate fields is a later change. `watch_agents` keeps nested loops because it needs visibility and ids from every level beside config and stats.
- Labels: custom name, else folder name (project), branch or `default` (workspace), foreground program (tab).
- **A split tab is named after its first pane** (`Tab::label`: the first leaf of `Tab::layout`, the top-left pane), not the active one, so the name stays put while the focus moves between panes; it followed the focus before (#40), and the row changed name on every click. Its row ends with a muted `+n`, the number of other panes (`TabEntry::others`), also for a custom name, fitted first like `↓n` (`Tags::fit`) so a long name is cut before it. Only the rows show it; search and the compact bar's breadcrumb keep the plain label. Model and context still follow the active pane (`Tab::context`), since they describe the agent you are looking at.
- **A tab's program** (`term::program`): a known agent (`agents::detect`) gives its kind; for an interpreter (`node`, `bun`, `deno`, `python`, `python3`, `ruby`) the whole argv is matched, for anything else only `argv[0]`, so `less claude` stays `less`. An interpreter whose first non-flag argument is a script (contains `/` or has a script extension, no whitespace, and no `-e`, `--eval`, `-p`, `--print`, `-c` or `-m` before it, so modules and inline code keep the interpreter's name) gives the script's stem: npm installs run `node /…/bin/codex`. Linux `comm` is the main thread's name, which recent Node renames to `node-MainThread`; that becomes `node`. Its PTY test runs a copy of `/bin/bash` named `node` (`comm` comes from the executed file; a symlink to dash would do on Linux, but macOS names the process after the target).
- Closing kills processes; removal waits for the shell to exit, never synchronous. A pane goes when its reader hits the PTY's end (`Exited`) or, on any `App::refresh`, when `Term::exited` finds the shell reaped (`try_wait`), whichever comes first. Both, because the PTY's end only comes once every process has closed the terminal: one that left the shell's session and ignores SIGHUP (`nvim --embed` outliving its UI, `nohup`, `setsid`) would keep the tab as `?` forever. Like tmux, the pane goes with the shell; the reader thread and the master's fd stay until that process exits. `Term::kill` skips a reaped shell, since portable-pty signals the pid unconditionally and it may have been reused. Closing a project asks first (`Overlay::CloseProject`), since it stops every shell in it, agents included; a tab or a plain workspace closes at once in wide mode and asks first in compact mode. Closing the last tab keeps the workspace; closing the last workspace keeps the project.
- **Groups**: one level, no nesting; a new one goes last. A project holds `group: Option<u64>`; the projects column is `ui::sidebar_rows` (loose projects first, then per group a gap, the header and, unless collapsed, its projects). `project::group_indices` maps missing groups to loose projects; `project::sidebar_order` gives the project order with every group open for the agents section, the Every project changes scope and project stepping. Tests keep that order equal to the project rows of the unfolded UI. Drawing, hit testing and `App::follow` share the UI row list. A collapsed group holding the active project gets the `▌` on its header. Deleting a group (the `×` on its header, or its menu) asks first (`Overlay::DeleteGroup`). A group holding projects asks what to do with them: **keep projects** (the submit, so `Enter` keeps the old behaviour and stops nothing) only ungroups them; **close projects** (`ui::Confirm::extra`, a grey button left of the submit, `FormHit::Extra`) closes each of them like `close_project`, then deletes the group once they are gone (`App::deleting_groups`: a closing project stays in its group until its shells exit, so it never jumps to the loose ones for a frame, nor shows as moved in the log; `View` and `sidebar_rows` take a `group` pointing at a deleted group as loose, so leaving the id dangling would not have helped; a project added or moved into the group meanwhile that is not closing makes it stop waiting as it enters (`App::cancel_pending_group_deletion`, on every way in: a drag, **move to group**, the picker), even when it closes before the others, so it is never deleted unasked), since emptying a group meant closing its projects one by one. The message says how many tabs that stops; folders and worktrees stay on disk. An empty group keeps the plain **delete**. The labels come from `App::dialog_labels`, live from the group's projects (closing ones left out), so drawing and hit testing agree. Icons are a fixed set of one-cell symbols (`project::group::GROUP_ICONS`, no emoji or Nerd Font glyphs, whose width varies); colours are palette indices (`project::group::GROUP_COLOURS`, no greys, black or white, which vanish on some themes). A new group takes the first of eight presets (`project::group::GROUP_STYLES`, chosen by `project::group::preset`) that no group has, the same icon and colour, else they repeat in order, and nothing opens: the icon and colour modal used to open after the name, a question asked at the moment one only wanted a group, and it is one click away in the group's menu (` ⋯ ` or right-click → **icon and colour**), whose clicks apply at once. The presets start with blue, the favourite colour in every one of the ten countries of YouGov's 2015 survey, then green, purple and red (the runners-up there), orange, yellow, pink and teal; each has its own shape, so groups differ without colour. Each is in `GROUP_ICONS` and `GROUP_COLOURS`, so the modal marks it.
- **Adding to a group**: the group's menu starts with **add project**, which opens the picker (`Overlay::Picker { group: Some(_) }`, titled ` add project `) in the folder above the group's first project; what it opens lands in the group (an already open project moves there) and the group expands. `+ new project` never guesses a group from the active project: a new project landing in a group you did not pick would surprise.
- **VS Code workspaces** (`project/vscode.rs`): the picker lists `*.code-workspace` files after the folders, tagged `vs code`, also while filtering (folders first, then the match rank), so a quick `Enter` on a filter goes into a folder rather than importing; choosing one imports it once, never linked (cornercase does not write the file nor watch it). The group is the file's stem, reused when a group has that name (re-importing brings in folders added since), else a new one with the next preset. Each folder opens as a project in it, in order, the first one active; a folder already open moves into the group; its `name` (only when it differs from the folder's name) becomes the project's custom name when the project has none: a new one, or an open one never renamed; a name given in cornercase is never overwritten. `path` is relative to the file's folder, `uri` is read only as a local `file://` path, `file:///…` or `file://localhost/…` (another host or scheme is skipped, never read as a relative path); missing folders are skipped and counted in the toast, and a new group left empty is removed. A folder whose shell cannot start (`open_into` fails) does not end the import, as in the restore: it is logged with its cause, counted apart from the missing ones (`n could not open, see server.log`, with the bug icon) and the next folder goes on. The toast counts distinct projects (a folder listed twice, `api` and `./api`, opens once and counts once) and says `nothing imported from <name>` when none opened, since the empty new group is gone by then. A UTF-8 byte order mark is skipped, and every read error, not only a JSON one, names the file. VS Code accepts comments and trailing commas, `serde_json` does not, so `strip_jsonc` removes both outside strings first, rather than adding a JSON5 crate. A file that cannot be read keeps the picker open with the error.
- Menus are one `Overlay::Menu { actions: Vec<MenuAction> }`, labels from `App::menu_label`; a submenu (move to group, **open in…**) replaces the menu at the same spot. `+ New` opens a menu (open project / new group); it was `+ new project`, which named only one of the two. The workspaces column's `+ New` (in every layout, and a project's `+ New` row in the tree) opens one too, for that project: **new workspace**, what `+ New workspace` did, and **start a flow…** (#263). A flow makes a workspace, so offered in the projects' `+ New` it read as if it made a project.
- **Reordering** (drag; the `move` request goes through the same `move_project`, `move_group`, `move_workspace` and `move_tab`, see Arranging the session): project, group, workspace and tab rows act on release. A press grabs the row (`Drag::Row` in `App::drag`, holding a `Target`); leaving the row's rect, or releasing outside it, makes it a drag, otherwise the release is the click (activate, collapse), so a cancelled drag changes nothing and the compact menu stays open while dragging. `×` and `+` still act on press. Releasing outside the list, `Esc` or another button cancels; no hover while dragging.
- Where it lands (`ui::sidebar_drop`, `ui::workspace_drop`) comes from the pointer and the layout without the line, so the line never feeds back: the row under the pointer gives its slot (before it when above the dragged row, after when below); a group with its projects and a workspace with its tabs are one block; a group header takes a project in first (last when collapsed); a gap is the end of the section above; tabs stay in their workspace, workspaces in their project (moving a shell or a worktree elsewhere was left out). The line goes on a neighbouring gap, on the line above or below the visible rows at an edge, else as an inserted one-line `Landing` row; it is indented where a grouped project or a tab would start.
- Holding a drag on `↑ n more` / `↓ n more` scrolls one item every `AUTO_SCROLL_EVERY` (150 ms); `App::tick` shortens the server's wait meanwhile. Moving only changes `Vec` positions (`project::move_before` keeps the active index on its item), so ids, menus and jobs are unaffected and the session saves the order as is; worktrees found outside cornercase go last.
