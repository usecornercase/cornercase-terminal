# Each workspace's changes against its base (#716)

A git workspace's row ends with `+640 −9`, and `status`, `watch` and `view` carry `against_base`.

- **What is counted**: the Changes panel's All mode as a counts-only read (`changes::summary::compared`, with `expanded: Some(vec![])`): `diff --numstat` and `--name-status` from the merge base with the workspace's base, plus the untracked files' lines, with the same caps. No patch is built. `Loaded.base` names the base (`origin/main`, or the one chosen). On a project's own checkout `default_base` gives `origin/HEAD`, so it counts the uncommitted files and the commits not pushed; without `origin/HEAD` a local `main` or `master` is the base and only uncommitted changes count. With no base (no default branch, no merge base, an unborn branch) nothing is drawn or reported.
- **What draws the rows** (`App::drawn_workspaces`): a visible view draws every workspace; otherwise an attached window draws the active project's (side by side, stacked, compact) or the open projects' (tree); with neither, nothing runs. A hidden view draws nothing, so a minimised GUI does not run git every few seconds. `watch` alone does not count as drawing.
- **Pacing** (`changes/tally.rs`): its own one-job slot, apart from the panel's, because a read can last up to `GIVE_UP_AFTER` and must not freeze the open panel. One workspace at a time; each at most every `CLOSED_EVERY`, or ten times its last read's duration (`SHARE`) if longer. The next is the one with a working agent, then the least recently asked. Workspaces sharing a folder and base (plain workspaces) are read once. An unchanged digest keeps the count, a timeout keeps it, another error drops it. A count held for another base is neither given nor drawn and its workspace is due at once; a discard or stage drops its pacing; closing or removing forgets the count and ignores the answer in flight.
- **On the wire**: `against_base` is present only while its workspace is drawn and a count is held for its base, so it is never stale; `files: 0` means counted and clean. It is skipped when absent, so the fixtures stay byte for byte. Feature `against-base`. `status` needs no hash for it: answers and draw changes are traced events. A view's lines also carry `changes` (Uncommitted) for the workspace each visible view shows, kept current by the counts-only sweep, unless the window's target or a stream already covers it.
- **The row**: the last tag, after `↓n`, so it is dropped first; green `+A`, red `−R` with U+2212, both always shown when `files > 0`. It is fitted as one unit and yields to the name: it stays only if the name keeps `min(its width, MIN_NAME_WIDTH = 8)` cells, because the default columns (26 and 32 wide) would cut names to a few cells. The pull, stack, `⇄` and `▶` targets use the same fit, so clicks stay where tags are drawn. It is not clickable. Machine rows show none: their link is a `watch`, which does not make the machine count.
- **Rejected**: the client running git (it repeats the rules and cannot reach a machine); one followed `changes` stream per workspace (a process each and full patches); sharing the panel's slot (a slow read freezes the panel); counting every project while only a window is attached; a setting to turn it off; counting a view's workspace in the window's mode (side panels are window-only).
- **Checked**: unit tests on real repos against a full All load; app tests with a window and with views.
