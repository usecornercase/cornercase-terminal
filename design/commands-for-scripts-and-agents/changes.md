# Commands for scripts and agents › Following the changes panel

Part of [Commands for scripts and agents](../commands-for-scripts-and-agents.md).

- **Following the changes panel** (#339, `control/changes.rs`, `app/changes_panel/streams.rs`, `app/control/changes.rs`, `cli/changes.rs`, `cli/args/changes.rs`; `cornercase changes list|file|gap|base|viewed|mode`): the panel's data (files with status, counts, fold class, the patch with words that changed and highlighting, unchanged lines, the base and the viewed marks) was reachable only by drawing it. Seven request names (`changes`, `changes-mode`, `changes-file`, `changes-gap`, `changes-base`, `changes-viewed`, and `changes-discard` from #421), so an older server refuses each by name; feature `changes`, stream `changes` version 1, `CONTRACT` stays 1. None takes a view (a client passes the workspace id from its view line).
  - **A stream per connection, like `surface`**: `changes` (`scope` project or every, `workspace`, `mode`) answers a first `Summary` at once, possibly `state: loading`, then streams a whole new one (`revision` + 1, only when its content differs from the last sent) each time the files change, through the held-snapshot slot (`Streamed::Snapshot`), so a slow reader gets the latest and `server.rs` needed no change. Summaries are whole objects, never patches, as `watch`'s are. A project stream has one workspace entry while ready, even with no files; an Every project stream has one per workspace with changes, in `project::sidebar_order` then workspace order (built from `every::group`), and never ends by itself. A project stream ends with `Detached` when its workspace is gone or its project closing. A second `changes` on one connection is `conflict`. A stream belongs to the connection that opened it: `changes-mode` finds only that connection's stream, and another connection naming its id gets `not-found`, as for an id that does not exist, so one client cannot change what another follows.
  - **The mode belongs to the stream**: `Panel::mode` is the window's, saved in the session and changed by its tabs; side panels are window-only. Each stream carries its own mode and `changes-mode` changes it in place on the connection that holds the stream, so a GUI can follow one workspace in Uncommitted and another in Commits without flipping the window's tabs. **The base and the viewed marks are shared**: `Workspace::base` is the workspace's saved state and the marks are review state, like folds and names, which views already share; `changes-base` and `changes-viewed` do what the picker and the `✓` do and the window shows it. Every project shows only uncommitted changes (`malformed` otherwise), with no workspace.
  - **Ids and strings only**: summaries carry project and workspace ids, never labels (a rename would otherwise have to produce a summary; `status` and `watch` have the names, the command's text output reads them with one `status`). `Mode` and `Scope` are `changes::Mode` and `Scope`, lowercase, as in the session, and wire enums of their own (`FileStatus`, `FoldClass`, `LineKind`, `State`) map the diff's types: serde is not added to `changes::diff`, so a domain change cannot change the contract by accident, as with `Layout`. **Digests are 16 hex digits**, not numbers: they are `u64` hashes and JSON numbers lose precision past 2^53 in JavaScript. A file's `digest` is its review identity (`File::viewed_digest`: the metadata fingerprint in Uncommitted, the patch digest in Commits and All), so it changes whenever the file's change does. **`changes-viewed` needs the digest to set a mark**, not to clear one: the client marks the version it saw, and a file that changed meanwhile is not marked, which is the window's own rule; it also needs no model in memory.
  - **A patch is the live model's, or a one-off job's**: `changes-file` answers at once from the model of that (workspace, mode) while it was read within `LIVE_FOR`, where the full loader already parsed and highlighted every hunk (project-scope streams and the window's workspace); otherwise a job reads it (the summary loader with the one path expanded in Uncommitted, which pairs renames through `status`, the full loader in Commits and All) and answers as `Stage::Reading`. The one-off result is written into no shared model. `changes-gap` always reads the file's new side in a job (`changes::gap`, which the window's gap click uses too). **A path from the request is only looked up among the files git listed**, never joined to the workspace's folder: `file.path` from git's output is what reaches the disk. `changes-file` and `changes-gap` are chatty (debug), since a GUI may ask on each click or prefetch.
  - **Highlighting is a style table of palette indices** (`control::surface::Style` and `Table`, shared with `surface` frames: index 0 is `{}`, colours `{"index": n}`, `bold` and `italic`), each line's `syntax` runs `{style, text}` over `text`. No RGB and no tints: the window's `Tints` stay in the window, the client tints added and removed lines. `emphasis` is `[start, end)` pairs in characters (Unicode scalar values) of `text`, the indices `ui/changes.rs` draws with, left out when empty; `syntax` is left out where the line is not highlighted. `text` is the window's (`diff::expand`: tabs as four spaces, a trailing `\r` dropped). Token classes were rejected: they would change `highlight::highlight`'s cached output type, and palette indices are what the window draws with.
  - **Pacing**: a stream's feed is built when something changed (`App::trace` marks it, like `watch`) and at most once every `FEED_EVERY` (100 ms), with `tick` waking for a due build; each followed pair asks git at most once a second (`OPEN_EVERY`), the digest skip applies, and `every_targets()` (which reads `.git/HEAD` per workspace) is worked out once per `refresh_changes` and passed down. A workspace nobody follows costs nothing more than today. The count behind ` Changes n ` is `WorkspaceInfo.changes` (`files`, `added`, `removed`, `mode`) in `status`, `watch` and `view`, present only while cornercase keeps it current (the window's target, a workspace a stream follows, or any workspace while a stream sweeps Every project), never stale and left out otherwise (`skip_serializing_if`, so the v1 fixtures are byte for byte what they were).
  - **`cornercase changes list`** prints one line per workspace (`project › workspace  uncommitted  2 files +6 −5`, `vs X` in Commits and All) and the panel's rows (`M  src/a.rs  +4 −3`, `R  old → new`, `A  new.txt  +5 −0  untracked`, tagged `lockfile`, `binary`, `too large`, `viewed`) once the state is no longer loading; `--follow` prints the summaries as JSON lines (always JSON), `--every` is Every project. `file` prints a unified diff, `gap` the numbered lines, `base` the branches with `(current)` and `(default)` tags (naming one sets it, `--default` clears it), `viewed` first reads the file for its digest, and `cornercase changes list` exits non-zero when the state is `failed`. There is no command for `changes-mode`: it only reaches a stream of its own connection (see above), which a separate invocation can never be, so it is a request for programs holding the stream open (CodeRabbit asked for a handoff; rejected: a stream another connection could steer would need ownership rules of its own). **Rejected or left for later**: a global mode (`changes-mode` flipping the window's tabs), patches inside summaries (a summary would carry every hunk of every file each second), a per-stream patch cache, labels in summaries, following a view's navigation (`--view`), digests as numbers, and writing marks per mode (they are per file, as the window's are).
  - **Discarding a file** (#421, `changes-discard`, `cornercase changes discard PATH`): the digest is required, as for `changes-viewed` when setting a mark, so a client discards the version it saw. Refusals: `malformed` for no path, no digest or a bad one, `not-found` for a file git lists no change for, `conflict` when the file's digest changed since, `failed` with git's message otherwise (`index.lock` held by another git). It answers `workspace`, `path`, `old_path` and `status`. The CLI reads the file's digest first and asks on a terminal (`--yes` skips the question; without a terminal and without `--yes` it fails), and the window shows no toast for a request that came over the socket, since nothing else changes what the window shows. Two discards in one repository at once can meet `index.lock`; nothing retries.
