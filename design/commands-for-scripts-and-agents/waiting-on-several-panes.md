# Commands for scripts and agents › Waiting on several panes

Part of [Commands for scripts and agents](../commands-for-scripts-and-agents.md).

- **Waiting on several panes** (#129): `wait` takes `--pane` and `--tab` more than once, with `--any` or `--all`, since an agent coordinating others had to run one background wait per agent and keep track of which one ended. Each target gets its own `Watch` with the same condition: `Stage::Several` holds them as plain `Pending` parts that `advance` moves like any other, so every condition, the reaction check after a submission and `--until turn-over` work the same on several panes; the `--timeout` is the request's, and its message says what each pane still being waited for is doing. `--any` answers with one pane, the first in the order given among those that ended on the same check: one line is what a script reads without parsing (`read -r pane ended`), and a wait on the rest hears about the others at once, since their condition still holds. `--all` keeps each pane's first ending rather than asking every condition to hold at the same moment, which would never end for agents sent more work meanwhile. A line is `<id> <ending>` (the matched line for `--text`, as for one pane), the id being the one given, so a tab's line starts with the tab's id (ids come from one counter, so it never names a pane), in the order given, `--pane` ones first (clap keeps no order across two options). The same id given twice is watched once. A pane that closes ends as `closed` and counts as ended: closing a tab is ordinary while agents run side by side, and failing would throw away the wait on the others. Other failures (the agent exited, it never took the Enter) fail the whole wait as they do for one pane, since something needs looking at. One target without `--any` or `--all` keeps the old answer and output; several without either is wrong usage (exit 2, checked after parsing since clap cannot count across two options) rather than a default, so a script says which it means. The answer is `Done::panes`, so `--json` prints `{"panes": [...]}`, an object like every other answer. On the wire it is a command of its own, `wait-several`, with the `Wait` fields plus `panes`, `tabs` and `all`: a server from before it ignores unknown fields and would wait on the caller's pane alone, while an unknown command is refused with `has no wait-several command; update cornercase and restart the server`. A wait on one pane still goes as `wait`, so it works with older servers.
