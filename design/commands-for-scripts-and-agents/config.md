# Commands for scripts and agents › Reading and changing settings

Part of [Commands for scripts and agents](../commands-for-scripts-and-agents.md).

- **Reading and changing settings** (#336, `control/config.rs`, `app/control/config.rs`, `cli/config.rs`; `cornercase config`): one request, `config` (operation index 43 of 44, feature `"config"`, `CONTRACT` stays 1), tagged by `action` like `queue` (`get`, `set`, `project`, `secret`, `remove`; an action an older server does not know fails to parse, never ignored), and one answer shape for every action: `settings`, `connections`, `projects`, the `revision`, the file's `path`, its `problem` and the `notices` of what changed. `set` takes a map of key to JSON value and is all or nothing: the values are applied in turn to a throwaway model, the first refusal is returned, and only then is the result written through `write_config`. Strict JSON types on the wire; the CLI reads the descriptor first (`config` again, as the `--worktree` lookup does) and converts each `KEY VALUE` by the setting's `type`. Codes: `not-found` for an unknown key, `malformed` for a wrong type or a value the modal's check refuses (its text unchanged), `conflict` for what the state blocks (an environment-variable token, Jira's or Plane's prerequisite, a folder that is not a repository, an unreadable `config.json`; its meaning widens to "does not fit the current state"), `failed` when the service refused a token. **Secrets are write-only**: `issues::Secret` is `transparent` for serde and prints `Secret(..)` in `Debug`; `Configure::fields` logs the action and the key, never a token or a value (`jira_jql` could hold something private, so `set` logs key names only, as the modal's log line does); the check runs the modal's own (`check_token_for` and `check_messenger_for` with the request's key) and answers as a `Stage::Reading` pending when the job ends, with the account, never the token; the modal's open copy is refreshed quietly (`refresh_open_settings`), since `Settings::checked` and `bot_checked` clear the edit field the user may be typing in; the refusal log line prints every message, so none carries a token. The CLI reads a token only from standard input (echo off on a terminal through `rustix::termios`), never from argv. `project` sets a folder's setup and teardown through `change_config`, only for a repository root (clearing is always allowed), by `project` id or `path`; the editor's line-break rule applies (`ProjectSettings::normalised` turns other control characters into spaces). Removing what is not set answers with a notice (`` `linear` is not set ``), not an error. A request does not take a view (`takes_view` is a whitelist).
- **Sharing a setup** (#414, `control/config.rs`, `app/control/config.rs`, `app/share_settings.rs`, `cli/config/share.rs`; `cornercase config export [--to FILE]`, `config import FILE|- [--only SECTIONS] [--yes]`): two commands of their own, `config-export` (operation index 96) and `config-import` (index 97, the last of the 98 in `Command::NAMES`), not new `config` actions: an older server refuses an unknown command by name (and `contract` lists both as operations), where an unknown action would only fail to parse; additive, so `CONTRACT` stays 1 and the feature list is unchanged. `config-export` answers `text` (the TOML, see Settings › Sharing settings), the counts of `settings` and `repositories`, `left_out` (what was not shared and why) and `warnings` (possible secrets), and refuses with `failed` when the text would pass 256 KiB. `config-import` takes `text`, `sections` (optional, every section when left out; an unknown id is `malformed`) and `apply`: without it, it answers the preview (`sections`, each with its `changes` as `key`, `label`, `from`, `to` and its `notes`, then the `notes` of no section, each with a `kind`: `risk`, `missing`, `connect`, `unknown`, `repository`, `secret`; a later kind reads as `other`); with it, it applies the ticked sections and answers like `config get` with the `notices`. Both run the same build, so the preview refuses as an apply would: `malformed` for a file that is not a setup, a newer version, a bad value or two entries matching one project, `conflict` for a folder that stopped being a repository, and, when applying, an unreadable `config.json` (the preview reads the settings in use). The CLI shows the preview on stderr and asks `[y/N]`; reading `-`, or without a terminal, it refuses unless `--yes`, as `flow import` does, and exits 1 on any refusal. The logged fields are the text's size, the sections and `apply`, never the text.
