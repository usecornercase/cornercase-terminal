# Commands for scripts and agents › Streaming a tab's terminals

Part of [Commands for scripts and agents](../commands-for-scripts-and-agents.md).

- **Streaming a tab's terminals** (#286, `control/surface.rs`, `control/surface/patch.rs`, `app/surfaces.rs`, `server/surfaces.rs`; `cornercase surface --tab ID --cols N --rows N [--patches]`, `cornercase redraw --surface ID`): `read` gives plain text and a window gets ANSI for the whole TUI, so an external UI (an editor extension, a GUI) could show neither the live terminals with their colours and cursor nor the splits, short of parsing the rendered sidebar. The daemon already owns Ghostty, its cell snapshots and the split tree, so the `surface` request streams them.
  - **The frame** is one JSON object (`control::surface::Frame`), the first answer and every streamed line (`{"ok": frame}` in both modes), always complete: `boot` (`control::server_token()`), `session` (the revision of the latest `status --follow` snapshot sent, `Snapshots::revision`, kept for the whole server run and 0 only before the first one), `surface` (this stream's id, see Driving a tab's terminals), `surface` (this stream's id, see Driving a tab's terminals), `revision` (counts this stream's frames from 1), `tab`, `cols` and `rows` (the request's), `layout` (the whole split tree, as `status --json`'s `Layout`, naming hidden panes too), `dividers` (`Node::dividers`: `dir`, `path` from the root with `false` = first, the region split, the line's cells), `styles` and `panes`. A pane has its `rect` in the surface, its terminal's own `size`, `active`, `cursor` (`null` when hidden or scrolled out), `modes` (mouse, mouse encoding, alternate screen, alternate scroll, bracketed paste, application cursor, focus events, kitty keyboard flags), `scroll` (Ghostty's scrollbar: `total`, `offset`, `rows`) and `lines`.
  - **Cells and styles**: a line is runs of cells of one style and one hyperlink (`{"style": i, "hyperlink": h, "cells": [...]}`, `hyperlink` left out when the run has none), one string per terminal cell (the grapheme Ghostty stores), a blank is `" "`, and the right half of a wide character is `""` so a client does not draw it (`Cell::spacer`, from Ghostty's `CellWide::Wide`, not `unicode-width`: Ghostty decides the width). Cells after the last one that is not a default-style blank are left out, so an empty line is `[]`; the test for "default" is the wire style, since the emulator writes `fg(Reset).bg(Reset)` for styled cells. The `styles` table is shared by all the frame's panes and deduplicated; index 0 is `{}`, the terminal's own colours. Colours stay palette indices (`{"index": n}`, or `{"rgb": [r, g, b]}`), never resolved, so the client's theme applies, as Terminals says for the window. A selection made in a window shows as `inverse`, since selection is shared state. A blank that carries a hyperlink is kept at the end of a line (it is clickable). Style entries also carry `underline_style` (`double`, `curly`, `dotted` or `dashed`; a plain underline is `underline: true` alone), `underline_colour` (only on underlined cells) and `overline`; a pane carries `colours` when its program changed any (see What else a cell carries).
  - **What else a cell carries** (#333): the frame holds everything Ghostty knows about a cell that affects how it is drawn. **Additive keys within surface format 1, no format 2**: the contract's rule is that a version goes up only when something that was there changed meaning or shape, and `watch` and `view` already grew keys within format 1; `underline: true` keeps its meaning (underlined, any style), so a client that knows only it draws an undercurl as a plain underline, as before; a format 2 a client asks for would be a request field that an older server drops in silence in legacy mode, and the server would keep two encoders. Every new key is left out when empty (`hyperlinks`, a run's `hyperlink`, a pane's `colours`, a style's new keys), so the frame of a terminal using none of it is byte for byte what it was (a test strips the keys from the fixture and checks it writes back unchanged). No new `features` entry: absent keys mean none. **Hyperlinks** (OSC 8) are a per-frame table `hyperlinks` of `{"uri"}` entries (objects, so an `id` can be added), shared by all the panes and deduplicated like `styles`; a cell's run refers to an entry. **A hyperlink's identity is its address within a frame**: libghostty-vt 0.2.2, the newest release, gives a cell's URI (`GridRef::hyperlink_uri`) but not its OSC 8 id (Ghostty keeps ids internally; no header exposes them), so cells with one URI are one entry: across a soft wrap (every cell on both rows carries the URI), across separate lines drawn with one explicit `id=`, and also two separate spans to the same address (a click on either opens the same address; only a hover highlight widens). Rejected: grouping by contiguity (it splits an explicit-id link drawn line by line), recovering ids from the OSC 8 sequences in the status stream observer (it sees sequences, not cells, and reflow and redraws make the mapping guesswork) and a patched binding. When a binding exposes ids, `id` is added to entries and they split by (id, uri), additively. **The cost** stays out of the window: `GridRef` lookups are not for render loops, so only the surface path asks (`Emulator::surface_snapshot`; `snapshot` reads no links), only on rows Ghostty marks (`Row::has_hyperlink`), only for cells that have one, and the URI buffer starts at 2048 bytes (Ghostty's cap for an OSC) and grows on `OutOfSpace`. A URI loses its control characters, as symbols do. **Program colours**: a pane's `colours` (`fg`, `bg`, `cursor` as `[r, g, b]`, and `palette` as `{"1": [r, g, b]}`) are the entries that differ from Ghostty's own defaults (`color_palette` against `default_color_palette`, `fg_color` against `default_fg_color`…), so a host theme (`set_default_*`, what `apply_theme` does) is never an override, also after the theme changes, while OSC 4, 10, 11 and 12 are, and OSC 104, 110, 111 and 112 clear them; a client resolves an index through `palette` before its own palette and draws default-coloured cells with `fg` and `bg` when present. The limit is that an entry set to exactly the value it already had is invisible (the API has no override mask). The window still draws plain underlines and the outer terminal's palette (unchanged: `to_style` does not set ratatui's underline colour).
  - **Per-pane grids, not a composed one**: composing one grid through `ui::pane::draw_tab` (as herdr's frame data does) would bake the window's chrome into the cells (dimming of inactive panes, the `↓ n more` badge, link underlines, padding) and crop terminals whose PTY size differs from their rectangle. Per-pane grids carry everything and are what a native UI draws.
  - **Sizes**: the caller's `cols` and `rows` lay the panes out through `Tab::shown`, the window's own rule (a tab too small for all its panes shows only its active pane over the whole surface, with no dividers). The PTYs keep the size the window gives them, so a pane's `size` can differ from its `rect`; `lines` and `cursor` index `size`. A `--tab` surface resizes no terminal: `App::resize` sizes every tab on every draw, so a surface that resized them would make the PTY bounce between two sizes. A view's surface (`surface --view`) is laid out at the view's size, and the PTYs take that size only while the view controls the tab (see Views of your own). The minimum is 1×1 (`start-server`'s 90×10 is for the window layout), the maximum 1000×500 (as `start-server` and the browser bridge).
  - **When frames are drawn**: `Step::Surfaces` runs every loop turn after `Step::Draw`, so it sees the sizes that draw just set. A subscription is dirty after output in a pane it shows (`App::surface_printed`, looked up by pane, so output nobody shows stays the early exit of `Server::due`: the window is not drawn for a pane only a surface shows, and nothing renders when neither does), after any other server event (`touch_surfaces`, where `handle` sets `changed`), and at least every 500 ms (`REFRESH_EVERY`, which catches what refresh changes without an event). A dirty one renders at most every 16 ms (`FRAME_EVERY`, the window's `FRAME`), and sends only when its content differs from the last one sent, so an unchanged frame raises no revision. `App::tick` wakes for the next render (`surface_wake`), always in the future, so the loop never spins. Everything renders on the server loop: `Emulator` is `!Send`.
  - **Slow readers**: `render_surfaces` takes the ids of the clients with fewer than `SURFACES_QUEUED` (2) messages queued, and a subscription whose client is full is not rendered at all, so work never piles up; it stays dirty and is looked at again after one frame, and once there is room it gets one frame with the latest state. A skipped frame never corrupts a display: a complete frame needs nothing before it, and with patches the frame after a skip is complete (see Patches). The revisions received still have no gaps. A reader that stops reading meets the 1 s write timeout like any client, and its connection closing drops the subscription. A frame that panics while it is built ends that stream and shows the bug toast, so one broken frame cannot panic every turn.
  - **`boot`, `session` and `revision`**: `boot` changes on every server start, so a frame of another run is stale (ids are reused). `session` relates a frame to the session snapshots: a frame below the snapshot the client holds was drawn before that change, one above it after a change whose snapshot the client has not received yet; they arrive on different connections, so there is no order between them. `revision` orders one stream's frames. To recover a baseline, reconnect: the first answer is always complete, from revision 1; there is no resync message.
  - **Outcomes**: the first answer is the frame, built in the step the request arrives in and answered before any later one (`Step::Answer` runs before `Step::Surfaces`). A refusal is an ordinary error with a code: `not-found` (no such tab), `malformed` (no tab, size out of range), `failed` (a second `surface` on the connection, which streams one tab: `resize` changes a `--tab` surface's size, another connection streams another tab), `stale-boot`, `unsupported` (an older server). A pane's shell exiting drops it from the next frame. The tab closing (last pane exited, or the tab, workspace or project closed or removed) ends the stream with `Detached`; the server stopping with `Shutdown` or `Restart`. Closing the connection unsubscribes (logged as `surface ended`, with the frame count) and leaves the shells and the window as they were. `cornercase surface` exits 0 on all of these, and 1 when the connection is lost any other way. It needs no window.
  - **Not sent yet** (documented as unsupported): images (kitty, sixel, iTerm2), OSC 8 link ids (see What else a cell carries), notifications (they come on `events --notices`, see What a view shows counts as seen), explicit pane sizes (#288), a scroll position or selection per client (both are shared with windows), pixel sizes, the cells of panes hidden because the tab is too small, and the window's chrome.
  - **Rejected**: sharing snapshots between streams of one tab (left for later: a frame snapshots every shown pane, about the window's draw cost, at most ~60 times a second per stream and only while something changes), a text output mode (the stream is for programs), and going through `serde_json::Value` for streamed frames (it would allocate a node per cell; the first answer does, through `refuse_or_answer`, which sorts keys, so clients must not depend on key order).
  - **Patches** (#334, `control/surface/patch.rs`, `control/surface/mirror.rs`): every frame was complete, one string per cell, up to about 60 a second, so a native UI parsed the whole tab on each one while an agent streamed, and through `cornercase proxy` each crossed the link whole.
    - **Opt-in**: `surface` takes `patches` (`cornercase surface --patches`, always serialized, since a request field must not skip). Without it every frame is byte for byte what it was. An older server ignores the field in legacy mode and keeps sending complete frames, which a patching client handles anyway; in structured mode it answers `unknown-field`. The feature `surface-patches` tells a client the field exists, and the CLI checks it before sending `--patches`, as it does for `--host`.
    - **A patch** is a frame's header plus `base` (the `revision` it applies to, always the one before it), tables of its own, and `panes`: only the panes that changed. Each has `pane` and `cursor` (always, so a client never has to tell an absent key from `null`), and only what changed of `active`, `modes`, `scroll`, `colours` (`{}` once a program resets them), `copy` and `lines` (row number to a whole line of runs). A complete frame never has `base` and is still a format 1 frame (`SURFACE_VERSION` stays 1, as for #333 and `host-events`: a new message kind that only goes to readers who asked, plus a feature). A patch's `style` and `hyperlink` numbers index that patch's tables, so a client resolves them as it applies; a table kept per subscription was rejected because it only grows (true-colour gradients) and would need resets of its own.
    - **`copy`** (`from`, `to`, `count`, at most one per pane), applied before `lines` from the rows as the client held them: output that scrolls moves every row, so rows alone save almost nothing of a vim-style scroll. A whole-pane shift was measured too: it sends an agent's footer (spinner, rules, input box) again on every scroll, which a copy of the rows above leaves in place.
    - **Changed rows are found by comparing with the last content sent to that subscription**, which the server already kept to send nothing when nothing changed. Rows are compared by what they look like (cells, and style and link resolved through their frame's tables), so a table in another order is no change. The copy's offset is voted for by rows with equal hashes (blank rows do not vote, at most four candidates per row), the longest run of exactly equal rows at that offset is copied, and only when that sends fewer rows; exact comparison decides what is sent, the hash only proposes. Memory per subscription stays one frame.
    - **Ghostty's dirty tracking was not used**, although libghostty-vt 0.2.2 exposes it on `RenderState` (a clean, partial or full flag, and one per row). Each emulator has one render state, shared by the window's snapshot, `active_contents` and every surface, and its flags are cleared by whoever reads them, so readers at their own pace would need a generation layer of their own; a scroll marks every row dirty anyway, and `copy` needs the rows' contents. Comparing reads rows the change check already reads. Reading only dirty rows is left for when the numbers ask for it.
    - **Complete frames** come first, and again whenever the layout, a divider, the set or order of panes, a pane's rect or terminal size, the surface's tab or size, or a view's projection changes. One also comes after the server held back a due frame because the reader had no room: a skipped update ends in a complete frame, so a reader that fell behind gets a fresh baseline (the issue's rule). A held-back frame with nothing new sends nothing, and under sustained overload the stream is #286's complete frames again, bounded by the reader's speed. A patch against the last queued frame would have been as safe, since a queued message is written in order or the connection closes (`Outbox::send` hands each message to the client's writer thread, and surfaces only render for clients with room, so nothing queued is dropped), but the issue asked for a baseline.
    - **`redraw`** (`cornercase redraw --surface ID`; a request of its own, so an older server refuses it by name, not in `takes_view`): the next frame of that surface is complete and goes out at once, even if nothing changed, still waiting for room. It works for any surface, patched or not, `--tab` or `--view`; a paused view's surface sends it when it resumes. The answer is `surface` and `tab`; `malformed` without a surface, `not-found` for one that ended. It shares its lookup with `resize`.
    - **A patch never meets a base the client lacks**: the server makes each patch against the last frame it queued on that connection, which arrives first or never, and the client checks `base` against the last `revision` it applied, asking for `redraw` (or reconnecting) when they differ. `control::surface::mirror::Mirror` (test-only) is that client, executed: the unit and app tests feed it the patches and compare it with what a complete stream shows.
    - **Text runs** (a run's cells as one string when each cell is one character) were estimated: they roughly halve complete frames and patches again, but would be a second cell format every client reads, while patches already cut an agent's stream by an order of magnitude. Left out, for an opt-in of their own if the numbers ever ask for it.
    - **Measured** (October 2026; a simulation of 15 s of deterministic workloads through a terminal emulator on a virtual clock with the server's 16 ms pacing, building frames in this JSON shape and applying every patch to check it rebuilds the next frame; mean bytes per frame; CPU was not measured, since comparing rows is O(cells) and a frame's build already reads every cell):

      | workload, size | frames/s | complete | rows only | rows + copy | rows + copy, text runs |
      | --- | --- | --- | --- | --- | --- |
      | agent 80×24 | 24 | 7,525 | 1,719 | 555 | 355 |
      | agent 120×40 | 24 | 14,767 | 2,167 | 630 | 374 |
      | agent 200×60 | 24 | 19,735 | 1,029 | 782 | 426 |
      | scroll 80×24 | 33 | 6,041 | 5,788 | 946 | 586 |
      | scroll 120×40 | 33 | 10,368 | 10,193 | 1,127 | 634 |
      | scroll 200×60 | 33 | 15,507 | 15,432 | 1,456 | 718 |
      | dashboard 120×40 | 4 | 6,787 | 5,075 | 4,838 | 1,996 |

      An agent at 120×40 goes from about 348 KiB/s to 15 KiB/s; an in-place dashboard that repaints most rows gains only about 1.4×.
    - **Never logged**: cells. The debug line per frame gives its `kind` (`patch` or `complete`), and the subscribe line whether it asked for `patches`.
    - **Tests**: `control/surface/patch/tests.rs` (rows by look, scroll up and down, a footer that stays put, when a copy is not worth it, blank rows, the cursor and the rest, shape changes, a sequence applied through `Mirror`, the fixtures `tests/fixtures/control/surface/v1/patch.json`), `app/tests/control_requests/surfaces/patches.rs` (first frame, not asked, scroll copy, split, resize, no room, nothing missed, redraw and its refusals, a patched stream against a complete one, reconnecting), `server/surfaces/tests.rs` and `e2e::commands`.
  - **A plugin's popup** (#456, `app/surfaces.rs`; `cornercase surface --popup`): a UI built on the socket saw that a popup was open (`popup` in the `app` feed) but not what it showed. `surface` takes `popup` (always serialized, as every request field), which streams the popup open in the window instead of a tab: the same frame, so a client draws it with the code it draws panes with, holding one pane (the popup's `Term`, its id from the panes' counter, `active`, its `rect` the whole surface), `cols` and `rows` the popup's terminal size, `tab` 0, `layout` null and no `dividers`, and `popup` (`pane`, the popup's term id, then `plugin` and `action`), left out of every other frame. The label is looked up by that id (`popup_label`), as the content (`popup_content`) and the place (`popup_place`) are, so a frame can never pair one popup's cells with another's name, whatever path builds it. It is addressed by "the popup" rather than by an id, since at most one is open (an overlay) and the `app` feed already says which: a popup id in `status` was rejected in #435 (`status`, `send` and `close` would reach a dialog that only exists while it is open). The subscription keeps the popup's term id, so the stream ends with `Detached` when that popup closes, and a popup opened afterwards needs a new subscription, as a closed tab's does; a frame never shows another popup under the same stream. Its size is the popup's own, which follows the shared window size (see Plugins › Popups), so `cols`, `rows`, `tab` and `--view` with it are `malformed`, `resize` refuses its surface (`failed`), and a new size sends a complete frame, as any shape change does. Output marks it dirty like a pane's (`popup_output` calls `surface_printed`); `redraw` and `patches` work as for a tab. Nothing changes in the window: the popup is drawn and typed into as before. No popup open is `not-found`. The feature `popup-terminal` tells a client the field exists (the CLI checks it before `--popup`); an older server ignores `popup` in legacy mode and refuses the request for its missing tab (`malformed`), and in structured mode answers `unknown-field`. Additive: `SURFACE_VERSION` and `CONTRACT` stay 1, and the frames of tabs are byte for byte what they were (`popup` skips when absent). Tests: `app/tests/plugin_popup/external.rs` (the first frame, output reaching a frame, closing, a later popup, refusals).
  - **Never logged**: cells and frames. The request's `tab`, `cols`, `rows` and `patches`, each frame's revision and size at debug, and the frame count at the end are.
  - **Tests**: the encoding is unit tests (`control/surface/tests.rs`: runs, trailing blanks, wide characters, the shared table, colours, attributes, sizes) and `tests/fixtures/control/surface/v1/frame.json`, written and read back, and as a streamed line; `term/emulator/tests.rs` reads underline styles and colours, hyperlinks (across a wrap, two addresses, a linked blank, none in the window's snapshot) and program colours (with a host theme, and each reset); `app/tests/control_requests/surfaces.rs` drives subscriptions with explicit instants (first answer, styles, hyperlinks, a link that wraps, undercurl, program colours and their reset, a background cleared with a colour, cursor, splits, a hidden tab, the early exit, pacing, a reader without room, closing, reconnecting, refusals, the session revision); `server/surfaces/tests.rs` the queue limit, that output only a surface shows draws no window, and the end with `Detached`; `e2e::commands` streams a tab the window does not show.
