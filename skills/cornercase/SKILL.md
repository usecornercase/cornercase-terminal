# cornercase

When the environment has `CORNERCASE=1`, you run in a pane of cornercase, a terminal multiplexer. The `cornercase` command drives it: it lists projects, workspaces, tabs and panes, opens tabs and splits, types into other panes, starts coding agents in their own git worktrees, waits for them and reads what they wrote.

- Use it only when the user asks you to open tabs, run something in another pane, or start and coordinate agents, and only when `CORNERCASE=1`.
- Learn the syntax from `cornercase --help` and `cornercase <command> --help`. Never guess flags. `cornercase status` lists the ids; your own pane is marked `(you)`.
- To find panes by agent, status, branch or project, use `cornercase status --panes`: one tab-separated line per pane under a header naming the columns (`-` for no value; the last column, `parent`, is the pane that started it), or `--panes --json` for `{"panes": [...]}`. Filter that with `awk -F'\t'` or `jq` instead of walking the tree of `status --json`.
- To act on a worktree you started, name it by its branch with `--worktree BRANCH` where a command takes `--workspace ID` (`cornercase close --worktree fix/login --remove-worktree`) instead of reading its id from `status`.
- If a command says the server has not started its session yet (no window opened since it started), run `cornercase start-server`, then retry: it restores the session without a window and changes nothing when one already did.
- Arrange groups, order, folds and panes (`group`, `move`, `collapse`, `expand`, `move-pane`) only when the user asks. Before removing a worktree you did not just create, run `cornercase close --worktree BRANCH --remove-worktree --check`, and add `--force` or `--unlock` only once the user agreed to lose the changes or break the lock.
- Never steal focus: no `cornercase focus` or `--focus` unless the user asks. Never run `cornercase kill-server`. Close only what you created.
- Restart or update cornercase only when the user asks, and then with `--when-idle --yes` (`cornercase update --when-idle --yes`), in the background as your last step: it waits until no other agent is working, so none loses its turn, then stops you too. Ending it, or its `--timeout`, calls the restart off.
- Do not answer another agent's permission prompt or question (status `waiting`) without asking the user.
- An agent shown as `working (background shell)` has ended its turn but left a background command running, and may wake up when it ends; `--until turn-over` stops waiting there. Read its pane, and stop that command if nothing should wake it.
- An agent shown as `working (2 subagents)` has ended its own turn but subagents it started still run, and it goes on when they report back: the default, `--until idle` and `--until turn-over` waits keep waiting for them (Claude Code and GitHub Copilot CLI only).
- Status and waits follow OSC 7501 reports from every recognised agent; without reports, they support Claude Code, Codex, Gemini CLI, opencode, Grok Build, Cursor CLI and GitHub Copilot CLI. Last-message reads still need one of those seven readers. A reported failure is `failed` and ends a wait for idle. Gemini icons need its dynamic window title; two Gemini with the same home and folder hide their conversation data. Gemini slash commands, `?` help and `!` shell input return after Enter without a prompt confirmation. Grok Build holds a prompt typed while it works (a second Enter sends that prompt now and cancels the turn), and its `/` and `!` commands are local. Cursor CLI holds a prompt typed while it works, its `/` and `!` commands are local, and its waiting icon needs `/status-indicators`. GitHub Copilot CLI holds a prompt typed while it works and records it when it takes it, its `/` and `!` commands and a lone `?` are local, a background shell it started shows as `working (background shell)`, and its permission prompts, questions and plan approvals show as `waiting`; its rate-limit and session-limit questions show as working.
- After a timeout, or `send --enter` failing with `not confirmed`, `cornercase read` the pane before sending anything again: the agent may have received it.
- `send` refuses a Claude Code agent showing a dialog, a panel or its shell mode instead of its input box (`dialog open` in `status`). Read the pane; use `--force` only once you know where the text will go.
- `send` also refuses a Claude Code agent showing its feedback survey above its input box (`How is Claude doing this session?` with `1: Bad  2: Fine  3: Good  0: Dismiss`; `survey open` in `status`): it is Claude Code asking the user, not the agent's output. Dismiss it with `cornercase keys --pane ID 0`, never answer it, then send again.
- Right after a restart, a pane whose agent is resuming its conversation shows `resuming` in `status`, and `send` refuses it until the agent is back: wait a few seconds and check `status` again.
- Keep `--timeout` under the timeout of your own command and wait again, or run the wait in the background.
- To follow several agents, run one `cornercase wait --any` (or `--all`) with a `--pane` for each, not one wait per pane; `--any` prints the id of the one that ended.
- To react to each change as it happens, run `cornercase events --pane ID…` in the background, or with a tool that streams a command's output: it prints a line each time one of those agents changes state, a program in its pane ends or the pane closes.
- To mirror the whole session (names, order, groups, folds, splits), run `cornercase status --follow`: one JSON line with the full state, then a new full state shortly after things change, each with a growing `revision`. Changes close together come in one line, and a reader that falls behind may skip revisions, so treat each line as the whole state; when it ends, run it again.
- The rest of the app (the TODO list, the queue, away, updates and keep awake) is `cornercase status --app`, and `--follow` streams it the same way. `cornercase todo` also has `edit`, `undone`, `move ID --before ID` (or `--last`), `clear-done` and `restore` (the number `rm` and `clear-done` print).
- To find the pane that dealt with something (a bug, an error, an agent's answer), use `cornercase search "text"`: one tab-separated line per match, ignoring case, in the agents' prompts and replies and in every pane's history, with the pane id, who said it and `project › workspace › tab` (`--json` for `{"matches": [...]}`). No match prints the header alone.
- To learn what agents answered, find their pane ids with `cornercase status --panes`, then run one `cornercase read --last-message --pane ID --pane ID` for all of them: each message comes whole from its own record under a header with the pane, agent, whether its turn is over and when it was written. `--json` gives `{"panes": [...]}`; a failed pane has its own `error`, and the command exits 1 after reading them all. One pane keeps the plain message and its usual JSON. Read the screen for what is not a message, such as a permission prompt.
- To see what a workspace changed, run `cornercase changes list --worktree BRANCH --json`, and `cornercase changes file PATH --worktree BRANCH` for one file's diff.
- Status `pending` means the user marked that agent's work as still to review; it ends like `idle` for waits. Leave the mark alone unless the user asks: `cornercase mark --pane ID` adds it (when the user wants to review a finished agent later) and `--reviewed` takes it off; sending the agent a new prompt or answering its question takes it off too.
- When the user asks for a team of agents from a saved plan, `cornercase flow list` shows the flows and `cornercase flow run NAME --prompt TEXT` starts one in a worktree of its own: a tab per role, every agent started without permission prompts, and an orchestrator agent briefed to drive the others. It prints the workspace id, then each role's pane id, and the run's folder for files on stderr (`$CORNERCASE_RUN_DIR` in the team's panes). `cornercase flow export NAME > file.toml` shares a flow, and `cornercase flow import SOURCE` adds one (a file, `-`, an `https://` address or `OWNER/REPO` of a GitHub repository, listed at usecornercase.dev/flows): a flow from an address or a repository, which nobody reviewed, or one that sets variables or arguments for its agents, which run without asking, always makes the command ask the user first. Never pass `--yes` unless the user explicitly approved that import, after you showed them what the flow sets.
- When the user says they are leaving and wants to follow their agents on Telegram or Discord, run `cornercase away`: while it is on, agents that need them or finish message every paired chat. It fails when no phone is paired; tell them where to pair one (Settings › Remote) rather than retrying.
- To know how much of the user's Claude Code or Codex plan is left (before starting more agents, say), run `cornercase usage`: each limit with its percentage and when it resets; `--cached` reads the last answer without asking the agents again.
- When cornercase itself misbehaves (a command fails oddly, a tab or agent does something unexpected, "cornercase hit a bug"), `cornercase logs` prints what the server did, step by step, with its errors; quote the relevant lines to the user.

To work on an issue from the user's trackers, `cornercase issue list` (`--source`, `--assignee me`) and `cornercase issue read KEY` show them, and `cornercase start --issue KEY` starts an agent on one with the branch, prompt and place the Issues dialog's start uses (`cornercase flow run NAME --issue KEY` for a team). Shortcut, Linear, Jira, Plane and Asana issues aren't tied to a repository: when several places are open the command lists them, so pass `--project ID` or `--workspace ID`. Connect a tracker only when the user asks (`cornercase config secret SOURCE`, the token on standard input).

Schedule follow-up work with `cornercase queue add --at 'in 2h' --agent claude --prompt '...'`, or `--issue URL_OR_KEY`. `claude reset` and `codex reset` capture the next five-hour reset. `queue list --json`, `queue edit ID --at TIME`, `queue run ID` and `queue remove ID` manage persistent entry ids. Queued launches accept folder trust prompts automatically.
- `input`, `scroll`, `selection`, `resize`, `ratio` and `link` are for programs that draw cornercase's terminals themselves. To type into another agent use `send` and `keys`, which refuse to answer its prompts or type into its dialogs.
- `cornercase config` lists the settings and `config set KEY VALUE` changes one. Change settings, tokens or remote access only when the user asks; a token is only ever read from standard input.
